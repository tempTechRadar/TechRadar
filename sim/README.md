# 시뮬레이터 (시연용 가짜 입력)

진짜 취약점은 발표 시간에 맞춰 나오지 않으므로, 시연은 가짜 변경으로 처음부터 끝까지 돌린다. 가짜 줄에는 모두 가짜 표시(`is_simulated`)가 붙고, 지우기는 그 줄만 지운다.
코드: `lib/server/simulator.ts` · 화면: `app/admin/simulator/` · 자세한 문구는 [관리자 사용설명서 7절](../docs/관리자-사용설명서.md)

## 무엇이 들어 있나
| 위치 | 무엇 |
|---|---|
| 배포 주소 `/admin/simulator` (관리자만) | 버튼 3개: "가짜 변경 1건 만들기"(npm `mcp-remote` 0.1.15, 위험) · "적용 기회 1건 만들기"(가짜 새 기술 + 확정된 같은 역할 관계) · "시뮬레이터 지우기" |
| [`skills/`](skills/) | 채점용 가상 스킬 4개(SPEC-10 G6–G9). 실행하지 않는다 |

## 시연 순서
1. **준비:** 시연 계정의 내 기술에 진짜 `npm:mcp-remote` 0.1.15 줄이 있는지 본다. 알림은 시연 계정에만 가고, 그 기술이 없으면 0건이 되며 결과 화면에 이유가 나온다.
2. 관리자로 `/admin/simulator` → "가짜 변경 1건 만들기". 같은 버튼을 또 눌러도 변경은 1건 그대로다(멱등).
3. `/admin/flow`에서 시뮬레이터 시작 노드의 실행을 골라 상자가 차례로 켜지는 것을 본다. 판단 대기에서 멈춘다.
4. 시연 계정으로 알림 상세 → 판단(적용 후보 / 보류) → 기록 찾기에 쌓인 것을 본다.
5. 실패 장면은 [관리자 사용설명서 5-2·5-3절](../docs/관리자-사용설명서.md)대로 깨진 시연 저장소를 등록해 보인다(운영에서는 실패 스위치를 켜지 않는다).

## 초기화
- **"시뮬레이터 지우기"는 시연의 맨 마지막에 한 번만.** 가짜 표시가 붙은 줄만 지우고, 실행 기록은 증거라 남으며, 바꾼 기록(`audit_logs`)에 한 줄이 남는다.
- **발표 당일 주의:** 같은 날 만들고 지운 뒤 다시 만들면, 대응안 초안은 하루 한 번만 부르는 제한(`lib/server/draft.ts`, 비용 막기) 때문에 "만들지 못했어요"처럼 보인다. 시연 직전까지는 돌리지 않거나, 앞 변경을 지우지 않고 그대로 쓴다(`docs/qa.md` 남은 오류).
- 막히면 "서비스 키가 없어요" → 서버 환경변수를 확인한다(값은 문서에 쓰지 않는다).
