# abbs-log: 단계마다 abbsbook에 기록하기

기준: 안내서 8장 vibelog 의무 기록 항목(날짜, 제목, 한 줄 메모, 화면 하나, 막힌 일과 푼 방법, 정한 일과 이유, 인터뷰한 날의 내용(신원 빼고), 자동 기록에도 내 판단 덧붙이기). 이 스킬은 그 기록을 abbsbook에 남긴다.
스케치북은 **사람마다 다르다.** 팀 저장소에는 id를 적지 않고, 각자 git에서 빠지는 `.claude/CLAUDE.md`에 둔다.

## 0. 처음 세팅 (한 사람당 한 번)
1. abbsbook 사이트 설정 > 에이전트 연동(`/settings/agents`)에서 연결 파일과 설치·테스트 프롬프트를 받아 Claude에게 붙여 넣는다(설치 → 앱 완전 재시작 → `verify_connection`). 키 파일 내용은 채팅·저장소 어디에도 넣지 않는다.
2. 저장소 루트의 `.claude/CLAUDE.md`(개인용, git 제외. 없으면 만든다)에 아래를 붙이고 값을 자기 것으로 바꾼다.
   ```
   ## abbsbook 자동 기록 (켜짐)
   - 작업 한 단계가 끝날 때마다 묻지 말고 `abbs-log` 스킬로 기록한다.
   - 스케치북: 「<이름>」 `<sketchbookId>` (계정: `<list_accounts의 account>`)
   - project: `tempTechRadar/TechRadar`
   ```
3. `node .claude/skills/abbs-log/shot.mjs test` 로 이미지가 만들어지는지 확인한다(Edge 또는 Chrome 필요).

개인 설정이 없으면 자동 기록은 하지 않는다. 사용자가 기록을 부탁했는데 설정이 없으면 0단계를 안내한다. 계정이 2개 이상이면 자동 기록을 멈추고 어느 계정·스케치북인지 먼저 묻는다.

## 1. 언제 (한 단계 = 이벤트 하나)
PR을 만들었다 · 문서 하나가 승인됐다 · 기능/조각이 끝났다 · QA를 한 바퀴 돌았다 · 막힌 오류를 풀었다 · 인터뷰를 정리했다 · 오늘 작업을 마무리한다.
읽기만 한 턴, 질문에 답만 한 턴, 아직 진행 중인 단계는 기록하지 않는다. 같은 단계를 다시 기록하면 새로 만들지 말고 같은 `sessionId`로 갱신한다.

## 2. 순서
1. **이미지 만들기** (임시 폴더·스크래치패드에 저장, 저장소에 넣지 않는다)
   - 요약 카드(항상): `card.json`에 `{date,title,memo,done[],blocked[],decided[],next[]}`를 쓰고
     `node .claude/skills/abbs-log/shot.mjs card <card.json> <out.png>`
   - 실제 화면이 있으면 하나 더: 로컬 서버·배포 주소·생성한 HTML 등
     `node .claude/skills/abbs-log/shot.mjs url <주소> <out.png> [가로] [세로]`
     (로그인 쿠키가 없는 새 브라우저 프로필로 찍는다. 로그인이 필요한 화면은 내장 브라우저로 확인만 하고 카드에 글로 적는다.)
   - 만든 이미지는 Read로 열어 깨짐·민감정보가 없는지 눈으로 확인한다.
2. **기록하기** `save_session` 한 번:
   - `sketchbookId`, `project`, (계정이 여럿이면 `account`): 개인 설정의 값
   - `sessionId`: `YYYY-MM-DD-<단계-짧은-영문-slug>` (예: `2026-11-17-abbs-setup`). 갱신은 같은 값으로.
   - `eventDate`: 오늘, `title`: 무엇을 끝냈는지 한 줄(120자 이하), `type`: `work`
   - `look: "photo"`, `photoPath`: 가장 잘 보여 주는 이미지(실제 화면 > 요약 카드)의 절대 경로, `lookCaption`: 40자 이하 한 줄
   - `files`: 나머지 이미지
   - `links`: 이 단계의 PR, 문서, 배포 주소
   - `tags`: 단계 종류(문서, PR, QA, 디버그, 인터뷰, 설정, 마무리 중) + 출처 ID(PRD-F1, UJ-2 …)
   - `note`: 아래 양식
3. 결과(이벤트 링크, 첨부 실패 여부)를 답변 끝에 한 줄로 알린다. `failures`가 비어 있지 않으면 성공이라고 쓰지 않는다.

## 3. note 양식 (Markdown)
```
**한 줄 메모:** …

### 한 일
- …
### 막힌 일 → 푼 방법
- … (없으면 줄 생략)
### 정한 일 · 이유
- … (없으면 줄 생략)
### 인터뷰 (인터뷰한 날만, 신원 없이)
- …
### 근거
- PR / 문서 / 커밋 링크

**내 판단:** _(직접 덧붙여 주세요)_
```
"내 판단"은 사람이 채우는 칸이다. 비워 두고, 답변에서 채워 달라고 상기시킨다.

## 4. 넣지 않는 것
비밀키·토큰·비밀번호·`.env` 내용, 인증 파일, 이메일·이름·연락처, 인터뷰 대상의 신원, 대화 원문 통째, 개인 데이터가 보이는 화면. 잰 것 / 당사자 말 / 팀 추정은 섞지 않고 구분해 적는다.
