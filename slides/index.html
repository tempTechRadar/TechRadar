문제 2/3 · 어떻게 골랐고, 무엇을 접었고, 근거의 한계

가설을 나란히 두고 인터뷰로 좁혔다

근거

  • 사람 인터뷰 2건(5명, 팀 밖, 동의 문구 읽음, 익명)
  • AI 인터뷰 3건은 가설용 — 실제 조사가 아니다

들은 말 사람 인터뷰, 요약

  • "있는 줄 몰라서 포기"는 거의 없다 (목적을 정하고 먼저 검색)
  • 보안 확인 = 유명세·사례 확인. 실제 점검(권한·코드·출처)은 안 한다
  • 새 기준: 무료로 쓸 수 있는가

접거나 바꾼 것

  • 기술 지도: 근거가 가장 약해 "대신 작게"
  • 빈도·손해 수치화: 하지 않음 (ADR 0011)
  • 가설들 → 통합안 승인 (ADR 0005·0013)

한계

  • 표본이 작다
  • 한 응답자는 인터뷰 전에 주제를 알고 있었고 "일부러 삐딱하게 답변"한다고 말했다
  • AI 인터뷰는 근거로 세지 않는다

문제 3/3 · 좋아졌는지 잴 숫자 하나

같은 저장소를 손으로 vs 앱으로, 걸린 시간

빈도·손해는 수치로 딸 수 없다고 판단해 당사자 말로 대신한다. 발표의 숫자 하나는 실제로 재는 비교 작업이다.

방법하는 일걸린 시간
① 손으로파일을 열어 깐 것을 적고, 기술마다 취약점·최근 업데이트를 검색▢ 재서 채울 것
② 앱으로저장소 등록 → 내 기술 목록 → 등급과 이유 확인▢ 재서 채울 것
아직 재지 않았다. 사람이 한 번 재고 여기에 쓴다. 사용자가 없어 앱 안의 숫자는 시연 계정 값뿐이라는 한계도 함께 말한다.

사건과 대응

알림은 두 종류, 조치는 사람이 판단한 뒤에만

보안 경고

쓰는 기술의 등급이 위험이 되면 알림. 이전 값 → 현재 값, 쉬운 이유, 근거 링크.

적용 기회

같은 역할의 새 기술이 나왔고 조건을 모두 만족할 때만(확정된 같은 역할·등록 이후·위험 아님).

판단 → 기록

적용 후보(설치 프롬프트에 기본 포함) 또는 보류(사유 기록). 판단 전에는 아무것도 바뀌지 않고, 관리자도 건너뛸 수 없다.

  • 같은 변경을 다시 읽어도 알림은 두 번 생기지 않는다. 저장이 실패하면 "처리 완료"로 보이지 않는다.
  • 대응안 초안은 Claude가 쓰고 참고한 출처를 함께 보여 준다. 출처가 없으면 "찾지 못함".

Claude 연결은 켜졌다: 키는 운영(Production)에만 있고, 운영 시뮬레이터로 실제 호출 1번이 성공했다(초안 584자, ai_calls succeeded, 11-19).

실제 초안 화면 캡처 1장(알림 상세의 대응안 초안과 참고한 출처). 사람이 운영에서 찍는다.

시연 (시뮬레이터로)

상자가 차례로 켜지는 걸 보여 준다

  1. 시뮬레이터 버튼으로 가짜 위험 변경 1건을 만든다.
  2. 흐름 화면에서 상자가 차례로 켜진다 — 미리 그린 그림이 아니라 실제 실행 기록(runs·run_steps)에서 그린다.
  3. 알림 상세: 이전 → 현재 값, 출처, 대응안 초안.
  4. 판단(적용 후보 / 보류)을 저장하면 "조치와 기록" 상자가 켜진다.
  5. 일부러 실패시킨다: 빨간 상자와 오류 기록. 실패 시연 버튼 5가지는 운영에서 일부러 꺼 두어 로컬에서만 돈다. 배포 주소에서는 package.json을 깨 둔 시연용 저장소를 등록해 "내 기술 뽑기" 상자를 빨갛게 만든다(시연 저장소는 아직 준비 전, ADR 0024 제안).
  6. 비슷한 지난 판단을 찾아 보여 준다.
리허설로 순서와 시간을 재고, 발표 전에 시뮬레이터 줄을 지운다(가짜 줄만 지우기). 인터넷이 끊길 때를 대비해 시연 화면 녹화도 챙긴다.
