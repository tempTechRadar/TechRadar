# 문제와 범위

> TechRadar는 AI 코딩 도구로 직접 만드는 사람(v1 대표: 바이브코딩 부트캠프 수강생)이 "내가 무엇을 깔았는지, 안전한지, 더 나은 것이 나왔는지"를 한눈에 보게 하는 서비스다. (출처: docs/문제정의.md 1절, docs/adr/0013-문제정의-통합안-승인.md)

## 문제 한 문장
- 사용자는 스킬·MCP·플러그인을 소식(쇼츠·유튜브)이나 그때그때의 필요로 하나씩 깐다. (출처: docs/문제정의.md 1절)
- 그래서 깐 것의 목록, 안전한지, 더 나은 것이 나왔는지를 한눈에 볼 수 없다. (출처: docs/문제정의.md 1절)
- 결과: 유명세만 보고 검증 안 된 도구를 쓰고, 컴퓨터를 바꾸면 쌓은 세팅을 처음부터 다시 쌓는다. (출처: docs/문제정의.md 1절)
- 지금은 휴대폰 캡처, "생각나면 다시 보기", 유명세·사례 확인으로 버틴다. (출처: docs/문제정의.md 1절)
- 서비스 기준 문장은 "지키고(보안), 고르고(판단), 옮긴다(설치 프롬프트)"다. (출처: docs/adr/0013-문제정의-통합안-승인.md 정한 것)
- 이 통합안은 2026-11-18 회의(D1)에서 승인됐다. (출처: docs/adr/0013-문제정의-통합안-승인.md)

## 누구를 위해
- 대상: AI 코딩 도구(Claude Code·Cursor·Codex 등)로 직접 개발하는 사람. (출처: docs/문제정의.md 4절)
- v1 대표 사용자: 바이브코딩 부트캠프 수강생(초·중급, 비전공 포함). 과정이 끝나면 컴퓨터를 바꾼다. (출처: docs/문제정의.md 4절, docs/adr/0002-v1-범위.md)
- 비교 사용자: 스타트업 대표(숙련자). 스스로 먼저 검색해 이 서비스의 가치가 작다는 반대 근거다. (출처: docs/문제정의.md 4절)
- 대상은 넓게 두되 판단 기준이 흐려지지 않게 대표 사용자를 하나로 정했다. (출처: docs/adr/0002-v1-범위.md)

## 놓치면 잃는 것
- 쌓은 세팅: 목록이 없어 컴퓨터를 바꿀 때 처음부터 다시 쌓는다. 앞으로의 계획이라 손해 크기는 모른다. (출처: docs/문제정의.md 5절)
- 안전: 유명세만 보고 깐 스킬·MCP가 비밀값 유출이나 의도치 않은 명령 실행으로 이어질 수 있다(공개 사례 P1–P5). (출처: docs/문제정의.md 5절)
- 시간·기회: 더 나은 것이 나와도 모르고 지나간다. 팀 가설이며 팀 밖 인터뷰에서는 나오지 않았다. (출처: docs/문제정의.md 5절)
- 결과물 포기: 팀원 본인 인터뷰에만 있는 힌트이고 팀 밖 근거는 없다. (출처: docs/문제정의.md 5절)

## 서비스가 하는 일 (흐름)
- 공개 저장소 등록 → 내 기술 목록 → 보안 점검(등급 + 쉬운 이유) → 기술 지도에 표시. (출처: docs/문제정의.md 2절)
- 기술 소식 수집 → 내 기술 목록과 맞춰 보기 → 알림 → 사용자 판단(적용 후보 / 보류) → 판단 저장. (출처: docs/문제정의.md 2절)
- 내 프로젝트는 공개 GitHub 저장소 주소만 받는다. `package.json`, `.mcp.json`, `.claude/skills/`를 읽고 `requirements.txt`는 3순위다. (출처: docs/문제정의.md 2절, docs/adr/0020-v1-범위-정리-스킬-읽기만-1순위.md 정한 것 1·2)
- 보안 등급은 코드 규칙으로 통과 / 주의 / 위험 / 찾지 못함, 등급마다 쉬운 이유를 붙인다. (출처: docs/문제정의.md 2절)
- 알림은 두 종류: 보안 경고(내 기술이 "위험"으로 바뀜), 적용 기회(새 기술이 내 기술과 같은 역할). (출처: docs/문제정의.md 2절)
- 첫 화면은 기술 지도이고 내 기술 목록은 메뉴에서 연다(회의 D8). (출처: docs/문제정의.md 2절)
- 지켜볼 분야는 AI 코딩 도구 생태계(LLM, Claude Code 확장, 하네스 패턴, 개발 도구)뿐이다. (출처: docs/adr/0002-v1-범위.md)
- 가장 가까운 기존 서비스 Glama와 다른 점: 내 목록 기준으로 바뀐 것을 알리고, 판단을 기록하고, 옮길 프롬프트를 만든다. (출처: docs/문제정의.md 2절)

## 이번에 하지 않을 것
- AI 코딩 도구 생태계 밖의 IT 분야(프런트엔드 프레임워크, 클라우드 등). (출처: docs/문제정의.md 9절)
- 비공개 저장소 등록: GitHub 로그인 연동이 필요해 다음 버전. (출처: docs/문제정의.md 9절, docs/adr/0002-v1-범위.md)
- Reddit 수집: 사전 승인이 필요하고 약관을 확인하지 못했다. (출처: docs/문제정의.md 9절)
- 뉴스레터 전체, Anthropic 뉴스 크롤링(2순위로 둠). (출처: docs/문제정의.md 9절)
- 사용자 대신 설치·적용, 세팅을 대신 옮겨 까는 "이사". 대신 설치 안내 프롬프트(글)는 만든다. (출처: docs/문제정의.md 9절)
- 필요 문장과 기존 도구를 맞추는 검색을 사건으로 쓰는 것(바깥 변화가 아님). (출처: docs/문제정의.md 9절)
- `requirements.txt` 읽기, 프로젝트 수정·보관, GitHub 주제 태그로 새 기술 찾기는 3순위로 내렸다. (출처: docs/adr/0020-v1-범위-정리-스킬-읽기만-1순위.md 정한 것 2–4)

## 접은 후보와 이유
- 보안 공지·지원 종료 알림만 하는 서비스: 팀이 원하는 "큰 그림 + 판단 도움"에 한 단계로 흡수. (출처: docs/문제정의.md 10절)
- IT 기술 전체 지도: "모든 뉴스 요약"처럼 사건 기준이 흐려져 AI 코딩 도구 생태계로 좁힘. (출처: docs/문제정의.md 10절, docs/adr/0002-v1-범위.md)
- 모두에게 새 소식을 알리는 뉴스형: 뉴스레터·changelog가 이미 있고 소음 위험. (출처: docs/문제정의.md 10절)
- B 중심안(필요 → 검색·추천): 팀 밖 사람 인터뷰에서 "몰라서 포기" 장면이 0명이라 보조로 내림. (출처: docs/문제정의.md 10절)

## 안내서를 대하는 태도
- 안내서는 그대로 따를 의무가 없는 참고 기준이고 팀 아이디어(문제정의)를 우선한다. (출처: docs/adr/0001-안내서-유연-적용.md 결정)
- 안내서와 다르게 간 곳은 ADR에 이유를 남기고, 제출 항목은 체크리스트로 챙긴다. (출처: docs/adr/0001-안내서-유연-적용.md 결정·결과)
