# 용어

> TechRadar에서 자주 쓰는 용어(내 기술 목록, 보안 등급, 알림, 판단, 적용 후보, 보류, 설치 프롬프트 등)의 뜻과 피할 말을 모은 쪽. (출처: docs/GLOSSARY.md)

## 자주 쓰는 용어

| 용어 | 뜻 한 줄 | 출처 |
|---|---|---|
| 기술 | 지도에 노드 하나로 올라가는 것(MCP·스킬·플러그인·SDK·모델 등) | 출처: docs/GLOSSARY.md 기술 |
| 종류 | 기술의 모양 7가지(MCP 서버, 스킬, 플러그인, SDK, 모델, 연동 서비스, 개념) | 출처: docs/GLOSSARY.md 종류 |
| 기술 키 | 생태계 + 이름으로 정한 기술의 신분증(`npm:…`, `mcp:…` 등) | 출처: docs/GLOSSARY.md 기술 키 |
| 기술 지도 | 기술을 갈래와 연결선으로 엮어 큰 그림을 보여 주는 화면 | 출처: docs/GLOSSARY.md 기술 지도 |
| 갈래 | "하는 일"로 묶는 분류 나무의 가지, v1은 2단계 | 출처: docs/GLOSSARY.md 갈래 |
| 같은 역할 | 같은 작은 갈래에서 같은 일을 하는 두 기술의 관계, 후보 → 관리자 확정 | 출처: docs/GLOSSARY.md 같은 역할 |
| 내 프로젝트 | 공개 GitHub 저장소 주소로 등록한 프로젝트와 거기서 읽은 기술 | 출처: docs/GLOSSARY.md 내 프로젝트 |
| 내 기술 목록 | 저장소에서 읽은 기술과 직접 더한 기술을 합친, 사용자가 깔아 쓰는 기술 목록 | 출처: docs/GLOSSARY.md 내 기술 목록 |
| 직접 추가 | 사용자가 손으로 더한 기술. 이름만 쓰면 등급은 "찾지 못함" | 출처: docs/GLOSSARY.md 직접 추가 |
| 직접 숨김 | 읽은 기술을 목록에서 뺀 상태. 지우지 않고 되돌릴 수 있음 | 출처: docs/GLOSSARY.md 직접 숨김 |
| 프로젝트 밖(내 컴퓨터) | 저장소에 없는 전역 MCP·스킬을 담는 칸, 사람마다 하나 | 출처: docs/GLOSSARY.md 프로젝트 밖(내 컴퓨터) |
| 보안 등급 | 통과 / 주의 / 위험 / 찾지 못함 네 가지 | 출처: docs/GLOSSARY.md 보안 등급 |
| 찾지 못함 | 값이나 근거를 확인하지 못했을 때의 말. 수집 오류와 다름 | 출처: docs/GLOSSARY.md 찾지 못함 |
| 위험 패턴 | 스킬·MCP 코드에서 문구로 찾는 위험한 모양(원격 실행, 비밀값 내보내기, 넓은 권한) | 출처: docs/GLOSSARY.md 위험 패턴 |
| 고친 버전 | 보안 경고의 취약점이 고쳐진 버전(OSV가 알려 준 값) | 출처: docs/GLOSSARY.md 고친 버전 |
| 변경 | 바깥에서 생긴 변화 한 건. 안내서의 "사건"이 우리 말로 변경 | 출처: docs/GLOSSARY.md 변경 |
| 알림 | 사용자에게 판단을 요청하는 한 건. 보안 경고와 적용 기회 두 종류 | 출처: docs/GLOSSARY.md 알림 |
| 보안 경고 | 내 기술의 보안 등급이 위험으로 바뀌어 생기는 알림 | 출처: docs/GLOSSARY.md 보안 경고 |
| 적용 기회 | 새 기술이 내 기술과 확정된 같은 역할이라 생기는 알림 | 출처: docs/GLOSSARY.md 적용 기회 |
| 모델 종료 | 내 코드에 문자열로 쓴 모델 이름이 공식 지원 종료 공지에 있어 생기는 알림. 종료일·공식 추천 대체·찾은 파일을 보여 줌 | 출처: docs/GLOSSARY.md 모델 종료 |
| 첫 점검 | 처음 읽을 때 위험인 기술만 보안 경고를 1번 만드는 점검 | 출처: docs/GLOSSARY.md 첫 점검 |
| 판단 | 알림에 대한 적용 후보 또는 보류 결정. 판단 전에는 아무것도 안 바뀜. 11-20부터 알림이 없어도 기술에 판단 상태(쓰는 중·적용 후보·관심·보류)를 남길 수 있고, 판단은 기록일 뿐 설치하지 않음 | 출처: docs/GLOSSARY.md 판단, ADR 0028 |
| 적용 후보 | 판단의 한 가지. 보안 경고에서는 "고친 버전으로 올리기" | 출처: docs/GLOSSARY.md 적용 후보 |
| 보류 | 판단의 다른 한 가지, 이유 5자 이상. 불변 4의 "거절"을 우리 말로 | 출처: docs/GLOSSARY.md 보류 |
| 조치 | 우리 서비스에서는 판단 저장(적용 후보 기록 / 보류 사유 기록) | 출처: docs/GLOSSARY.md 조치 |
| 판단 대기 / 완료 | 알림의 상태 두 가지. 완료는 판단을 마쳤다는 뜻이지 실행했다는 뜻이 아님 | 출처: docs/GLOSSARY.md 판단 대기 / 완료 |
| 판단 기록 | 판단과 이유를 남긴 것, 비슷한 기술이 나오면 다시 보여 줌 | 출처: docs/GLOSSARY.md 판단 기록 |
| 대응안 초안 | 알림 상세에서 Claude가 쓰는 짧은 대응 제안, 변경마다 한 번 | 출처: docs/GLOSSARY.md 대응안 초안 |
| 적용 시나리오 | 기술을 넣는 방법을 Claude가 쓴 참고 자료, 요청할 때만 만듦 | 출처: docs/GLOSSARY.md 적용 시나리오 |
| 설치 프롬프트 | 고른 내 기술을 다른 컴퓨터의 Claude에 붙여 넣는 설치 안내 글, 정해진 틀로만 | 출처: docs/GLOSSARY.md 설치 프롬프트 |
| 내 컴퓨터 목록 가져오기 | 전역으로 깐 MCP·스킬 목록을 정해진 형식으로 출력하게 하는 글 | 출처: docs/GLOSSARY.md 내 컴퓨터 목록 가져오기 |
| 알파 | 필수 기능 외 우리 사용자에게 도움이 되는 기능, v1은 설치 프롬프트 + 목록 가져오기 | 출처: docs/GLOSSARY.md 알파 |
| 수집 오류 | 읽기에 실패한 상태. "변화 없음"·"삭제됨"으로 단정하지 않음 | 출처: docs/GLOSSARY.md 수집 오류 |
| 수집 자료 | 출처에서 읽은 값 중 바뀐 것만 남긴 한 줄(이전 값 → 현재 값) | 출처: docs/GLOSSARY.md 수집 자료 |
| 실행 기록 | 시작 방식 6가지가 한 번 돌 때마다 남는 기록(`runs`, `run_steps`) | 출처: docs/GLOSSARY.md 실행 기록 |
| 시뮬레이터 | 가짜 취약점·가짜 새 기술로 알림 흐름을 시연하는 장치 | 출처: docs/GLOSSARY.md 시뮬레이터 |
| 얇은 기술 / 두꺼운 기술 | 카탈로그에 얼마나 깊게 모으는지(두꺼우면 등급·정기 확인까지) | 출처: docs/GLOSSARY.md 얇은 기술 / 두꺼운 기술 |
| 관리자 | DB 역할 칸이 admin인 팀원. 남의 알림에는 판단할 수 없음 | 출처: docs/GLOSSARY.md 관리자 |
| 영역 | 팀원 한 명이 맡는 기능 묶음(A 지키기, B 고르기, C 옮기기·운영) | 출처: docs/GLOSSARY.md 영역 |
| 조각 / 이정표 | 하루 안에 끝낼 일 하나(`P-n`) / 여러 조각이 합쳐진 지점(M0–M2) | 출처: docs/GLOSSARY.md 조각, 이정표 |
| 필터 (지도 보기) | 지도에서 보고 싶은 기술만 남기는 조건(종류·하는 일·위험·주의만·수집 오류만·NEW만·내 기술과 비교군). 화면 글자는 "필터"(전에는 "거르기"). 카탈로그에 넣을 때의 "관문"과 다름 | 출처: docs/GLOSSARY.md 필터 (지도 보기), 2026-11-20 |
| 이 분류만 보기 | 지도에서 묶음 하나를 골라 그 안의 기술만 다시 펼쳐 보는 것. 위에 경로 칩이 생기고 주소로 공유됨 | 출처: docs/GLOSSARY.md 이 분류만 보기, 2026-11-20 |
| NEW | 이번 주(7일 안) 카탈로그에 새로 들어온 기술 표시. 처음 채운 날과 레지스트리 첫 전체 읽기(대량 채우기) 동안 들어온 기술은 NEW가 아님 | 출처: docs/GLOSSARY.md NEW |
| 내 레이더 | 내 기술을 판단 상태별 칸반(관심 → 적용 후보 → 쓰는 중, 보류)에 놓은 화면(`/views`), 대시보드 숫자를 함께 보여 줌 | 출처: docs/GLOSSARY.md 내 레이더, ADR 0028 |
| 코드 동결 | 새 기능을 더 넣지 않고 고치기만 하는 때. 2026-11-23(월) 18:00부터(11-20 21:00에서 늦춤), 제출은 같은 날 23:59 | 출처: docs/GLOSSARY.md 코드 동결 |

## 피할 말 (사실처럼 쓰지 않음)
- 아래 낱말은 GLOSSARY에서 "_Avoid_"(피할 말)로만 나온다. 이 서비스의 기능 이름이 아니다. (출처: docs/GLOSSARY.md 각 항목의 _Avoid_ 줄)
- 백업: 목록 내보내기·설치 프롬프트의 피할 말이다. 저장소 문서에 DB 백업 주기는 정해져 있지 않다. (출처: docs/GLOSSARY.md 목록 내보내기·설치 프롬프트 _Avoid_)
- 자동 백업, 노션 동기화: 노션으로 보내기(다음 버전)의 피할 말. 한 방향 쓰기라서. (출처: docs/GLOSSARY.md 노션으로 보내기 _Avoid_)
- 이사, 자동 설치: 대신 깔아 주는 것으로 들려 피한다. 우리는 설치하지 않는다. (출처: docs/GLOSSARY.md 설치 프롬프트 _Avoid_)
- 승인, 결재, 채택: "판단"·"적용 후보"로 쓴다. (출처: docs/GLOSSARY.md 판단·적용 후보 _Avoid_)
- 거절, 무시, 삭제: "보류"로 쓴다. (출처: docs/GLOSSARY.md 보류 _Avoid_)
- 처리 완료, 승인됨: "완료"로 쓰고 실행했다는 뜻으로 쓰지 않는다. (출처: docs/GLOSSARY.md 판단 대기 / 완료 _Avoid_)
- 사건, 이벤트: 안내서와 짝지을 때만 "사건", 평소엔 "변경". (출처: docs/GLOSSARY.md 변경 _Avoid_)
- 안전한 버전, 최신 버전: "고친 버전"으로 쓴다. 다른 문제가 없다는 뜻이 아니라서. (출처: docs/GLOSSARY.md 고친 버전 _Avoid_)
- 없음, 통과: 확인하지 못한 것은 "찾지 못함"으로 쓴다. (출처: docs/GLOSSARY.md 찾지 못함 _Avoid_)
- 삭제됨, 사라짐: 읽기 실패는 "수집 오류"로 쓴다. (출처: docs/GLOSSARY.md 수집 오류·기술 상태 _Avoid_)
- 추천: 적용 기회와 다르다. 추천은 3순위의 따로 있는 기능이다. (출처: docs/GLOSSARY.md 적용 기회·추천 _Avoid_)
- 테스트 계정: 발표용은 "시연 계정"으로 쓴다. (출처: docs/GLOSSARY.md 시연 계정 _Avoid_)
- 거르기: 지도 화면에서는 옛 글자이고 지금은 "필터"로 쓴다. (출처: docs/GLOSSARY.md 필터 (지도 보기) _Avoid_)
- 드릴다운, 확대: "이 분류만 보기"로 쓴다. (출처: docs/GLOSSARY.md 이 분류만 보기 _Avoid_)

## 지금 쓰지 않는 말
- 필요, 발견: 접은 가설 B의 용어로 지금 서비스에서는 쓰지 않는다. (출처: docs/GLOSSARY.md 필요·발견)
- 평판 요약: v1에서 하지 않는다. (출처: docs/GLOSSARY.md 평판 요약)
- 펼치기, 검사 전, 중심 보기: 제안 단계이고 팀 확인 전이다. (출처: docs/GLOSSARY.md 펼치기·검사 전·중심 보기)

## 문서끼리 다른 곳
- GLOSSARY "알림"은 "적용 기회와 보안 경고 두 종류"라고 쓴다(출처: docs/GLOSSARY.md 알림) / 같은 GLOSSARY "모델 종료"와 spec SPEC-3.3은 모델 지원 종료도 알림으로 만든다고 쓴다(출처: docs/GLOSSARY.md 모델 종료, docs/spec.md 3절 SPEC-3.3).
