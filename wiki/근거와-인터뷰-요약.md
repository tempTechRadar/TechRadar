# 근거와 인터뷰 요약

> 문제정의의 근거는 팀 밖 사람 인터뷰 2건(대표1, 그룹1 4명)이 전부이고, AI 인터뷰 3건은 가설, 팀원 본인 인터뷰는 힌트로만 쓴다. (출처: docs/문제정의.md 머리말·3절)

## 근거를 세는 규칙
- 팀 밖 사람 2명 이상에게서 나온 주장만 중심에 둔다. (출처: docs/문제정의.md 3절 판정)
- 팀원 본인 인터뷰(인터뷰 A)와 AI 인터뷰는 세지 않는다. (출처: docs/문제정의.md 3절 판정)
- AI 인터뷰는 "확인한 근거"에 넣지 않고 "AI 인터뷰 가설" 칸에만 적는다. (출처: docs/문제정의.md 6절 근거 표)
- 각 인터뷰는 "잰 것 / 당사자 말 / 팀 추정"을 나눠 적는다. (출처: interviews/2026-11-16-수강생A-AI.md 기록표, interviews/2026-11-17-대표1-사람.md 4절)

## 사람 인터뷰 (팀 밖)
- 그룹1: 부트캠프 노트북을 과정 끝에 초기화·반납하는 참여자 4명(P1–P4), 동의 문구 읽음. (출처: interviews/2026-11-17-그룹1-사람.md 머리 표)
- 그룹1 당사자 말: 깐 것이 정리 없이 흩어져 있고, 정리해 둔 목록이 없다(P1). (출처: interviews/2026-11-17-그룹1-사람.md 1절)
- 그룹1 당사자 말: 반납 전에 세팅을 정리해 내 컴퓨터로 옮길 계획이다(P1, 아직 하지 않음). (출처: interviews/2026-11-17-그룹1-사람.md 1절)
- 그룹1 당사자 말: 다른 한 명은 막막해서 처음부터 다시 쌓으려 했다(P3 추정). (출처: interviews/2026-11-17-그룹1-사람.md 1절)
- 그룹1 팀 추정: 정리해 옮기려는 사람은 4명 중 3명, 발화자는 말투로 추정했다. (출처: interviews/2026-11-17-그룹1-사람.md 4절)
- 대표1: 스킬·MCP를 필요에 따라 쓰는 숙련 사용자(스타트업 대표), 동의 문구 읽음. (출처: interviews/2026-11-17-대표1-사람.md 머리 표)
- 대표1 당사자 말: 새 도구는 쇼츠·유튜브로 알고 휴대폰으로 캡처해 둔다. (출처: interviews/2026-11-17-대표1-사람.md 1절 Q1)
- 대표1 당사자 말: 쓰기 전 확인은 유명한지·사례뿐이고 캡처 당시 보안은 크게 신경 쓰지 않는다. (출처: interviews/2026-11-17-대표1-사람.md 1절 Q2·Q8)
- 대표1 당사자 말: 먼저 검색하는 편이라 있는 줄 몰라 놓친 경우는 드물다. (출처: interviews/2026-11-17-대표1-사람.md 1절 Q4)
- 대표1 당사자 말: MCP 없이 유료 API뿐이면 쓸지 고민한다. (출처: interviews/2026-11-17-대표1-사람.md 1절 Q11)
- 두 사람 인터뷰 모두 "잰 것"(정확한 수치)은 없다. (출처: interviews/2026-11-17-그룹1-사람.md 4절, interviews/2026-11-17-대표1-사람.md 4절)

## 사람 인터뷰의 한계
- 그룹1은 전사 끝부분만 있고 발화자 표시가 없어 Claude가 말투로 추정했다. (출처: interviews/2026-11-17-그룹1-사람.md 머리 표 한계)
- 그룹1은 그룹이라 서로 맞장구칠 수 있고, 자동 전사라 단어가 틀렸을 수 있다. (출처: interviews/2026-11-17-그룹1-사람.md 머리 표 한계)
- 대표1은 주제를 미리 알았고, 일부러 반대로 답했을 가능성이 있으며, 숙련자라 v1 대상과 다르다. (출처: interviews/2026-11-17-대표1-사람.md 머리 표 한계)
- 대표1에게는 Q5·Q6·Q7·Q9·Q10·Q12–Q14, 지도 질문 M1–M4를 묻지 못했다. (출처: interviews/2026-11-17-대표1-사람.md 1절)
- 초심자 근거는 그룹1뿐이다. (출처: docs/문제정의.md 3절 판정)
- 보안 상태가 바뀌어 실제로 손해 본 장면은 팀 밖 인터뷰에 없고 공개 자료뿐이다. (출처: docs/문제정의.md 6절 근거 표)

## 팀원 본인 인터뷰 (힌트)
- 인터뷰 A는 서비스를 만드는 팀원 본인 1명이라 자기 확인 편향이 있을 수 있어 힌트로만 쓴다. (출처: interviews/인터뷰-A-비전공수강생.md 머리 표)
- 내용 요약: 작업 중 막힐 때 도구가 있을 것 같지만 이름을 모르고, Claude에게 스킬을 찾아 달라고 자주 시킨다. (출처: interviews/인터뷰-A-비전공수강생.md 1·2절)

## AI 인터뷰 (가설, 실제 사람 아님)
- 수강생A·개발자B·대표C는 AI 페르소나에게 질문지로 물은 결과이고 숫자·날짜는 지어낸 것이다. (출처: interviews/2026-11-16-수강생A-AI.md 머리말, interviews/2026-11-16-대표C-AI.md 머리말)
- 수강생A 가설: 강사가 큐레이터 역할을 하고, 무엇을 확인할지 몰라 '공식' 표시에 맡긴다. (출처: interviews/2026-11-16-수강생A-AI.md 기록표)
- 개발자B 가설: 손해는 몰라서보다 깔고 나서 충돌해서 생기고, 지도는 안 볼 것 같다는 반대 근거. (출처: interviews/2026-11-16-개발자B-AI.md 기록표)
- 대표C 가설: 병목은 소식보다 팀 허용 판단과 데이터 정책 확인이다. (출처: interviews/2026-11-16-대표C-AI.md 기록표)
- 세 AI 인터뷰 모두 "잰 것"은 없음이고, 손해는 "한 달 몇 시간 수준" 같은 팀 추정뿐이다. (출처: interviews/2026-11-16-수강생A-AI.md 기록표, interviews/2026-11-16-개발자B-AI.md 기록표)

## 판정 결과
- 중심으로 올림: 깐 것을 한눈에 보지 못한다(그룹1 2명 추정). 다만 생태계 전체가 아니라 "내가 깐 것". (출처: docs/문제정의.md 3절 판정 표)
- 남김: 안전한지 모른 채 깐다(대표1 1명 + 공개 자료 P1–P5). (출처: docs/문제정의.md 3절 판정 표)
- 중심에서 내림: 몰라서 원하는 결과물을 포기한다(팀 밖 0명). (출처: docs/문제정의.md 3절 판정 표)
- 확인 못 함: Claude에게 찾아 달라고 시키는 방법과의 비교(Q5를 묻지 못함). (출처: docs/문제정의.md 3절 판정 표)
- 후보: 유료라서 망설인다(대표1 1명). (출처: docs/문제정의.md 3절 판정 표)

## 공개 자료 (사람 인터뷰 아님)
- P1–P5: 악성 MCP·탈취된 패키지·스킬 보안 결함에 대한 실제 사례와 연구. 업체 자료(P2, P4)는 이해관계가 있을 수 있다. (출처: docs/문제정의.md 6절 공개 자료 표)
- P5(학술): 공개 MCP 서버 1,899개 중 5.5%에서 도구 오염, 7.2%에서 일반 취약점. (출처: docs/문제정의.md 6절 P5)
- P6·P13(팀이 직접 집계): Claude Code 릴리스 빈도, 공식 MCP 레지스트리가 13시간에 100건 넘게 바뀜. (출처: docs/문제정의.md 6절 P6·P13)
- P7은 2차 보도만 있는 숫자다. (출처: docs/문제정의.md 6절 P7)
- 반대 자료 P11·P12: 바이브 코딩이 자기 업무가 아니라는 응답이 많고, 사용자는 소수 인기 스킬로 몰린다. (출처: docs/문제정의.md 6절 P11·P12)

## 잴 숫자
- 주 숫자(회의 D4): 내 기술 목록 가운데 보안 등급과 이유를 확인한 기술의 비율. (출처: docs/문제정의.md 7절)
- 보조 숫자: 알림부터 판단까지 걸린 시간, 설치 전에 보안을 확인한 비율. (출처: docs/문제정의.md 7절)
- 판단 시간의 지금 값은 인터뷰에서 얻지 못해 당사자 말로 대신한다. (출처: docs/문제정의.md 7절·11절)
