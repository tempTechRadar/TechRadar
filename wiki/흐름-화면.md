# 흐름 화면

> 흐름 화면(관리자 탭 IA-16, 사용자의 내 실행 기록 IA-11)은 `flow/flow.json`의 상자·화살표 위에 실제 실행 기록(`runs`, `run_steps`)을 칠한다. 미리 그린 가짜 불빛은 쓰지 않는다. (출처: docs/flow.md 머리말, CLAUDE.md 3절 불변 6)

## 두 길
- 카탈로그 수집 길: 매일 예약 실행 또는 지금 실행 → 바깥 출처 → 같은 모양 → 비교 → 등급 → 사건인가. (출처: docs/flow.md 1절)
- 내 저장소 길: 처음 등록하거나 다시 읽기 → 내 저장소 → 내 기술 뽑기 → 등급 → 사건인가. (출처: docs/flow.md 1절)
- 두 길은 "등급 계산"에서 만난다. (출처: docs/flow.md 1절)
- 상자는 모두 27개다. (출처: docs/flow.md 바뀐 기록 2026-11-18 초안, flow/flow.json nodes)

## 상자마다 실패하면
- 바깥 출처 상자가 실패하면 그 기술·출처만 수집 오류로 남고 다른 상자는 계속 돈다. (출처: docs/flow.md 2절 fetch_osv·fetch_github 행)
- 다운로드 수집이 일부 기술에서 실패하면 그 기술의 이전 값을 그대로 둔다. 404를 0으로 읽지 않는다. (출처: docs/flow.md 2절 fetch_downloads 행)
- 대응안 초안이 실패해도 알림은 만들고 초안 칸은 "만들지 못함"으로 둔다. (출처: docs/flow.md 2절 summarize 행)
- 판단 저장이 실패하면 둘 다 그대로 두고 "저장하지 못했어요"를 보인다. (출처: docs/flow.md 2절 action_record 행, CLAUDE.md 3절 불변 4)
- 같은 변경이 이미 있으면 새로 만들지 않고 그 변경에 잇는다. (출처: docs/flow.md 2절 save_change 행, CLAUDE.md 3절 불변 3)

## 칠하는 규칙
- 상자 색은 `run_steps.status`로 칠한다: 회색 아직 안 켜짐, 파랑 실행 중, 초록 성공, 빨강 실패, 주황 점선 판단 대기. (출처: docs/flow.md 3절)
- 누른 시작에서 출발한 길만 굵게, 그 시작 상자는 굵은 테두리다(`runs.trigger`). (출처: docs/flow.md 3절)
- 화살표 위 숫자는 넘어간 건수다. 분기는 갈래마다 건수를 보인다(`count_in`·`count_out`·`branch_counts`). (출처: docs/flow.md 3절, docs/erd.md 2.4절 run_steps)
- 바깥 서비스 상자 위에는 작은 표시(OSV, GitHub, Claude …)를 단다(`flow.json`의 `badge`). (출처: docs/flow.md 3절)
- 상자를 누르면 설정·들어온 것·나간 것·호출·오류가 보이고, 비밀값·개인정보는 가린다. (출처: docs/flow.md 3절)
- 실행 목록은 새로고침해도 남고, 줄을 누르면 그 실행의 길과 색으로 바뀐다(`runs`). (출처: docs/flow.md 3절)
- 사람 판단 상자는 주황 점선으로 멈춰 있다가, 판단이 저장되면 같은 실행의 "조치와 기록"이 초록으로 켜진다. 판단 전에는 켜지지 않는다. (출처: docs/flow.md 3절)
- 시나리오는 점선 화살표다. 참고 자료라 판단 대기 중에도 켜질 수 있다. (출처: docs/flow.md 3절, docs/adr/0010-적용-시나리오는-참고-자료.md)
- 사용자 화면(IA-11)은 자기가 시작한 `first_read`·`user_reread` 실행만 같은 그림으로 본다(RLS). (출처: docs/flow.md 3절)

## 가짜 불빛 금지
- 흐름 화면은 실제 실행 기록(`runs`, `run_steps`)을 읽어 그린다. 미리 그린 가짜 불빛은 안 된다. (출처: CLAUDE.md 3절 불변 6)
- 데이터에서는 `runs`·`run_steps`만 읽는 것으로 지킨다. (출처: docs/데이터설계.md 5절)
- 단계로 남기지 않는 상자는 실제 실행에서 늘 회색일 수 있다: 처음 읽기·정기 수집의 `no_change`, 처음 읽기의 `collect_error`. 이때는 화살표 위 건수로 본다. (출처: docs/flow.md 3절, docs/flow.md 2절 no_change·collect_error 행)
- 위험이 없는 읽기는 `notify`를 부르지 않아 상자가 켜지지 않는다. 의도한 동작이다. (출처: docs/flow.md 2절 notify 행)
- 사용자가 시작한 읽기 실행은 `notify` 건수를 시작한 사람 기준으로만 남긴다. 남의 사용 규모가 드러나지 않게 하려는 것이다. (출처: docs/flow.md 2절 notify 행, docs/flow.md 바뀐 기록 2026-11-18 P-3)

## 시연에서 실패를 보여 주는 법
| 시연 | 하는 일 | 보이는 것 | 출처 |
|---|---|---|---|
| 수집 오류 | 한 출처 주소를 일부러 틀리게 두고 지금 실행 | 그 API 상자가 빨강, 오류 종류 표시, 나머지 상자는 계속 | 출처: docs/flow.md 4절 |
| 사건 아님 | 같은 값으로 두 번 실행 | "변화 없음" 갈래 숫자만 늘고 알림 없음 | 출처: docs/flow.md 4절 |
| 중복 | 시뮬레이터를 같은 시나리오로 두 번 | 두 번째는 새 변경 없음, 새 알림 0건, 알림 수 그대로 | 출처: docs/flow.md 4절 |
| 판단 대기 | 시뮬레이터로 가짜 취약점 | 사람 판단에서 주황 점선으로 멈춤 → 판단하면 조치와 기록이 켜짐 | 출처: docs/flow.md 4절 |
| 저장 실패 | 시연용 스위치로 판단 저장을 실패시킴 | 조치 상자 빨강, 알림은 판단 대기 그대로 | 출처: docs/flow.md 4절 |

- 위 다섯은 시연 스위치가 켜진 곳(지금은 로컬)에서만 된다. 운영 배포는 스위치를 끈다. (출처: docs/flow.md 4절 표 아래)
- 배포 주소에서는 package.json을 일부러 깨 둔 공개 시연 저장소를 등록해 "처음 등록 읽기"를 실패로 만든다: 시작 상자와 `extract_my_tech`가 빨강, `fetch_repo`는 초록. 이 결정(ADR 0024)의 상태는 제안이다. (출처: docs/flow.md 4절 표 아래, docs/adr/0024-배포-주소의-실패-시연은-진짜-입력으로.md 상태)

## 운영 화면 캡처
- 운영 주소에서 관리자 계정으로 연 실제 실행 기록 캡처 두 장이 `docs/flow.md` 6절 "화면 캡처"에 있다(2026-11-20). 그림은 여기에 옮기지 않는다. (출처: docs/flow.md 6절)
- ① 시뮬레이터 실행이 성공해 사람 판단에서 주황 점선으로 멈춘 모습. (출처: docs/flow.md 6절 ①)
- ② 일부러 실패시킨 실행: 깨진 `package.json` 저장소를 등록하자 처음 등록 읽기와 내 기술 뽑기가 빨강, 내 저장소 파일 읽기는 초록, 뒤 상자는 0건. 사건은 생기지 않았다. (출처: docs/flow.md 6절 ②)

## 알림이 앱 안인 이유
- v1 알림은 앱 안(알림 목록·지도 띠)만 쓴다. 그래서 알림 상자는 바깥 서비스 표시가 없는 DB 저장 상자다. (출처: docs/flow.md 5절)
- 메일·메신저 알림은 다음 버전으로 미뤘다. (출처: docs/flow.md 5절)
