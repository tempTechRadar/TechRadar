# 화면 구조

> 화면 ID(IA-1~IA-23) 목록: 사용자 화면과 관리자 화면, 모든 화면의 공통 상태, 11-20에 바뀐 지도와 화면 흐름, 11-23에 바뀐 화면(관측소 테마 · 지도 · 청사진 · 관리자). (출처: docs/ia.md 1·3·4·5절, docs/adr/0026·0027·0028·0029)

## 큰 틀
- 메뉴는 "사용자 메뉴(본인 데이터만)"와 "관리자 메뉴(관리자만)" 둘로 나뉜다. 사용자 메뉴는 왼쪽 기술 지도 · 새 기술 · 추천 · 내 레이더 · 알림 · 기록, 오른쪽 + 기술 넣기 · 내 프로젝트 · 설정이다. 기술 지도는 로그인 전에도 보인다. (출처: docs/ia.md 1절)
- 관리자 메뉴는 화면·서버·DB 모두에서 막는다. (출처: docs/ia.md 1절, 불변 5)
- 로그인 뒤 첫 화면은 기술 지도(IA-10)다(회의 D8). (출처: docs/ia.md 1절·7절 D8)
- 화면 ID는 요구·PR·QA에서 `IA-n`으로 부른다. (출처: docs/ia.md 머리말)

## 11-20에 바뀐 지도와 화면 흐름
- 로그인 전에도 누구에게나 같은 카탈로그 지도를 보여 준다. (출처: docs/adr/0029-로그인-전-지도는-RLS를-열지-않고-서버가-공개-칸만-읽는다.md 배경)
- 로그인 전 지도는 `anon`의 RLS를 열지 않고, 서버가 공용 표(`technologies`·`categories`)의 공개 칸만 읽어 그린다. 개인 표는 읽지 않는다. (출처: docs/adr/0029-로그인-전-지도는-RLS를-열지-않고-서버가-공개-칸만-읽는다.md 결정 1–3)
- 지도의 묶기는 사용자가 1~3단계로 고른다(하는 일 · 세부 갈래 · 종류 · 쓰는 곳 · 보안 등급 · 내 프로젝트). 기본은 하는 일 › 종류다. (출처: docs/ia.md 3절 IA-10 "11-20 바뀜", docs/adr/0026-지도는-사용자가-고르는-묶기와-분류-색.md 결정 1)
- 색은 고른 기준의 값이고, 보안은 기호로 보인다(위험 · 주의 · 수집 오류). NEW 표시가 있다. 인기 크기 · 오래됨 흐림 · 지도 위 업데이트는 쓰지 않고 카드 · 사이드바에 둔다. (출처: docs/ia.md 3절 IA-10 "11-20 바뀜", docs/adr/0026-지도는-사용자가-고르는-묶기와-분류-색.md 결정 2·3)
- 로그인 뒤 첫 지도의 기본은 전체 지도다. "내 기술과 비교군(한 단계)"은 필터 하나와 칩으로 둔다(11-23부터 화면 말 "사용 중인 항목과 비교군"). 로그인 전에는 이 필터가 없다. (출처: docs/ia.md 3절 IA-10·IA-Q5 "11-20 바뀜", docs/adr/0027-로그인-뒤-지도는-전체로-내-기술과-비교군은-필터로.md 결정 1–3, 바뀌지 않는 것)
- 기술을 누르면 지도를 떠나지 않고 오른쪽 패널이 열린다. "전체 상세 보기"로 기술 상세(IA-4)에 간다. (출처: docs/adr/0028-1차-목적을-기술-지형-조망과-스스로-판단으로.md 결정 1)
- (11-23 바뀜: 지금 IA-5는 프로젝트 관리 보드의 숫자 띠다. 아래 IA-5 행 참고, 출처: docs/ia.md 3절 IA-5 "11-23 바뀜") 11-20에는 대시보드(IA-5)를 "내 레이더" 화면이 맡았다: 위에 안내서 숫자(내 기술 수, 변경 수, 판단 대기 / 완료), 아래에 판단 상태별 칸반(관심 → 적용 후보 → 쓰는 중, 보류)과 목록. (출처: docs/adr/0028-1차-목적을-기술-지형-조망과-스스로-판단으로.md 결정 3)
- 내 레이더의 주소는 `/views`, 새 기술은 `/new`다. (출처: docs/ia.md 1절)
- ADR 0028은 메뉴를 다섯(기술 지도 · 새 기술 · 내 레이더 · 알림 · 기록, 오른쪽에 내 프로젝트)으로 정했고, 그 뒤 P-23으로 추천이 더해져 지금은 여섯이다. (출처: docs/adr/0028-1차-목적을-기술-지형-조망과-스스로-판단으로.md 결정 5, docs/ia.md 1절·바뀐 기록 11-20)

## 11-23에 바뀐 화면
- 테마는 어두운 관측소(남색 밤하늘 바탕 · 청록 강조) 한 벌이고, 관리자 화면까지 컴팩트하게 줄였다. 마우스 화면 단추는 34px, 손가락 화면은 44px 그대로다. (출처: docs/adr/0044-관측소-테마-남색-밤하늘-청록-강조-컴팩트.md 결정 1 · 6, 토큰과 대비)
- 메뉴 오른쪽 상태 줄은 `마지막 수집 hh:mm │ ● 출처 m │ ● 수집 오류 k`다. 출처 m은 이름이 `fetch_`로 시작하는 가져오기 단계 수, 수집 오류 k는 수집 오류 단계 · 오류 종류 · 실패 단계를 세고 같은 출처의 짝은 한 번만 센다. 마지막 정기 실행의 `runs` · `run_steps`만 읽는다. (출처: docs/adr/0044-관측소-테마-남색-밤하늘-청록-강조-컴팩트.md 결정 3)
- 색의 뜻: 판단 대기 = 얼음 파랑, 완료 = 회색, 수집 오류 = 회색 점선. 초록은 "통과"에만, 청록은 주 행동 · 탐색선에만 쓴다. (출처: docs/adr/0044-관측소-테마-남색-밤하늘-청록-강조-컴팩트.md "P-12n 공통 색 뜻")
- 지도의 기본 보기는 "LS점프업"(스킬 · 플러그인 · 개념 · 개발 도구 · "AI 작업 방식" 규칙 + 팀이 고른 목록)이다. 첫 화면 관문("Ready to Catch?")은 없어졌고, 처음 연출은 파동 하나와 옅은 잔물결, 도는 선은 뒤에서 아주 옅게 돈다. (출처: docs/adr/0044-관측소-테마-남색-밤하늘-청록-강조-컴팩트.md "뒤이어 바뀐 것", docs/GLOSSARY.md LS점프업)
- 지도 사이드 패널 · 기술 상세 · 청사진 서랍의 한 줄 설명은 한국어 개요를 먼저 보이고 "AI 번역" 표시와 [원문 보기]를 붙인다. (출처: docs/adr/0045-AI를-쓰는-두-곳-청사진-프롬프트-진단-기술-한국어-개요.md 결정 2)
- 청사진에서 단계 2개 이상을 섹션으로 묶으면 섹션이 공통 기술을 따로 가지고, 내보내기에 섹션 머리 줄이 한 번 들어간다. (출처: docs/GLOSSARY.md 섹션, GitHub PR #221 설명)
- 청사진 확정본의 "점검 받기"는 프롬프트 진단(중복 · 충돌 · 순서 · 다듬은 프롬프트)까지 주고 "AI 제안 · 검증 아님"을 붙인다. 청사진과 원래 내보내기는 바뀌지 않는다. (출처: docs/adr/0045-AI를-쓰는-두-곳-청사진-프롬프트-진단-기술-한국어-개요.md 결정 1)
- 청사진 오른쪽 아래 가이드 캐릭터는 문제정의를 묻고 단계 · 기술 후보를 제안만 한다. 넣기는 사용자가 누르고, 로그인한 사람만 하루 20번 쓴다. (출처: docs/adr/0045-AI를-쓰는-두-곳-청사진-프롬프트-진단-기술-한국어-개요.md "같은 날 저녁 일곱으로", GitHub PR #230 설명)
- 청사진 단계는 근처에 놓아도 저절로 잇지 않는다(잇기는 점에서 선을 끌 때만). 카드 아래 [＋ 나란히]로 같은 순서에 단계를 더한다. (출처: GitHub PR #230 설명 "사용자 추가 2개")
- 청사진 아래 "기술" 탭에서 기술을 누르거나 Enter를 치면 오른쪽 서랍(휴대폰은 창)에 상세가 열린다. 판에 없는 기술도 열린다. (출처: GitHub PR #231 설명)
- 관리자 첫 화면(`/admin`)은 관제 요약(마지막 정기 실행 · 수집 오류 · 판단 대기 · 신고 · 분류 거리)이다. 못 읽은 숫자는 0이 아니라 "읽지 못함"으로 보이고, 왼쪽에 묶음 메뉴 4개가 있다. (출처: GitHub PR #227 설명)
- 관리자 화면은 모두 같은 순서를 따른다: 머리 → 툴바 → 알림 → 숫자 띠 → 필터 → 섹션. (출처: GitHub PR #229 설명)
- 관리자는 일반 계정을 관리자로 지정하고 다른 관리자를 일반으로 되돌린다(탭 "회원과 권한"). 둘 다 DB 함수로만 하고, 자기 자신과 마지막 관리자는 되돌리지 못하며 사유와 함께 기록이 남는다. (출처: docs/erd.md 4절 profiles 줄, GitHub PR #212 · #215 설명)

## 관리자 화면
- 일반 사용자가 주소나 API로 직접 요청해도 막는다(화면·서버·DB). (출처: docs/ia.md 4절 머리말)
- 관리자가 무언가를 고치면 담당자·시각·사유가 남는다. (출처: docs/ia.md 4절 머리말)
- 관리자도 남의 알림에는 판단을 대신하거나 건너뛸 수 없다. 본인 알림은 사용자 메뉴의 IA-7에서 판단한다. (출처: docs/ia.md 4절 머리말, docs/adr/0016-관리자도-본인-알림은-판단할-수-있다.md)

## 모든 화면의 공통 상태
| 상태 | 보여 줄 것 | 출처 |
|---|---|---|
| 데이터 없음 | "아직 등록한 프로젝트가 없어요" 등 + 다음 할 일 버튼 | 출처: docs/ia.md 5절 |
| 조회 실패 | "불러오지 못했어요" + 다시 시도. 데이터 없음과 다른 모양 | 출처: docs/ia.md 5절 |
| 수집 오류 | 해당 기술·출처에 "수집 오류". "변화 없음"·"삭제됨"으로 단정하지 않음 | 출처: docs/ia.md 5절, 불변 2 |
| 권한 없음 | 다른 사람 데이터나 관리자 주소에 들어오면 막고 안내 | 출처: docs/ia.md 5절, 불변 5 |
| 판단 대기 | 첫 화면 지도 띠·알림·대시보드에서 눈에 띄게 | 출처: docs/ia.md 5절, 불변 1 |

## 화면 크기와 알림 방식
- 대시보드(IA-5)와 알림(IA-6, IA-7)만 휴대폰에서 깨지지 않게 맞추고, 나머지는 PC 기준이다. (출처: docs/ia.md 5절, IA-Q8)
- 알림은 앱 안에서만 보여 주고 메일·메신저로 보내지 않는다. (출처: docs/ia.md 5절, IA-Q7)
