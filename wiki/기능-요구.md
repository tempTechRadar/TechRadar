# 기능 요구

> PRD 기능 요구(PRD-F1–F44)를 만드는 순서(1순위 핵심 길, 2순위 알파, 3순위 확장 여지, 따로, 다음 버전)별로 한 줄씩 모은 쪽. (출처: docs/prd.md 2절 만드는 순서)

## 순서를 정한 방법
- 기능을 잘라 내지 않고 모두 순위를 붙이며, 위 순위부터 되는 데까지 만든다. (출처: docs/prd.md 2절 만드는 순서)
- 1순위 안의 첫 이정표는 "얇은 한 줄": OSV 1곳 → 보안 경고 1종류 → 판단 저장 → 기록 → 흐름 화면. (출처: docs/prd.md 2절 만드는 순서 1-0)
- 안내서 필수 8가지와 알파가 어느 요구로 채워지는지는 PRD 1절 표에 있다. (출처: docs/prd.md 1절)

## 1순위: 핵심 길
- PRD-F1: 구글 계정으로 가입·로그인·로그아웃. 이메일 테스트 계정은 개발·QA 환경에서만. (출처: docs/prd.md 2절 PRD-F1)
- PRD-F3: 관리자는 DB 역할 칸으로 정하고, 관리자 화면·API는 관리자만 쓴다. (출처: docs/prd.md 2절 PRD-F3)
- PRD-F4: 공개 GitHub 저장소 주소로 프로젝트를 여러 개 등록한다(수정·보관은 3순위). 수정·보관은 PR #194로 합쳐졌다. (출처: docs/prd.md 2절 PRD-F4, docs/plan.md 4절 P-22)
- PRD-F5: 사람마다 "프로젝트 밖(내 컴퓨터)" 칸이 자동으로 생긴다. (출처: docs/prd.md 2절 PRD-F5)
- PRD-F6: 저장소 파일을 읽어 AI 코딩 도구만 내 기술 목록에 넣고 기술 키로 카탈로그에 잇는다. (출처: docs/prd.md 2절 PRD-F6)
- PRD-F7: 기술 직접 추가·직접 숨김·되돌리기, 바꿀 때마다 누가·언제 남김. (출처: docs/prd.md 2절 PRD-F7)
- PRD-F8: 출처(OSV, MCP 레지스트리, GitHub, npm·PyPI)를 하루 1번 + "지금 한 번 실행"으로 모으고 바뀐 것만 남김. (출처: docs/prd.md 2절 PRD-F8, 만드는 순서 1 행)
- PRD-F9: 읽기 실패는 "수집 오류"로 남기고 연속 실패는 관리자 화면에 보인다. (출처: docs/prd.md 2절 PRD-F9)
- PRD-F10: 기술마다 코드 규칙으로 보안 등급(통과/주의/위험/찾지 못함)과 쉬운 이유·근거 링크. (출처: docs/prd.md 2절 PRD-F10)
- PRD-F11: 보안 경고: 내 기술 등급이 위험으로 바뀌면 사건을 만든다. (출처: docs/prd.md 2절 PRD-F11)
- PRD-F12: 적용 기회: 새 기술이 관리자가 확정한 같은 역할이면 사건을 만든다. (출처: docs/prd.md 2절 PRD-F12)
- PRD-F13: 같은 변경을 다시 읽어도 사건·알림이 두 번 생기지 않는다. (출처: docs/prd.md 2절 PRD-F13)
- PRD-F14: 알림은 앱 안에서만, 판단 대기 수는 첫 화면 띠에. (출처: docs/prd.md 2절 PRD-F14)
- PRD-F15: 알림 상세에 이전 값 → 현재 값, 쉬운 이유, Claude 대응안 초안과 출처. (출처: docs/prd.md 2절 PRD-F15)
- PRD-F16: 적용 기회 알림에 내 기술과의 비교표(5개 항목, 항목마다 출처). (출처: docs/prd.md 2절 PRD-F16)
- PRD-F17: 알림마다 적용 후보 또는 보류(이유 필수)로 판단, 판단 전에는 아무것도 안 바뀜. (출처: docs/prd.md 2절 PRD-F17)
- PRD-F18: "적용 시나리오 만들기"를 누를 때만 Claude가 시나리오를 만든다. 설치는 안 함. (출처: docs/prd.md 2절 PRD-F18)
- PRD-F19: 판단·시나리오 저장 실패 시 판단 대기로 남고 다시 시도할 수 있다. (출처: docs/prd.md 2절 PRD-F19)
- PRD-F20: 기록 찾기: 지난 판단과 이유를 이름·종류·결과·기간으로, 본인 것만. (출처: docs/prd.md 2절 PRD-F20)
- PRD-F21: 새 알림 상세에 비슷한 과거 판단과 이유를 함께 보여 준다. (출처: docs/prd.md 2절 PRD-F21)
- PRD-F22: 대시보드: 내 기술 수, 변경 수, 판단 대기/완료 수, 최근 변경. (출처: docs/prd.md 2절 PRD-F22)
- PRD-F24: 갈래 나무는 "하는 일" 한 축 2단계, 같은 역할 확정은 관리자 확인만. (출처: docs/prd.md 2절 PRD-F24)
- PRD-F26: 내 실행 기록: 내 저장소를 읽은 실행마다 성공·실패·시간·건수. (출처: docs/prd.md 2절 PRD-F26)
- PRD-F27: 관리자 화면: 회원별 등록, 수집 자료, 알림 현황(판단 버튼 없음), 실행과 오류. (출처: docs/prd.md 2절 PRD-F27)
- PRD-F28: 흐름 화면: `flow/flow.json`의 상자와 화살표를 실제 실행 기록으로 그린다. (출처: docs/prd.md 2절 PRD-F28)
- PRD-F29: 시뮬레이터: 가짜 취약점 1건과 가짜 새 MCP 서버 1건으로 알림 2건. (출처: docs/prd.md 2절 PRD-F29)
- PRD-F30: 채점 파일: 정답 사건과 실제 사건을 비교해 맞음·놓침·잘못 울림 수. (출처: docs/prd.md 2절 PRD-F30)

## 회의 D8에 따라 1순위
- PRD-F23: 기술 지도(첫 화면, 2D), 검색·키보드 이동·갈래 접기. (출처: docs/prd.md 2절 PRD-F23, 만드는 순서 D8 행)
- PRD-F23은 11-20에 바뀌었다(ADR 0026·0027·0028 확정): 사용자가 고르는 1~3단계 묶기, 색 = 고른 기준의 값, 보안은 기호(위험·주의·수집 오류), NEW 표시. 인기 크기·오래됨 흐림·지도 위 업데이트는 쓰지 않는다(카드·사이드바에). 로그인 뒤 기본은 전체 지도이고 "내 기술과 비교군(한 단계)"은 필터·칩. 옛 설명의 "색은 보안 등급, 크기는 인기"와 "내 기술을 가운데"는 이것으로 대신한다. (출처: docs/prd.md 2절 PRD-F23 87줄, 바뀐 기록 2026-11-20)

## 2순위: 알파
- PRD-F25: 설치 프롬프트 만들기, 정해진 틀로만·비밀값 가림·위험한 버전은 넣지 않음. (출처: docs/prd.md 2절 PRD-F25)
- PRD-F33: 내 컴퓨터 목록 가져오기 프롬프트, 출력을 붙여 넣으면 "프로젝트 밖" 칸이 채워짐. (출처: docs/prd.md 2절 PRD-F33)

## 3순위: 확장 여지
- PRD-F32: 가입 직후 취향 질문 3개 → 인기 신호로 추천(알림·판단과 따로). (출처: docs/prd.md 2절 PRD-F32)
- PRD-F34: 쓰고 있어요: 그 기술을 쓰는 사용자 수와 별명, 설정에서 숨김. (출처: docs/prd.md 2절 PRD-F34)
- PRD-F35: 사용기와 "도움이 됐어요", 신고 → 관리자 숨김. 등급에 영향 없음. (출처: docs/prd.md 2절 PRD-F35)
- PRD-F36: 보기 형식: 갤러리와 내 레이더. 11-20부터 내 레이더는 판단 상태별 칸반(관심 → 적용 후보 → 쓰는 중, 보류; "중단"은 보류에 합침)이고 대시보드(IA-5) 숫자를 함께 보여 준다. (출처: docs/prd.md 2절 PRD-F36, ADR 0028)
- PRD-F37: 소식판: 공식 출처 일반 소식을 별도 화면에, 최근 30일. (출처: docs/prd.md 2절 PRD-F37)
- PRD-F38: 세 번째 알림 후보: 모델 지원 종료. PR #201로 만들었다(규칙은 [보안 등급 규칙](보안-등급-규칙.md)). (출처: docs/prd.md 2절 PRD-F38, docs/spec.md SPEC-3.3, docs/plan.md 4절 P-22)
- PRD-F39: 다른 AI 도구의 설정 파일(`.cursor/mcp.json`, `AGENTS.md` 등)도 읽기. MCP 설정 3개(Cursor·VS Code·Gemini CLI)는 PR #194·#201로 합쳐졌고, `AGENTS.md`·`GEMINI.md`는 읽을 것이 정해지지 않아 남았다. (출처: docs/prd.md 2절 PRD-F39, docs/spec.md SPEC-7.1, docs/plan.md 4절 P-22)
- PRD-F40: 카탈로그 종류에 연동 서비스와 개념(등급·알림 없음). PR #201로 만들었다. (출처: docs/prd.md 2절 PRD-F40, docs/spec.md SPEC-7.4)
- PRD-F41: 보류 회고: 보류 30일 뒤 "다시 볼까요?". (출처: docs/prd.md 2절 PRD-F41)
- PRD-F42: 비교 모드: 기술 2–3개 나란히 비교표. (출처: docs/prd.md 2절 PRD-F42)
- PRD-F43: 이번 주 요약 카드: 대시보드에 "내 기술 변화 n건". (출처: docs/prd.md 2절 PRD-F43)
- 요구 일부도 3순위: F4 수정·보관, F6 `requirements.txt`, F8 주제 태그·Hugging Face·Hacker News·Firecrawl, F23 외톨이 표시, 플러그인 읽기. 이 중 F4 수정·보관과 F6은 합쳐졌고, F8의 주제 태그·Hacker News는 PR #203(11-21 열림, 리뷰 대기)에 있다. (출처: docs/prd.md 2절 만드는 순서 3 행, docs/plan.md 4절 P-21·P-22)

## 따로
- PRD-F31: 팀원·관리자 전용 위키 챗봇, 한 사람 하루 20개·답 800자 안. (출처: docs/prd.md 2절 PRD-F31)
- PRD-F44: 주 숫자(등급과 이유를 확인한 기술 비율)를 QA 때 SQL 한 번으로 계산. 화면 없음. (출처: docs/prd.md 2절 PRD-F44)
