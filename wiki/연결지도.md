# 연결지도

> 요구(PRD) ↔ 화면(IA)·여정(UJ)·데이터·규칙(SPEC)·조각(plan)·작업 의도(intent)·PR·QA를 이은 표. 2026-11-19 기준 main을 읽어 만들었고, 2026-11-20에 PR 칸에만 #172–#193을 더했다(#124–#171은 아직 잇지 않음). (출처: docs/prd.md 2·3절, docs/plan.md 4절, docs/intent.md, docs/qa.md, docs/qa-c.md, GitHub 합쳐진 PR #1–#123·#172–#193)

## 읽는 법

- 칸의 "—"는 **찾아봤지만 이어진 것이 없음**이다. 자동으로 잇지 못한 연결이 있을 수 있으니, 빈칸은 "없음"으로 단정하지 말고 원본을 확인한다. (출처: CLAUDE.md 3절 불변 2의 정신, wiki/log.md 2026-11-19 만든 방법)
- PR 칸은 PR 제목·설명에 적힌 요구 ID와, PR 제목·브랜치의 조각 번호(P-n)가 plan에서 가리키는 요구를 합친 것이다. (출처: docs/plan.md 4절 조각 표, GitHub PR 설명 "만든 요구" 줄)
- "11-20 더함" 뒤의 PR은 2026-11-20 반영 때 #172–#193의 제목·설명("어느 문서의 어느 요구")에 적힌 요구 ID와 조각 번호(P-23 → F32, P-24 → F35)로 손으로 이었다. intent·QA 칸은 이때 고치지 않았다. (출처: GitHub PR #172–#193 제목·설명, docs/plan.md 4절 P-23·P-24 행)
- 데이터 칸은 erd·데이터설계 문서가 요구 ID를 직접 적은 줄만 잡는다. erd는 요구 ID를 거의 적지 않아 대부분 비어 있다. (출처: docs/erd.md, docs/데이터설계.md)
