# QA 실행표 — 남은 사람 QA를 한 번에 돌리기

`docs/qa.md`·`docs/qa-c.md`에서 **아직 No Run이거나 Fail인 행**을 모아, 같은 로그인으로 한 번에 할 수 있는 묶음으로 나눈 **실행 순서표**다. 결과표가 아니다. 이 파일에는 결과를 적지 않고, 이 파일을 만들면서 원래 행의 상태도 바꾸지 않았다.

- **기준:** origin/main `8c3bbe0`(2026-11-19)에 이 작업의 링크 한 줄을 더한 `docs/qa.md`. 줄 번호(L)는 `docs/qa.md`의 줄이다. 다른 PR이 행을 더하면 줄이 밀리니 **검사 항목 이름**으로 찾는다.
- **만든 사람:** 차세일(Claude), 작업 `I-qa-runsheet-1119`. 정본은 여전히 `docs/qa.md`·`docs/qa-c.md`다(QA 시트를 둘지는 [ADR 0025](adr/0025-QA-시트-대신-저장소-md-표를-정본으로.md), 제안).

## 결과를 적는 법 (`rules/qa.md`)
1. 한 줄을 끝내면 **원래 행**(`끝나면 고칠 곳` 칸의 파일·행)의 세 칸을 고친다.
   - **상태:** `Pass` / `Fail` / `No Run` 중 하나. 일부만 했으면 `Pass(①②) · No Run(③)`처럼 한 범위와 남은 범위를 함께 쓴다. 근거 없이 Pass를 쓰지 않는다.
   - **수행자, 날짜:** 실제로 누른 사람과 날짜(`차세일, 2026-11-20`). Claude가 대신 눌렀으면 `Claude`, 사람이 시키고 Claude가 조작했으면 둘 다(`차세일·Claude(Playwright)`).
   - **증거:** 화면 캡처 파일 이름, 흐름 화면의 실행 id(앞 8자리), PR 번호, `docs/` 위치 중 하나 이상. "됐다"는 말만 있으면 "당사자 말"이라고 적는다.
2. **자동 채점과 사람 QA를 섞지 않는다.** 사람이 눌러 본 결과는 사람 QA 행(또는 그 행의 Claude QA 짝)에 쓰고, `npm test`·`npm run eval` 결과는 Claude QA 행에 쓴다.
3. **Fail은 숨기지 않는다.** 실제 결과 칸에 본 것을 그대로 쓰고, `docs/intent.md`에 고칠 일로 올리고, 원인을 찾으면 `docs/debug-note.md`에 남긴다.
4. 비밀번호·키 값은 어디에도 쓰지 않는다. **운영 주소에는 시험 계정 비밀번호를 넣지 않는다**(`docs/qa-c.md` 사람 QA 머리말). 운영은 구글 로그인만 쓴다.
5. 할 수 없어서 못 했으면 `No Run`을 그대로 두고 **이유**만 실제 결과 칸에 덧붙인다.

## 미리 알아 둘 것
- **로컬도 운영 DB를 쓴다.** 우리 DB는 하나뿐이라(`docs/qa.md` L69 "운영(유일한) DB") 로컬에서 만든 시뮬레이터 자료·판단·확정도 운영 DB에 남는다.
- **로컬 준비:** 각자 `.env.local`(Supabase 주소·키, 필요하면 `ANTHROPIC_API_KEY`) + `NEXT_PUBLIC_ENABLE_TEST_LOGIN=true` + `ENABLE_FAIL_DEMO=true` → `npm run dev`. 시연·관리자·일반 테스트 계정의 로그인 정보는 팀이 정한 곳(각자 `.env.local`, 팀 비밀 노트)에 있다.
- **운영 계정:** 관리자 = `role=admin`인 구글 계정, 시연 계정 = `is_demo=true`인 구글 계정(`docs/qa.md` L85처럼 사람이 SQL로 바꿈), 일반 계정 = 그 밖의 구글 계정.
- **되돌릴 수 없는 것:** 같은 역할 확정(1-1 ③), 시뮬레이터 지우기(`docs/qa-c.md` H12, 이미 Pass라 이 표에는 없음 — 이번에 만든 가짜 자료를 치우고 싶으면 **모든 묶음이 끝난 뒤** 관리자 `/admin/simulator`에서).
