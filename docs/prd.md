# PRD (요구사항)

> 상태: **초안, 팀 승인 전.** 팀 인터뷰(2026-11-17, 팀원 1명, 3라운드)를 바탕으로 Claude가 썼다. 요구는 `PRD-F n`(기능)·`PRD-NF n`(품질)로 부르고, 요구마다 출처(`UJ-n`, `IA-n`, 문제정의 절, 불변 규칙)를 단다. 회의 결정에 걸린 곳은 **[D2]**(알파), **[D4]**(잴 숫자), **[D6]**(필요 등록), **[D8]**(첫 화면)으로 표시했다.
> 함께 읽을 것: `docs/문제정의.md`(왜), `docs/ia.md`(화면), `docs/uj.md`(여정), ADR 0007(로그인과 노션 연동)

## 0. 한 줄 요약

AI 코딩 도구로 만드는 사람이 **내가 깐 기술의 목록·보안·더 나은 대안**을 한눈에 보고, 바깥 변화(새 취약점, 같은 역할의 새 기술)가 생기면 **알림을 받아 판단하고 기록**하며, 쌓인 목록을 **노션 데이터베이스로 보내** 컴퓨터를 바꿔도 잃지 않게 한다.

- 대표 사용자: 바이브코딩 부트캠프 수강생 (문제정의 4절, `docs/uj.md` 주인공)
- 주 숫자 **[D4]**: 내 기술 목록 가운데 보안 등급과 이유를 확인한 기술의 비율 (문제정의 7절, UJ-4)

## 2. 기능 요구

"끝 기준"은 QA에서 Pass/Fail을 정하는 기준이다. 숫자 기준(사건 기준, 등급 규칙)은 `docs/spec.md`에서 정한다.

### 계정과 권한

| ID | 요구 | 끝 기준 | 출처 |
|---|---|---|---|
| PRD-F1 | **노션 또는 구글 계정**으로만 가입·로그인·로그아웃한다(Supabase Auth). 비밀번호·메일 확인 흐름은 만들지 않는다. **이메일 테스트 계정은 개발·QA 환경에서만** 환경변수로 켜고, 배포 화면에는 보이지 않는다 | 두 방법 모두 로그인되고, 새로고침 뒤에도 유지된다. 배포 주소의 로그인 화면에 이메일 칸이 없다. 개발 환경에서는 테스트 계정 2개 + 관리자 1개로 권한 QA를 돌릴 수 있다 | IA-1, UJ-A1, ADR 0007 |
| PRD-F2 | 구글로 가입한 사람은 설정에서 **노션 연결**을 하고, 누구나 **연결 끊기**를 할 수 있다. 끊으면 저장된 노션 토큰을 지운다 | 연결 → "노션으로 보내기" 버튼이 보임. 끊기 → 토큰 행이 없어지고 "노션 연결하기"가 보임 | IA-19, ADR 0007 |
| PRD-F3 | 관리자는 DB의 역할 칸으로 정한다. 관리자를 정하는 화면은 없다. 관리자 화면과 API는 관리자만 쓸 수 있다 | 일반 사용자가 관리자 주소·API를 직접 불러도 막힌다(화면·서버·DB) | 불변 5, IA-12–IA-18 |

### 내 프로젝트와 내 기술 목록 (직접 입력)

| ID | 요구 | 끝 기준 | 출처 |
|---|---|---|---|

| PRD-F5 | 사람마다 **"프로젝트 밖(내 컴퓨터)"** 칸이 자동으로 하나 생긴다 | 가입 직후 IA-2·IA-3에 그 칸이 있음 | IA-Q4-3, UJ-A5 |

### 지켜보기와 보안 등급

| ID | 요구 | 끝 기준 | 출처 |
|---|---|---|---|
| PRD-F8 | **OSV**(취약점), **공식 MCP 레지스트리**(새 서버), **GitHub 저장소 정보**(최근 활동·라이선스, 서버 토큰으로), **npm·PyPI 다운로드 수**(사용량), **Hugging Face**(인기 모델·스페이스), **Hacker News**(인기 점수)를 **하루 1번 예약 실행**과 **"지금 한 번 실행"**으로 모아, 같은 모양(출처, 대상, 이전 값, 현재 값, 시각)으로 저장한다. 값이 바뀐 것만 수집 자료로 남기고, 실행마다 언제·어디를·몇 건·성공 여부를 남긴다. 3순위로 **Firecrawl로 skills.sh 인기 페이지 1곳**(스킬 설치 수, 스킬은 다운로드 수가 없어서). robots.txt는 공개 페이지 허용(`/api/`·`/search`만 막음, 2026-11-17 확인), 이용약관은 쓰기 전에 확인 | 배포한 앱에서 실행 기록이 간격대로 쌓임. 버튼으로 바로 한 번 돎. 같은 값을 다시 읽으면 수집 자료가 늘지 않음. **두꺼운 기술만 정기 확인**: 매일 OSV·새 버전 확인, 바뀐 게 없으면 거기서 끝(관문 셋, `docs/데이터설계.md` 8절) | 안내서 필수 2, `docs/data-sources.md`, IA-15, ADR 0008 |
| PRD-F9 | 읽기에 실패하면 **"수집 오류"**로 남기고, 같은 출처가 연속으로 실패하면 관리자 화면에 보인다 | 출처 주소를 일부러 틀리게 → 수집 오류 기록, "변화 없음"·"삭제됨"이 아님 | 불변 2, UJ-M1 |
| PRD-F10 | 기술마다 코드 규칙으로 **보안 등급(통과 / 주의 / 위험)**과 **쉬운 말의 이유**, 근거 링크를 붙인다. 근거는 **OSV**(패키지) + **위험 패턴 검사**(스킬·MCP 코드) + **저장소 정보**(최근 활동·라이선스) + **출처 상태**(중단·출처에서 사라짐은 "주의"). 근거가 없으면 "찾지 못함" | 같은 입력에 같은 등급. 위험 패턴 검사는 새 버전·커밋이 생겼을 때 + 주 1회만, 등급은 결과가 바뀔 때만 다시 계산(Claude 호출 없음). 이유 문장과 근거 링크가 있음. 스킬도 등급이 붙음 | ADR 0003, ADR 0008, IA-4, UJ-4 |

### 사건과 알림

| ID | 요구 | 끝 기준 | 출처 |
|---|---|---|---|
| PRD-F11 | **보안 경고**: 내 기술의 보안 등급이 위험으로 바뀌면 사건을 만든다(기준은 spec). **처음 읽을 때** 새로 들어온 내 기술이 이미 위험이면 "처음 확인 → 위험"으로 1번 만든다(주의·통과는 등급만) | 시뮬레이터의 가짜 취약점 → 보안 경고 1건 | 문제정의 2절, UJ-3 |
| PRD-F12 | **적용 기회**: 새 기술이 내 기술과 **같은 역할**이면 사건을 만든다(같은 역할의 판단 기준은 spec). **등록 시각 이후에** 새로 들어오거나 새로 확정된 같은 역할 기술만(처음 읽을 때 기존 대안은 알리지 않음) | 시뮬레이터의 가짜 새 MCP 서버 → 적용 기회 1건 | 문제정의 2절, UJ-6, IA-Q3 |
| PRD-F13 | 같은 변경을 다시 읽어도 사건·알림이 두 번 생기지 않는다 | 같은 수집을 두 번 돌려도 사건 수가 같음 | 불변 3, UJ-2 |
| PRD-F14 | 알림은 **앱 안에서만** 보여 준다. 알림 목록은 종류·상태·기간으로 거른다. 판단 대기 수는 첫 화면 띠에 보인다. 처음 읽은 뒤에는 띠에 **"첫 점검: 위험 n · 주의 n"** 요약을 한 번 보여 준다 | 띠의 숫자 = 판단 대기 알림 수 | IA-6, IA-10, UJ-1–UJ-2, IA-Q7 |
| PRD-F15 | 알림 상세에 무엇이 바뀌었나(**이전 값 → 현재 값**, 출처, 시각), 쉬운 이유, Claude가 만든 **대응안 초안**과 참고한 출처를 보여 준다 | 출처 링크가 열림. 출처가 없으면 "찾지 못함" | IA-7, UJ-3 |
| PRD-F16 | 적용 기회 알림에는 **내 기술과의 비교표**가 있다: 무엇이 다른지(하는 일, 보안 등급과 이유, 최근 활동, 라이선스), 항목마다 출처. 항목은 코드로 채운다 | 비교표의 모든 칸에 값 또는 "찾지 못함"과 출처가 있음 | UJ-6, UJ-9, 강사 11-16 |

### 판단과 조치

| ID | 요구 | 끝 기준 | 출처 |
|---|---|---|---|
| PRD-F17 | 알림마다 사용자가 **적용 후보** 또는 **보류**(이유 필수)로 판단한다. **판단 전에는 아무것도 바뀌지 않는다.** 관리자도 판단을 대신하거나 건너뛸 수 없다 | 판단 전 시나리오·기록 없음. 관리자 화면에 판단 버튼 없음, API로도 막힘 | 불변 1, UJ-5, UJ-6, UJ-M4 |
| PRD-F18 | 알림 상세의 **"적용 시나리오 만들기"**를 누를 때만(판단 전후 언제든) Claude가 **적용 시나리오**(대체 기술과의 비교표, 적용 단계, 위험과 되돌리는 방법, 출처)를 만들어 저장한다. 실제 설치·적용은 하지 않는다 | 누르기 전에는 시나리오도 Claude 호출도 없음. 누른 뒤 IA-8에 시나리오와 출처가 있음 | IA-8, UJ-5, 문제정의 9절, 데이터설계 원칙 6 |
| PRD-F19 | 판단·시나리오 저장에 실패하면 이전 상태(판단 대기)를 그대로 두고 "처리 완료"로 보이지 않는다. 다시 시도할 수 있다 | 저장을 일부러 실패 → 상태가 판단 대기, 다시 시도로 저장됨 | 불변 4, UJ-5x |

## 5. 이번에 하지 않을 것

- AI 코딩 도구 생태계 밖의 IT 분야, Reddit 수집, 뉴스레터 전체, Anthropic 뉴스 크롤링 (문제정의 9절)
- **비공개 저장소** 등록 (GitHub 로그인 연동 필요)
- **사용자 대신 설치·적용**, 다른 컴퓨터로 세팅을 대신 옮겨 까는 "이사" (문제정의 9절)
- 필요 문장과 기존 도구를 맞추는 검색을 사건으로 쓰기 (문제정의 9절)
- **앱 밖 알림**(메일·메신저) (IA-Q7)
- **프로젝트 목표 맞추기**: 적용 기회는 같은 역할만 (IA-Q3)
- **지도 2단계 이상** (IA-Q5)
- 대시보드·알림 밖의 **휴대폰 화면** (IA-Q8)
- **커뮤니티 평판 요약** (ADR 0003의 "참고"도 v1에서는 안 함)
- 노션: **양방향 동기화**, **자동으로 보내기**, **판단 기록 보내기**, 노션 페이지 내용 읽기
- 관리자를 정하는 화면
- 일반 의존성(react 등)을 내 기술로 읽기 (ADR 0008)
- 이전 프로토타입의 데이터 가져오기 (ADR 0008)
- Appwrite (Supabase와 둘 다 쓰면 권한이 두 곳으로 갈라짐)
- 3D 지도 (v1은 2D. 3D는 다음 버전 데모용)
