## 1. 사람과 영역

**기능 영역으로 나누고, 각자 자기 영역의 화면·서버·데이터·QA를 모두 해 본다.** 층(프론트/백엔드)으로 나누지 않는다. 영역 이름은 서비스 기준 문장 "지키고, 고르고, 옮긴다"에서 왔다.

| 영역 | 사람 | GitHub | 맡는 화면 | 맡는 서버 | 맡는 데이터 | 맡는 QA | 공용으로 더 맡는 것 |
|---|---|---|---|---|---|---|---|
| **A 지키기** (내 기술·보안) | 김영식 | sikomar00 | 프로젝트 등록(IA-2), 내 기술 목록(IA-3), 기술 상세(IA-4), 기술 지도(IA-10) | 저장소 읽기·기술 키, 수집(OSV·레지스트리·GitHub·다운로드), 등급 규칙·위험 패턴, 변경 만들기 | 허용 목록·위험 패턴·갈래 처음 목록, 정답 사례 G1–G9·시험용 스킬 | 등급, 수집 오류, 중복 막기, 첫 점검 | **뼈대 앱, DB 마이그레이션**, Supabase·Vercel 계정, 구글 OAuth |

**공용 파일의 주인:** 뼈대·공용 서버 함수(`lib/server/`)는 김영식, `flow/flow.json`은 차세일만 고친다. 다른 사람은 바꿀 게 있으면 주인에게 요청한다(같은 파일 동시 수정 막기, 가이드라인 V13).
**DB 마이그레이션:** 조각 담당자가 **새 파일로 직접** 만든다(`supabase/migrations/<YYYYMMDDHHMM>_P-n_<이름>.sql`). 이미 합친 파일은 고치지 않고 새 파일로 바꾼다. 마이그레이션이 든 PR은 **김영식 리뷰 필수**(11-18 바꿈, 한 사람에게 모든 DB 일이 묶이지 않게).
**공용 서버 함수의 주인(P-29에서 자리만 먼저 만들고 각 주인이 채운다):** 서비스 키 서버 연결·현재 사용자·관리자 확인·세션 갱신·변경 저장 = 김영식(A), 알림 만들기 = 황재웅(B), 실행 기록(`startRun`·`recordStep`) = 차세일(C).

## 2. 일하는 규칙

| 규칙 | 내용 |
|---|---|
| 조각 | 한 사람이 한 브랜치에서 하루 안에 끝낼 크기. 브랜치 `feat/P-n-짧은-이름` |
| PR | 조각 하나씩 작게. 설명에 **어느 문서의 어느 요구**(출처 칸)를 한 줄 |
| 리뷰 | **만든 사람이 아닌 팀원 1명의 승인**이 있어야 합친다. 리뷰어는 짝을 고정하지 않고 **각자 수시로** 요청한다. 한 사람에게 몰리지 않게 4절 표로 센다 |
| main 보호 | PR로만 합치기, 승인 1개 필요, 강제 푸시 금지(저장소 관리자가 GitHub에서 켠다) |
| 합치기 | 시간을 따로 두지 않고 수시로. 합친 사람이 팀 채널에 "합침: P-n"이라고 알리고, 나머지는 바로 최신 main을 받는다(내 컴퓨터에서 `git merge origin/main`. GitHub 웹의 충돌 해결·Update branch 버튼은 기록 문서 설정을 따르지 않음, ADR 0017). M0 이후에는 합칠 때마다 **시뮬레이터 한 번으로 얇은 한 줄이 아직 도는지** 확인한다(안내서 995줄) |
| 충돌 | 혼자 지우지 않고 그 코드를 쓴 사람과 함께 푼다. 합친 뒤 생긴 오류는 `docs/debug-note.md`. 기록 문서 5개(`intent`·`worklog`·`agents`·`connectors`·`debug-note`)는 양쪽 줄이 자동으로 남고(`.gitattributes`), 합친 뒤 `npm test`의 기록 검사가 번호 겹침·깨진 표를 잡는다. 설정이 없는 옛 브랜치는 처음 한 번 설정을 먼저 받는다(CLAUDE.md 10절, ADR 0017) |
| 기록 | 시작할 때 `docs/intent.md`(작업 ID는 `I-`+브랜치 이름, 번호 없음), 끝날 때 `docs/worklog.md`(행 첫 칸에 같은 작업 ID). 서브에이전트·커넥터를 쓰면 `agents.md`·`connectors.md`. 동작을 바꾸면 불변 규칙 테스트 |
| 테스트 | PR 설명에 `npm test` 통과 수와 `npm run build` 결과를 적는다(PR 검사는 Vercel 빌드뿐이라 리뷰어가 볼 수 있게). 테스트 파일은 `*.test.ts`, 상대 경로로 import. 시험이 불러오는 `lib/` 파일도 `@/` 별칭 대신 상대 경로(`.ts`)로 import하고 파라미터 프로퍼티·`enum`을 쓰지 않는다(`node --test`가 읽지 못함) |
| 비밀값 | 키는 각자 `.env`에 직접. 저장소·채팅·문서에 쓰지 않는다 |
| 3순위 | 1순위가 배포 앱에서 시연 가능해진 뒤에만 시작한다. 코드 동결 전에 못 하면 **화면에 자리만** 둔다("사용자가 모이면 열려요") |

## 4. 조각 표

**순위:** 1-0 얇은 한 줄 / 1 핵심 길 / 2 알파 / 3 확장 여지(PRD 만드는 순서). **리뷰어**는 PR을 올릴 때 정해서 채운다. **먼저 필요한 것**은 그 조각이 합쳐지기 전에 main에 있어야 하는 조각이다. 기다리는 동안에는 샘플 데이터로 로직·화면부터 한다.

**M0 사슬:** P-1 → P-2 → P-29 → (P-4 ∥ P-7) → P-3 → (P-5 ∥ P-8) → P-6. P-2·P-29가 가장 먼저라 김영식이 오후 이른 시간에 합치고, 그동안 황재웅·차세일은 DB 없이 P-4 함수·P-6 그림·P-7·P-8 화면부터 한다.
