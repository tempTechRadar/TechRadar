# 0012. M0은 로컬에서 끝까지 확인하고, 보안 경고의 "적용 후보"는 "고친 버전으로 올리기"다

- 날짜: 2026-11-18
- 상태: **채택** (2026-11-18, 개발 전 점검 뒤 사용자가 추천안으로 정함)

개발을 나누기 전 점검(`docs/agents.md` 11-18)에서 두 가지가 막혔다.
1. plan의 M0 끝 기준은 "배포 주소에서 시뮬레이터 → 경고 → 판단"이다. 그런데 M0의 로그인은 개발용 테스트 로그인뿐이고 운영 배포에서는 일부러 꺼진다(ADR 0007 개정). 구글 로그인은 M1(P-12)이고, Vercel 미리보기 주소는 SSO 보호로 막혀 있다. M0 시점에 배포 주소에서 판단까지 갈 방법이 없다.
2. ADR 0003은 "'위험' 기술은 적용 후보로 고를 수 없다"고 했다. 그런데 보안 경고(위험으로 바뀐 기술)에도 [적용 후보] 버튼이 있고(SPEC-5.1·5.2, UJ-5), ADR 0010은 "적용 후보면 설치 프롬프트 기본 목록에 들어간다"고 한다. 판단(B)과 설치 프롬프트(C)가 같은 뜻을 써야 한다.

## 정한 것
- **M0 끝 기준:** 로컬에서 개발용 테스트 로그인으로 시뮬레이터 → 보안 경고 → 판단 → 기록 → 흐름 화면이 끝까지 돌고, 같은 코드가 배포 주소에서 열린다(화면·DB 연결). 배포 주소에서 로그인해 끝까지 도는 것은 구글 로그인(P-12)이 붙는 **M1 기준**으로 옮긴다.
- **보안 경고에서 "적용 후보" = "고친 버전으로 올리기".** 판단에는 고친 버전(OSV가 알려 준 안전한 버전) 번호가 함께 저장된다. 설치 프롬프트에는 그 버전으로 **고정**해 들어간다. 위험한 버전 자체는 어떤 경우에도 적용 후보·설치 프롬프트에 들어가지 않는다. 고친 버전이 없으면(OSV에 고친 버전 없음) 보안 경고에는 [보류]만 있다.
- 적용 기회(같은 역할의 새 기술) 알림의 "적용 후보"는 지금 뜻 그대로다(그 기술을 써 볼 후보).

## 결과
- plan: M0 끝 기준과 P-12 끝 기준을 고친다. P-8(판단)에 고친 버전 저장, P-19(설치 프롬프트)에 버전 고정을 끝 기준으로 둔다.
- ADR 0003에 개정 줄을 단다(위험한 **버전**은 고를 수 없음, 고친 버전은 고를 수 있음).
- GLOSSARY에 "적용 후보", "보류"를 넣는다. spec 5절 보안 경고 버튼 문구를 맞춘다.

## 고르지 않은 것
- 구글 로그인을 M0으로 당기기: 구글 콘솔에서 OAuth 클라이언트를 사람이 만들어야 해서, 얇은 한 줄이 그 일에 묶인다.
- 운영 배포에서 테스트 로그인을 시연 계정에만 열기: 운영에서 비밀번호 로그인을 여는 예외가 생겨 불변 5·ADR 0007과 부딪힌다.
- 보안 경고에서 적용 후보 버튼을 없애기: 사용자가 "고쳐서 계속 쓴다"는 판단을 남길 자리가 없어진다.
