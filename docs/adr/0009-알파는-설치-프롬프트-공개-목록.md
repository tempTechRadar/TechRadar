# 0009. 알파는 설치 프롬프트로 하고, "쓰고 있어요"를 위해 내 기술 목록을 기본 공개한다

- 날짜: 2026-11-17
- 상태: **채택** (2026-11-18 회의). 처음: 제안 (팀원 1명이 정함. 2026-11-18 회의 D2·D11에서 팀 확인)

## 1. 알파 = 설치 프롬프트 (노션 보내기는 다음 버전)

그룹1 인터뷰의 가장 강한 장면은 "깐 게 중구난방인데 목록이 없어서, 노트북을 반납할 때 옮기기 막막하다"였다. 처음에는 목록을 노션 데이터베이스로 보내는 것을 알파로 골랐다(ADR 0007). 그런데 노션 연동은 OAuth, 토큰 보관, 노션 API가 필요해서 무겁고, "옮기기"에는 한 걸음 모자란다.

**정한 것**
- 알파는 **설치 프롬프트 만들기**다(PRD-F25). 고른 내 기술을 다른 컴퓨터의 Claude Code에 붙여 넣을 글로 만든다. 붙여 넣으면 Claude가 하나씩 확인받으며 설치한다.
- 반대 방향인 **내 컴퓨터 목록 가져오기 프롬프트**도 함께 만든다(PRD-F33). 사용자의 Claude Code가 전역으로 깐 MCP·스킬을 정해진 형식으로 출력하면, 사용자가 그것을 보고 앱에 붙여 넣는다.
- 노션 로그인과 노션으로 보내기는 다음 버전으로 미룬다. v1 로그인은 구글만 쓴다(ADR 0007 개정).

**설치는 여전히 우리가 하지 않는다.** 문제정의 9절은 "이사는 하지 않는다. 목록을 보여 주는 데까지만"이었다. 이것을 "**대신 설치는 하지 않는다. 설치 안내 글은 만든다**"로 고친다. 실행은 사용자가 자기 컴퓨터에서 직접 하므로, 불변 규칙 1(사람이 승인하기 전에는 실행하지 않음)을 지킨다.

**안전장치** (프롬프트가 공격 통로가 되지 않게)
- **정해진 틀(템플릿)로만** 만든다. AI가 자유롭게 쓰지 않는다. 바깥 README 글이 들어가면, 그 안에 숨은 지시가 사용자 컴퓨터에서 실행될 수 있다.
- 넣을 수 있는 것은 세 출처뿐이다(SQ8): ① 사용자 저장소에서 **실제로 읽은** 것은 그대로 ② 내 컴퓨터 목록 가져오기로 받은 것은 **값 검사(SPEC-6.3)를 통과한 것만** ③ 적용 후보로 판단한 카탈로그 기술은 **공식 레지스트리 이름과 정확히 일치하는 것만**(비슷한 이름은 넣지 않음). 항목마다 공식 출처 링크를 단다. (2026-11-17 SQ8로 고침: 처음엔 "저장소에서 읽은 것만")
- **비밀값은 `<여기에 직접 입력>`으로 바꾼다.**
- 위험 등급 기술은 기본으로 뺀다. 넣으면 "위험: 이유"를 적는다.
- 프롬프트 첫 줄은 "하나씩 설치 전에 나에게 확인받아"다.

## 2. "쓰고 있어요"를 위한 기본 공개 (불변 규칙 5 문구 변경 제안)

사용기·쓰고 있어요(PRD-F34·F35)는 사용자가 모이면 커지는 기능이다. 지금은 사용자가 없지만, 확장될 자리를 데모에서 보여 주려고 넣는다. 팀원은 "지금은 다 보여 주고, 숨기는 기능은 나중에"를 원했다.

그런데 팀 CLAUDE.md의 불변 규칙 5는 "사용자는 본인 데이터만"이다. 다른 사람이 무엇을 쓰는지 보여 주면 이 문구를 어긴다. 사용자가 생긴 뒤에 숨김이 늦게 들어오면, 그 사이에 이미 공개된다.

**정한 것**
- 내 기술 목록은 "쓰고 있어요"에 **기본으로 공개**한다. 대신 설정에 **숨김 체크박스 하나는 지금** 넣는다. 비용이 거의 없다.
- 가입할 때 "다른 사용자에게 '쓰고 있어요'로 보여요"라고 한 줄 알린다.
- 서버가 **별명**과 수만 계산해 주고, 남의 목록 원본은 내려보내지 않는다. 구글 표시 이름(실명일 수 있음)은 보이지 않고, 가입 때 정한 별명만 보인다(SQ9).
- 불변 규칙 5의 문구를 "사용자는 **본인이 공개한 것 말고는** 본인 데이터만, 관리자 데이터는 관리자만"으로 바꾸자고 **제안한다.** 팀 규칙을 바꾸는 일이라 회의 D11에서 정하고, 정해지면 CLAUDE.md를 고친다. 그 전에는 CLAUDE.md를 고치지 않는다.

## 결과
- PRD-F1·F2·F25·F33·F34, IA-3·IA-19·IA-22, uj UJ-B·UJ-A5, 데이터설계(`exports`, 공개 여부 칸), 문제정의 9절이 이 결정을 따른다.
- 알파가 가벼워진다. 노션 연동 앱, 토큰 보관, 노션 동의 화면 QA가 이번 범위에서 빠진다.
- **확인하지 못한 것:** 설치 프롬프트가 실제로 다른 컴퓨터에서 세팅을 옮기는지. 코드 없이 수강생 저장소 하나로 손으로 먼저 시험해 볼 수 있다.

## 고르지 않은 것
- 노션 보내기를 알파로 유지: 무겁고, "옮기기"에 한 걸음 모자란다(다음 버전).
- 숨김 기능을 나중에: 사용자가 생긴 뒤에 들어오면 그 사이에 공개된다.
- AI가 상황에 맞춰 프롬프트를 쓰게 하기: 바깥 글이 섞여 공격 통로가 된다.

## 개정
- 2026-11-18(기본 문서 점검 D-1, ADR 0012): 1절 안전장치의 "위험 등급 기술은 기본으로 뺀다. 넣으면 '위험: 이유'를 적는다."를 **"위험한 버전은 어떤 경우에도 넣지 않는다. 사용자가 직접 넣는 길도 없다."**로 고친다. 빠진 것은 "[넣지 않은 것 (위험)]"에 이유와 고친 버전을 알려 준다. 보안 경고에서 적용 후보로 판단한 것은 고친 버전으로 고정해 넣는다.
