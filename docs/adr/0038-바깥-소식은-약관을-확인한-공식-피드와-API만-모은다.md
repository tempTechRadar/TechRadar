# 0038. 바깥 소식은 약관을 확인한 공식 피드와 API만 모은다

- 날짜: 2026-11-22
- 상태: **확정 (사용자 승인, 2026-11-21 밤, 앱 구조 개편 계획 P-12f의 일부)**. 피드 목록은 DocsChecker가 11-21에 약관을 확인한 결과다. 구현 결과에 따라 "결과와 남은 일"을 채운다
- 관련: ADR 0037(현황의 "소식" 탭), `docs/data-sources.md` "소식 피드 후보와 약관" 절, 불변 2 · 3 · 6, SPEC-8(수집 오류 다섯 가지), ADR 0018 · 0023(배포 · 정기 실행), 소식판 IA-21 · PRD-F37

## 배경
현황의 "소식" 탭(ADR 0037)은 이미 모은 사건(내 기술의 새 취약점 · 새 버전, 모델 지원 종료, 요즘 뜨는 기술, 새 공식 스킬 · 플러그인)만으로는 바깥에서 나온 공식 소식(도구 새 버전, 공식 변경 기록)을 보여 주지 못한다. 그런데 블로그 · 변경 기록 피드는 사이트마다 약관과 robots.txt가 달라서, 확인하지 않고 모으면 약관을 어길 수 있다.

## 결정
1. **바깥 소식 수집기를 새로 둔다.** 표 `news_items`(마이그레이션 M7): 누구나 읽기(공개), 서버만 쓰기. 주소가 같은 소식은 한 줄(불변 3).
2. **수집 대상은 약관을 확인한 것만.** 11-21 확인 결과(`docs/data-sources.md`):
   - **쓴다:** 카탈로그 공식 저장소의 GitHub REST 릴리스 목록(`GET /repos/{owner}/{repo}/releases`, API 수집은 스크래핑이 아님 — GitHub AUP §7), GitHub Changelog 피드, Google AI 블로그 피드, Google Developers 블로그 피드.
   - **안 쓴다:** `github.com/OWNER/REPO/releases.atom`(robots.txt가 `/*.atom$`을 막음), OpenAI 뉴스 피드(약관이 자동 데이터 추출을 금지), Cursor 변경 기록 피드(약관이 스크래핑을 금지), Anthropic(공식 RSS를 찾지 못함 — Claude Code 소식은 GitHub REST 릴리스로).
3. **저장하는 것:** 제목 · 링크 · 날짜 · 짧은 요약만, 늘 원문 링크를 단다. AI 학습에 쓰지 않는다.
4. **읽는 방식:** 하루 1번 정기 실행 안에서, 피드끼리 1초 간격, 최대 10개 피드, 실행 몫 15초. 정기 실행 예산(240초)을 다른 수집기와 나눠 쓴다.
5. **실패는 "수집 오류"로 남긴다**(불변 2). 실행 기록(`run_steps`)에 남기고(불변 6) 흐름 화면에 상자 하나를 더한다.
6. 새 피드를 더하려면 먼저 약관 · robots.txt를 확인해 `docs/data-sources.md` 표에 적는다. 확인하지 못한 피드는 쓰지 않는다.

## 고민한 것
- **피드를 모으지 않고 이미 모은 사건만:** 약관 위험이 없지만 바깥 공식 소식이 비어 보인다. 컷 라인 2번(ADR 0037)이 이 안이다.
- **GitHub releases.atom:** 주소가 간단하지만 robots.txt가 막는다. 같은 정보를 이미 쓰는 GitHub REST API로 읽는다.
- **OpenAI · Cursor 피드를 하루 1번만:** 사이트가 피드 주소를 내보이지만, 약관 문구가 자동 추출을 금지하고 빈도는 그 문구를 바꾸지 않는다.

## 결과와 남은 일
- 판정은 약관 문구를 읽은 결과이고 법률 의견이 아니다. 블로그별 전용 약관 페이지는 확인하지 못했다(`docs/data-sources.md`).
- **마이그레이션 M7은 운영 적용 전에 사용자 승인.** `flow/flow.json`(흐름 화면)은 차세일 님 파일이라 리뷰를 요청한다.
- **구현 결과(DataCollector, 조각 6):** _아직 없음_
