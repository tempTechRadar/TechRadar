# 0014. 적용 기회 알림의 조건 4(갈래 안 점수)는 v1에서 뺀다

- 날짜: 2026-11-18
- 상태: **채택** (2026-11-18, 기본 문서 점검 D-3을 사용자가 추천안으로 정함. 다른 팀원은 PR 리뷰에서 확인)

기본 문서 점검(`docs/문서점검-20261118.md` D-3)에서 spec 3.2의 적용 기회 조건 4 "새 기술의 갈래 안 점수가 상위 절반"이 만들 순서와 맞지 않는 것이 나왔다. 갈래 안 점수는 사용량·성장·화제·별의 갈래 안 순위인데, plan은 점수 계산을 3순위 P-21(금)의 끝 기준으로 두었고, 점수 재료 중 화제(Hacker News)와 Hugging Face 인기 점수는 P-21의 수집이 있어야 나온다. 그런데 적용 기회 알림을 만드는 1순위 P-14(목)와 시뮬레이터의 두 번째 알림(F29)은 점수 없이 돌아야 한다. 이대로 만들면 알림이 안 생기거나, 조건 4를 몰래 건너뛰게 된다.

## 정한 것
- v1의 적용 기회는 **조건 셋**이 모두 맞을 때 만든다: ① 내 기술과 같은 역할로 **확정**됨(SPEC-4.4, 관리자 확인: ADR 0015) ② 새 기술이 내가 등록한 시각 이후에 카탈로그에 들어오거나 그 이후에 같은 역할로 확정됨 ③ 새 기술의 등급이 위험이 아님.
- **갈래 안 점수 조건은 점수가 만들어지는 P-21 뒤에 조건 4로 다시 넣는다.** 그때 spec 3.2·5.3과 이 ADR에 개정 줄을 단다. 지금은 알림 문구(SPEC-5.3)에서 "갈래 안 점수 {순위}"를 보이지 않는다.
- 알림이 쏟아지지 않는 이유: 조건 1이 **관리자가 확정한 짝**에서만 생기게 하므로 알림 수가 관리자 확인 속도로 정해진다. 비교표의 "사용량"(npm·PyPI 다운로드, P-9)은 이미 있어서 사람이 판단할 재료도 남는다.
- 갈래 안 점수는 적용 기회 조건에서만 빠진다. 지도의 크기·두껍게/얇게(상위 20개)에는 그대로 쓴다(데이터설계 8절, P-21).

## 결과
- prd F12(조건은 spec 3.2), spec 3.2(조건 셋), 5.3(점수 줄 빼기), 11절(추정 숫자 표에서 "상위 절반" 빼고 P-21 뒤 다시 넣는다고 적기), plan P-14("세 조건")·P-21("점수가 붙으면 적용 기회 조건 4로 추가"), GLOSSARY(갈래 안 점수·인기 신호의 "상위 절반" 문장)를 고친다.
- P-14는 점수 없이 만들 수 있다. 시뮬레이터의 가짜 새 MCP + 확정 관계(SPEC-3.5)만으로 두 번째 알림이 난다.
- **확인하지 못한 것:** P-21 뒤 "상위 절반"이 실제로 알림을 줄이는지(첫 수집 뒤에 갈래별 점수 분포를 보고 정한다).

## 고르지 않은 것
- 점수 계산을 P-14 앞으로 당기기: 점수 계산과 그 재료 수집이 목요일 일정에 더 들어와, P-14가 하루 안에 끝나기 어렵다고 보았다(팀 추정, 재 보지 않음).
- 조건 4를 말없이 건너뛰는 코드: spec에는 네 조건이라 쓰여 있는데 코드는 셋이 되어 문서와 코드가 어긋난다.

## 개정
- 2026-11-21(ADR 0030): **조건 4를 "별 수가 알려져 있으면 100 이상"으로 다시 넣는다.** 별 수를 모르면 제외하지 않고(불변 2), 시뮬레이터 변경(`is_simulated`)에는 적용하지 않는다. 갈래 안 점수(상위 절반)는 갈래 목록과 P-21 본 계산이 생긴 뒤에 이 조건을 바꿀지 다시 본다. spec 3.2·11절을 같이 고쳤다.
