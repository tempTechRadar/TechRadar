# 0027. 로그인 뒤 첫 지도는 전체로, "내 기술과 비교군(한 단계)"은 필터로

- 날짜: 2026-11-20
- 상태: **확정 (팀 승인, 2026-11-20)**. 한 사용자가 추천안을 고르고 팀이 승인했다. 지도에 올리는 모은 기술 수(구현의 1,200개)는 ADR 0030에서 500개로 바뀜(2026-11-21), 기본이 전체 지도라는 결정은 그대로 · **11-23 바뀜(ADR 0044):** 비교군은 지도 필터에서 빠지고 사용 중 기술 상세(사이드 패널 · 기술 상세 페이지)에서만 보인다. 아래 본문은 11-20 결정
- 시안: `docs/wireframes/radar.html`(로그인한 척 → 도구 줄 아래 "내 기술과 비교군" 칩, 필터의 같은 칸)
- 관련: D8(로그인 뒤 첫 화면 = 지도, 작게), IA-Q5(같은 역할 한 단계까지), UJ-A2 · UJ-A6, ADR 0015(비교군 = 관리자 확인), ADR 0028(1차 목적, 제안), ADR 0026(지도 묶기·색, `feat/P-12c-map`), `docs/usability-review.md` U12

## 배경
확정 문서(D8 · IA-Q5 · UJ-A6)는 "프로젝트가 있으면 지도 가운데에 내 기술, 둘레에 같은 역할 한 단계까지만, **작게**"라고 정했다. 지도의 근거가 가장 약하다고 봤기 때문이다. 구현(`feat/P-12c-map`)도 그렇게 만들었다(프로젝트가 있으면 내 기술 + 비교군 한 단계, 없으면 모은 기술 전체).

그 뒤 1차 목적을 "기술 지형을 한눈에 보고 스스로 판단하기"로 다시 말했고(ADR 0028), 지도는 로그인 없이 누구나 보게 했다(11-20). 시안은 로그인 전후 모두 전체 지도를 보여 주고 내 기술은 굵은 테두리로만 표시해서, 확정 문서·구현과 어긋났다(사용성 점검 U12).

## 결정
1. **로그인 뒤 첫 지도의 기본은 전체 지도**다. 로그인 전과 같은 지도에 내 기술(굵은 테두리)과 판단이 더해진다.
2. **"내 기술과 비교군(한 단계)"은 필터 하나**로 둔다. 켜면 내 기술 전부와, 그와 **관리자가 확인한** 비교군(ADR 0015)만 남는다. 비교군의 비교군은 넣지 않는다(IA-Q5 그대로). 주소는 `mine=1`(옛 "내 기술만"을 대신함).
3. 로그인하고 내 기술이 있으면 **도구 줄 아래 띠에 같은 칩**("내 기술과 비교군 n")을 둔다. 새 단추를 늘리지 않고(지도 단추 최소, 사용자 11-20) 한 번 누르면 D8의 "작은 지도"가 된다. 로그인 뒤에는 이 선택도 보기 설정으로 계정에 남는다(design.md 14절 저장 규칙).

## 바뀌지 않는 것
- 비교군은 관리자 확인으로만 정해진다(ADR 0015). 규칙·AI 후보는 이 필터에 들지 않는다.
- 로그인 전에는 이 필터가 없다(내 기술이 없음). 저장 규칙(로그인 전 저장 안 함)도 그대로.
- 불변 1~6.

## 고민한 것
- **D8 그대로(로그인 뒤 기본 = 내 기술 + 비교군):** 내 것과 대안이 바로 보이고 알림과 잘 이어지지만, 로그인하면 오히려 지도가 작아져 둘러보기가 사라지고 로그인 전후가 다른 지도가 된다. 내 것을 모아 보는 일은 "내 레이더"가 이미 한다.
- **전체 지도만(필터 없음):** 내 기술이 320개 사이에 묻힌다. D8이 지키려던 "내 것 먼저"를 잃는다.

## 결과
- 구현 넘김: `feat/P-12c-map`의 기본값을 바꾼다 — 프로젝트가 있어도 처음엔 모은 기술 전체, `mine` 보기 설정이면 지금의 "내 기술 + 비교군 한 단계" 규칙(`layout.ts` `keptNodes`)을 그대로 쓴다. 바꾸는 줄은 기본값 하나와 필터 이름이다.
- 팀 승인(11-20)으로 IA-10 · IA-Q5 · PRD-F23 · `docs/design.md` 3절 확정 줄에 이 ADR을 달았다.
- 번호: main에 QA 시트 ADR 0025가 먼저 들어가 있어, 1차 목적 ADR은 0028로 바꿨다(11-20). 0026은 `feat/P-12c-map`에 있다.
