# 0004. 팀 저장소는 평가 직전까지 공개로 두고, 제출 때 비공개로 전환한다

- 날짜: 2026-11-17
- 상태: 채택

안내서는 팀 저장소를 비공개로 유지하라고 하지만, 개발 기간에는 다른 플랫폼과 공유하기 불편해서 공개로 둔다. 평가(제출) 직전에 비공개로 바꾸고 강사를 collaborator로 초대한다.

## 결과
- 공개 기간에는 올리는 모든 것이 바로 공개된다. 사람 인터뷰는 익명 ID만 쓰고 이름·연락처·소속을 적지 않는다. 비밀값은 지금처럼 `.env`에만 둔다.
- `stage-check`는 제출 전 점검 전까지 공개 상태를 ➖(이 ADR)로 판정한다. 제출 단계에서는 비공개 전환과 초대 수락을 다시 확인한다.

## 2026-11-18 다시 확인
- 안내서 재검토에서 **강사의 비공개 초안**(`프로젝트3-안내서.html`, `프로젝트3-결과물-샘플.html`, 안내서 첫머리 "비공개 초안… 배포하지 않았습니다")과 **강사 메일 주소**가 11-16 첫 업로드부터 공개 저장소에 있다는 것을 확인했다.
- 팀원 결정: **비공개 전환은 평가(제출) 때 한다.** 다른 도구와 연결하고 링크로 공유하기 편해야 하기 때문이다. 이 ADR의 결정은 그대로다.
- 줄이는 방법(팀원 승인): 두 HTML 파일을 **저장소에서 뺐다**(`git rm --cached`, `.gitignore`에 추가, 이 컴퓨터의 파일은 그대로). 저장소 첫 화면과 최신 파일 목록에서는 사라진다.
- 남은 위험: 11-16 커밋 기록에는 남아 있어 찾으면 볼 수 있다. 기록을 고쳐 쓰는 강제 푸시는 팀 저장소 전체에 영향이 커서 하지 않는다. 제출 때 비공개로 바꾸면 기록까지 막힌다.
- 팀원은 안내서를 저장소가 아니라 수업 자료나 팀 내부 채널로 받는다. CLAUDE.md와 stage-check는 각자 컴퓨터의 로컬 파일을 읽는다.
