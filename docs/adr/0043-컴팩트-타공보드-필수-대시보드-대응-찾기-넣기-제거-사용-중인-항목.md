# 0043. 프로젝트 보드는 컴팩트 타공보드, 거르기는 기간 하나, 찾기 · 넣기는 빼고, "내 기술"은 "사용 중인 항목"

- 날짜: 2026-11-23
- 상태: **확정 (사용자 결정, 2026-11-23)**. 조각 P-12k(K1 · K1' · K2 · K3)는 `feat/P-12i-project-board`(#208)에 쌓였다. 전체 검사 · 자체 리뷰(K4) 결과는 끝나면 "결과"에 채운다
- 관련: ADR 0041(프로젝트 관리 보드, 이 ADR로 바뀜), ADR 0028(주 메뉴의 찾기 · 넣기), ADR 0037 · 0040(용어 "담기"), 불변 2 · 5, 안내서 공통 필수 "사용자 대시보드"(PRD-F22) · "직접 입력"(PRD-F7), 계획 사본 `.claude/plans-share/p12k-pegboard.md`

## 배경
사용자가 #208의 보드를 보고 다시 고칠 점을 짚었다.
- **너무 크다.** 글자 15px, 단추 44px, 제목 막대 40px였다. 기본 배치는 약 2,620px로 1440×900 화면의 2.9배였다.
- **같은 정보가 여러 번 나온다.** 판단 대기 수가 5곳, 레포 기술 표가 2벌, 다시 읽기가 2곳, 알림 목록이 3곳이다.
- **숫자가 궁금한 것과 다르다.** 사용자 말로는 "끽해야 오늘의 새 기술, 진행 중 프로젝트, 위험 발생 건수, 활용 기술 정도"이고, "내 기술 몇 개"가 궁금한 사람은 없다.
- **거르기가 맞지 않는다.** 거르기는 위젯마다 다르게 걸렸는데, 주석은 "모든 위젯에 걸린다"고 했다. 861~1199px에서는 오른쪽 열이 잘렸다.
- **"내 기술"이라는 말이 어색하다.** 내가 만든 기술처럼 들린다(사용자 11-23).
- **"찾기 · 넣기" 단추가 겹친다.** 지도 찾기와 하는 일이 겹치고, 붙여 넣기는 쓰임이 적다.

## 결정
1. **컴팩트 타공보드(이번에는 프로젝트 보드에만).**
   - 테마는 "블루프린트 워크벤치 레이더"로 간다. 이번에는 프로젝트 보드에만 타공 구멍 무늬(24px = 스냅 칸)를 입히고 판 머리에 고리를 그린다.
   - 색은 지금 토큰 그대로다.
   - 이 화면 안에서만 작게 쓴다: 본문 13px, 제목 막대 28px, 단추 28px. 판 안에 카드를 겹치지 않는다.
   - 칸 폭은 판 폭 ÷ 48이다. 861~1199px에서 잘리지 않고, ≤860px은 한 줄로 쌓는다.
2. **위 숫자 띠(고정) + 걸린 판 4개.** 위젯은 "걸린 판"이 된다.
   - **띠 6칸:** 오늘의 새 기술 · 진행 중 프로젝트 · 사용 중인 항목 · 위험 발생 · 판단 대기 · 완료. 끝에 [기간]이 붙는다.
   - **판 4개:** ① 진행 중 프로젝트 ② 지도 · 소식 ③ 청사진 ④ 직접 추가. 넣고 빼고 옮길 수 있고, 기본 배치는 1440×900 첫 화면에 다 보이게 한다.
   - **뺀 위젯:** 숫자 4칸 · 판단함 · 바뀐 것 · 옮기기 진행 · 점검한 비율 · 요즘 뜨는 대안 · 기록 찾기 · 레포 관리(→ 띠 · 판 · 레포 상세로). 점검한 비율은 화면에서 빠지고, 주요 지표는 QA 때 SQL로 센다(PRD-F44).
3. **거르기 폼을 없애고 기간 하나만 남긴다.**
   - 띠 안에 [기간] 고르기 하나(오늘 / 이번 주 / 이번 달 / 전체)를 둔다.
   - 상태는 띠의 "판단 대기" · "완료" 칸으로 나눈다.
   - 프로젝트 거르기는 **레포 상세 페이지 `/projects/[id]`** 가 대신한다(PRD-F22 개정).
4. **레포 상세 `/projects/[id]`(새).**
   - 본인 것이 아니거나 없거나 보관했으면 404다. RLS는 그대로다(불변 5).
   - 머리에 이름 · 설명 · 주 언어 · 마지막 푸시 · 마지막 읽기와 수집 오류, [다시 읽기] · [이름 · 메모 고치기] · [보관]을 둔다.
   - **사용 중인 항목 표 한 벌**(숨기기 · 되돌리기), 판단 대기, 바뀐 것, 확정 청사진이 이어진다.
   - 동작 뒤에는 이 페이지로 돌아온다. 보드의 레포 서랍과 레포 관리 판은 없앤다.
5. **찾기 · 넣기를 앱 전체에서 뺀다**(사용자 지시). 나중에 "커스텀 기술 추가"로 다시 넣는다.
   - 메뉴 단추, `CaptureDialog` · `app/capture` · `lib/capture` · `lib/server/capture`를 지웠다.
   - 지도 찾기 칸은 "기술 찾기"로 남는다. 카탈로그에 없을 때의 "직접 추가"는 뺐다.
   - 안내서 필수 "직접 입력"(PRD-F7)은 보드의 **직접 추가 판**이 맡는다. 레포 등록은 진행 중 프로젝트 판, 숨기기 · 되돌리기는 레포 상세가 맡는다.
6. **화면 말 "내 기술" → "사용 중인 항목"**, "내 프로젝트" → "프로젝트".
   - 칩 · 배지 · 트리 폴더처럼 짧은 자리는 "사용 중"이다.
   - **DB · 경로 · 키 · 코드 이름은 그대로다:** `my_technologies`, `/projects/tech`, `mine=1`, `#techs`, localStorage 키.

## 안내서 필수 대시보드(PRD-F22) 대응표 (ADR 0041 표를 바꿈)
안내서 문구: "관심 수, 변경 수, 승인 대기와 완료 수, 최근 변경 — 실제 DB 값, 기간과 상태로 거를 수 있고, 숫자를 누르면 목록, 데이터 없음과 조회 실패 구분."

| 안내서 조건 | 이번 보드에서 |
|---|---|
| 관심 수 | ③ 청사진 판의 "담은 기술 n"(로그인 = 적용 후보, ADR 0040) |
| 변경 수 | ② 지도 · 소식 판 머리의 **"바뀐 것 n"**: 모든 종류, 기간 반영, 누르면 목록(11-23 사용자 결정, DevAssi1이 더함). 띠의 "위험 발생" 칸은 그중 보안 변경만 센다 |
| 승인 대기와 완료 수 | 띠 "판단 대기" · "완료"(`summarizeDashboard`) |
| 최근 변경 | ② 지도 · 소식 판(내 항목에 생긴 새 위험 · 적용 기회 · 모델 종료) |
| 실제 DB 값 | 띠와 판은 서버 읽기 함수로 DB를 읽는다. 로그인 전에는 공개 값(새 기술 수 · 뜨는 것 · 소식)만 보인다 |
| 기간으로 거르기 | 띠의 [기간](오늘 / 이번 주 / 이번 달 / 전체)이 숫자에 걸린다 |
| 상태로 거르기 | 판단 대기 · 완료 칸이 상태별 숫자이고, 누르면 `/alerts?status=pending` · `done` 목록으로 간다 |
| (팀 PRD) 프로젝트로 거르기 | 레포 상세 `/projects/[id]` |
| 숫자를 누르면 목록 | 칸마다 링크가 있다. 숫자 = 그 목록 수(`summarize-dashboard` 시험) |
| 데이터 없음과 조회 실패 구분 | 못 읽은 칸은 "— 읽지 못함", 로그인 전은 "— 로그인 필요"이고, 0과 다르게 보인다(불변 2) |

## 고민한 것
- **거르기 폼을 남기기:** 안내서 문구에 가장 가깝다. 하지만 사용자가 "치운다"고 했고, 기간 하나와 상태 칸으로 문구는 채운다. 프로젝트별로 보는 일은 레포 상세가 더 잘한다.
- **"변경 수" 칸을 띠에 따로 두기:** 띠가 7칸이 되고, 사용자가 꼽은 숫자(위험 발생)와 겹친다. 처음에는 위험 발생 칸으로만 대응했다. 보안 변경만 세서 안내서 "변경 수"와 다르다는 것을 짚자, 사용자가 지도 · 소식 판 머리에 "바뀐 것 n"을 두기로 정했다(11-23).
- **타공보드를 앱 전체에:** 제출 전에는 범위가 크다. 프로젝트 보드에서 먼저 써 본다.
- **"내 기술"을 DB 이름까지 바꾸기:** 마이그레이션 · 경로 · 저장된 키가 깨진다. 화면 말만 바꾼다.
- **찾기 · 넣기를 고쳐서 남기기:** 지도 찾기와 하는 일이 겹친다. 커스텀 기술 추가로 다시 설계한다.
