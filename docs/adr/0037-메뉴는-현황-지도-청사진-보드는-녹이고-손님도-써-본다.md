# 0037. 메뉴는 현황 · 지도 · 청사진, 보드는 녹이고, 로그인 전에도 써 본다

- 날짜: 2026-11-22
- 상태: **확정 (사용자 승인, 2026-11-21 밤)**. Maestro 세션이 사용자와 인터뷰해 정한 앱 구조 개편 계획(P-12f, `I-P-12f-app-structure`)이다. 구현 결과에 따라 "결과와 남은 일"을 채운다
- 관련: ADR 0028(메뉴 다섯), ADR 0032(컨셉), ADR 0034(메뉴 지도 · 청사진, 보드 · 일지), ADR 0035(청사진 스튜디오), ADR 0036(공개 범위), ADR 0038(소식 수집기), 불변 5 · 6, 안내서 공통 필수(대시보드 · 직접 입력 · 기록과 찾기)

## 배경
ADR 0034로 메뉴를 지도 · 청사진 둘로 줄였지만, 11-21 밤에는 화면이 다시 흩어져 있었다.
- 보드 · 일지 · 대시보드 · 추천 · 비교 · 새 기술 · 소식판이 탭 바, 보는 곳 줄, 아바타 메뉴, 링크 없는 주소로 나뉘어 있다. `/new`는 들어가는 길이 없다.
- 대시보드와 일지가 같은 숫자 4칸을 따로 보인다.
- 보드(칸반)는 지도 · 청사진과 다른 세 번째 모양이다.
- 로그인 전에는 지도와 `/new`만 쓸 수 있어, 처음 온 사람이 청사진 · 갤러리 · 기술 상세를 맛볼 수 없다.
- 첫 화면 덮개 "Ready to Catch?" 뒤에서 지도 연출(약 3.75초)이 혼자 돌다 끝난다. 덮개와 지도를 잇는 코드가 없다.
- 화면마다 단추 · 토스트 · 대화상자 · 빈 상태 문구의 모양이 다르다.

## 결정 (인터뷰로 정한 표 그대로)
| 항목 | 결정 |
|---|---|
| 메뉴 | **현황 · 지도 · 청사진** + 찾기 · 종 · 아바타(내 프로젝트 · 설정 · 관리자). 기준 문장 "지키고 · 고르고 · 옮긴다"와 1:1 |
| 보드 | **없앤다.** 지도의 판단 칩(내 관심 · 적용 후보 · 보류)과 청사진 하단 패널의 **"후보" 탭**으로 녹인다 |
| 일지 | 현황 안의 탭으로 옮긴다(목록 유지, 안내서 필수 "기록과 찾기"). "관계로 보기"는 다음 단계 |
| 챗봇 | 관리자 탭 그대로(일반 사용자에게 내부 문서를 보이지 않음). 사용자 AI는 맥락 안에서만 |
| 커뮤니티 | 갤러리를 분야별로 거르고 많이 쓴 순 · 도움 순. 지도에 "요즘 뜨는" 칩. 팔로우 · 댓글은 안 함 |
| 비로그인 | 지도 · 기술 상세 · 청사진(브라우저 초안) · 갤러리 · 소식은 로그인 없이. 확정 · 템플릿 저장 / 공개 · AI 점검 · 판단 · 태그는 로그인 |
| 첫 화면 | 덮개 = 로딩. 데이터가 준비되면 단추가 켜지고, 누르면 연출이 시작된다. 움직임 줄이기면 바로 보인다 |
| 자동 할당 | 사용자: **내 태그 자동 제안**(규칙, 사람이 고름). 관리자: **카탈로그 자동 분류** 단추 |
| 소식 | 이미 모은 사건 + **바깥 소식 수집기**(ADR 0038) |

- **현황(`/dashboard`, 이름만 "현황"):** 탭 개요 | 일지 | 소식. 개요는 안내서 필수 숫자 4칸 → 내 레포 현황 → 적용한 기술 → 판단 대기 알림 → 이번 주 · 보류 회고. 일지의 숫자 4칸은 뺀다(개요에만). 로그인 전에는 소식만 보인다.
- **옮기는 주소:** `/views` → `/`(지도). 단 옛 탭은 가장 가까운 새 자리로: `?tab=gallery` → `/dashboard`(옛 "갤러리" 탭은 템플릿이 아니라 **내 기술 카드**였고, 새 자리는 현황 개요 "적용한 기술"), `?tab=news` → `/dashboard?tab=news`(현황 소식). `/new` → `/?t=week`. `/recommend`는 현황 개요 카드에서 들어간다. 계획 사본의 "갤러리 → `/blueprint/gallery`"는 템플릿 갤러리와 헷갈린 문구라 바로잡았다(11-22, 통합 브랜치 5cc096c `lib/nav/moved.ts`에서 확인).
- **불변 5:** 손님에게는 개인 데이터(내 기술 · 판단 · 알림 · 프로젝트 · 태그)를 절대 내보내지 않는다. 서버 함수마다 로그인 검사를 그대로 둔다. 손님 갤러리는 ADR 0036 개정.

## 고민한 것
(인터뷰 기록에 버린 안 목록은 없다. 아래는 계획에서 DocsChecker가 정리한 것이다.)
- **보드를 세 번째 메뉴로 남기기(ADR 0034):** 판단 상태를 한 화면에 모아 보지만, 지도 · 청사진과 모양이 달라 어긋나 보이고 같은 일을 두 곳에서 한다.
- **일지를 따로 메뉴로:** 안내서의 "기록과 찾기"는 현황 탭으로도 한 번에 간다.
- **로그인 전에는 지도만:** 가장 안전하지만 처음 온 사람이 청사진을 맛볼 수 없다.
- **챗봇을 사용자에게 열기:** 위키는 팀 내부 문서라 일반 사용자에게 보이지 않는다(위키 · 챗봇 규칙).

## 결과와 남은 일
- **ADR 0034를 바꾸는 곳:** 메뉴(지도 · 청사진 → 현황 · 지도 · 청사진), 보는 곳 줄 "지도 | 보드 | 일지"와 보드(4칸)는 없어진다. 판단 = 청사진으로 가는 관문(0034 1항)은 그대로다.
- **안내서 공통 필수:** 대시보드는 "현황", 직접 입력은 "내 프로젝트"로 둘 다 한 번에 가는 길이 남는다.
- **마이그레이션은 운영 적용 전에 사용자 승인:** M6(손님 갤러리), M7(소식, ADR 0038).
- **구현 결과(조각마다 채움):** _아직 없음_
