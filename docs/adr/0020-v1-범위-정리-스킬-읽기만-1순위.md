# 0020. v1 범위 정리: 스킬 폴더 읽기만 1순위, `requirements.txt`·프로젝트 수정·보관·주제 태그 탐색은 3순위

- 날짜: 2026-11-18
- 상태: **채택** (2026-11-18, 문서 점검 2차의 Y-8을 사용자가 `grilling`으로 추천안대로 정함. 다른 팀원은 PR 리뷰에서 확인)

문서 점검(`docs/문서점검-20261118.md` Y-8)에서 "요구는 있는데 맡은 조각이 없는 것"이 나왔고, 2차 점검에서 하나가 더 나왔다. PRD-F6(1순위)은 저장소의 `package.json`·`requirements.txt`·`.mcp.json`·`.claude/skills/` 4종을 읽으라고 하는데, 코드는 앞의 2종만 읽고 plan에는 나머지를 맡은 조각이 없었다(`lib/domain/manifest.ts`의 주석은 "P-9·P-11에서 더한다"고 하지만 둘 다 아니다). 남은 일정은 M1 11-19 21:00, 코드 동결 11-20 21:00이고 김영식 몫으로 P-9b·P-9c와 구글 로그인이 든 P-12가 남아 있다.

## 정한 것
1. **`.claude/skills/` 읽기만 새 조각 P-9e로 1순위에 남긴다**(김영식, M2 11-20 낮). 스킬은 이 제품이 지켜보는 핵심 종류(AI 코딩 도구)라 빠지면 내 기술 목록이 비어 보이기 때문이다. M1 끝 기준에는 넣지 않아 로그인 일정을 건드리지 않는다.
2. **`requirements.txt` 읽기는 3순위**(P-22 옆). 파이썬 의존성은 시연 저장소가 파이썬일 때만 의미가 있다.
3. **PRD-F4의 프로젝트 수정·보관은 3순위.** 공개 저장소 주소 검사·등록은 1순위로 이미 되어 있다(P-3 보강).
4. **GitHub 주제 태그로 새 기술 찾기는 3순위**(P-22 옆). 1순위의 새 기술 경로는 공식 MCP 레지스트리(P-9c)만 둔다.
5. **주 숫자(회의 D4)는 요구 PRD-F44로 만든다.** 화면은 만들지 않고, QA 때 SQL 한 번으로 계산해 숫자로 남긴다.
6. **NF2~NF5의 담당과 QA를 plan에 적는다**(NF2·NF3 김영식, NF4 황재웅, NF5 각자). NF3 끝 기준은 "측정값 기록"에서 "3초를 넘으면 이유도 기록"으로 고친다(넘어도 통과하던 빈틈을 줄임).
7. **F21 끝 기준(UJ-9 장면 재현)은 이미 있는 시나리오로 본다.** P-5b 적용 기회 시나리오와 P-15 비슷한 지난 판단 카드가 `docs/qa.md` 해당 행에서 Pass면 끝이고, 안 되면 그때 조각을 더한다.

## 결과
- prd F4·F6·F8·F21·NF3와 "만드는 순서"(3순위 행), 새 요구 F44, spec 7.1, ia IA-2·IA-3, 문제정의 2절, 데이터설계 7절, flow `fetch_repo`, plan(P-9 행, **P-9e 새 조각**, P-22 행, 품질 요구 담당 표), ADR 0008 개정 줄에 반영했다.
- 1순위 PRD 개수는 그대로 27개(F23까지 28개)다. F6은 1순위에 남고 그 안의 `requirements.txt`만 3순위로 내려갔고, F44는 순서표의 "따로"에 둔다.
- **확인하지 못한 것:** P-9e가 하루 안에 끝나는지(스킬 폴더 구조가 저장소마다 다르다). 주 숫자의 정의: F44는 erd가 이미 정한 대로 "`grade_views`가 하나라도 있는 내 기술 수 ÷ 내 기술 수"로 적었다(처음에 앱이 열어 본 것을 기록하지 않는다고 잘못 썼다가 검토에서 바로잡음). 카탈로그에 연결되지 않은 직접 추가 기술이 분자에 못 들어가는지는 코드로만 봤고 실제 값은 확인하지 못했다.

## 고르지 않은 것
- **`.claude/skills/`와 `requirements.txt`를 둘 다 P-9e에 넣기:** M1·M2 일정이 빠듯하고, 시연 저장소가 파이썬이 아니면 효과가 없다.
- **둘 다 3순위로 내리고 PRD-F6을 2종으로 줄이기:** 스킬이 빠지면 "내 기술 목록"이 제품 주제의 한 축을 잃는다.
- **프로젝트 수정·보관을 1순위에 두기:** 등록만으로 시연이 가능하다.

## 개정
- 2026-11-21(ADR 0030): 정한 것 4번의 **"GitHub 주제 태그로 새 기술 찾기"를 3순위에서 앞당긴다**(P-21a). 이유: 두껍게 들어오는 경로가 공식·사용 중뿐이라 지도·비교의 재료가 좁고, 별·포크·푸시 같은 신호가 검색 결과 한 건에 같이 와서 읽기 비용이 작다. 관문·의심 거르기·점수와 상한 100은 ADR 0030, 나머지(`AGENTS.md`·`GEMINI.md`·연동 서비스·모델 지원 종료)는 그대로 3순위.
