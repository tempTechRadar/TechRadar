# 0005. 문제 정의는 두 가설을 나란히 두고, 사람 인터뷰로 판정한다

- 날짜: 2026-11-17
- 상태: 채택 (판정 결과는 인터뷰 뒤 새 ADR로)

팀 안에서 서비스 방향이 두 갈래로 나뉘었다. 가설 A는 "새 기술 소식 지켜보기형"(이 PC 작업), 가설 B는 "작업 중 막힘 → 검색·추천형"(팀원 PR #1)이다. 한쪽으로 정리하지 않고 `docs/문제정의.md`에 둘 다 적고, 둘을 합친 안 C(공개 저장소 + 필요 등록 → 소식이 그 필요에 맞으면 알림)를 제안으로 둔다. 판정은 팀 밖 사람 인터뷰로 한다. 같은 쪽 장면이 2명 이상에게서 나오면 그쪽을 중심으로 C를 고치고, 결과가 갈리면 둘 다 적은 채 C로 간다. 팀원 본인 인터뷰는 판정 인원에 세지 않는다.

## 고려한 다른 방법
- 인터뷰 전에 한쪽으로 정하기: 근거가 AI 인터뷰(가설)와 팀원 본인 인터뷰(힌트)뿐이라 접었다.
- 인터뷰를 가설마다 따로 하기: 시간이 없어(최종 발표 11/23) 질문지 하나로 두 가설을 가르게 했다.
