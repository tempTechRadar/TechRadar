# 0026. 첫 화면 지도는 사용자가 고르는 단계별 묶기 + 색 = 분류 + 보안은 기호로

- 날짜: 2026-11-19
- 상태: **확정 (팀 승인, 2026-11-20)**. 처음엔 사용자(영역 A, 지도 담당)의 제안이었고 팀이 승인했다. 함께 바뀐 것: 로그인 뒤 기본은 전체 지도(ADR 0027, `docs/design-concept-3`), 1차 목적(ADR 0028, 처음 번호 0025)
- 관련: PRD-F23·F24, IA-10·IA-17, ADR 0015(같은 역할), ADR 0028(제안, 목적·흐름), 데이터설계 DQ2(갈래 처음 목록), `docs/design.md` 11절, 계획 `I-P-12c-map`

## 배경
PRD-F23 확정 표시는 "색과 기호 = 등급, 크기 = 인기, 흐림 = 오래 안 바뀜, 노란 점 = 최근 변경, 라벨 = 업데이트 n일 전, 내 기술을 가운데에"다. 1차 지도를 보고 사용자가 말했다(2026-11-19 밤):
- 원반을 갈래별 부채꼴로 나눈 것은 별로다. 같은 소속·같은 기준으로 **단계별로 분류**하고, 올리면 그 연결이 보여야 한다.
- 노션처럼 **1~n차 묶기 기준과 거르기를 사용자가 직접 골라** 볼 수 있어야 한다.
- 지도에는 업데이트 정보를 빼고, 위험·주의·새로 들어옴 같은 것만 표시한다.
- **색은 분류 값**(디자인·프로그래밍·리서치 …)이어야 한눈에 어떤 기술인지 안다. 위험·주의는 점 옆 기호와 효과로 눈에 띄게.
- **크기·모양은 단계(계층)**로. 인기는 수집 관문을 통과했으면 충분하고 고르는 건 사용자 몫이라 지도에 둘 필요가 없다. 흐림도 맞지 않다.
- "같은 역할"보다 "비교군"이 낫다. 점을 누르면 화면이 잠깐 밀렸다 돌아온다(버그).

운영 DB(11-19, 읽기만): 갈래 0개, `hosts` 0개, 모은 기술 5,565개(MCP 5,563). 분류 축으로 쓸 데이터가 비어 있었다.

## 결정
1. **묶기는 사용자가 고른다**: 1~3차 기준(하는 일 · 세부 갈래 · 종류 · 쓰는 곳 · 보안 등급 · 내 프로젝트). 기본 = 하는 일 › 종류. 레이더 고리 안쪽부터 1차 묶음(육각형) → 2차(마름모) → 3차(네모) → 기술(점). 크기·모양은 단계만 뜻한다.
2. **색 = 사용자가 고른 기준의 값**(기본은 1차 기준). 범주 8색은 dataviz 검사기로 옆 묶음끼리 구별되게(정상 ΔE ≥ 17.5, 색약 ≥ 7.6) 골랐고 빨강·호박은 뺐다. 8개를 넘는 값은 "그 밖", 값이 없으면 "분류 전"(회색). 색 기준이 보안 등급이면 위험 = 빨강, 주의 = 호박으로 고정.
3. **보안은 기호**: 위험 = 빨간 ✕ 표 + 깜박이는 고리(움직임 줄이기면 멈춘 고리), 주의 = 호박색 ! 표, 수집 오류 = 점선 고리, NEW = 카탈로그에 들어온 지 7일 안. 업데이트·인기·마지막 확인은 카드와 사이드바에만.
4. **올리면 이어진 것만 진하게**: 묶음은 위로 가는 길 + 그 아래 전부, 기술은 위로 가는 길 + 비교군.
5. **누르면 사이드바가 지도 위에 덮인다**(지도 크기 그대로). 고른 점이 가려지면 지도만 옆으로 옮긴다. 밀림 버그는 초점 이동 때 화면이 따라 스크롤된 것이라 `preventScroll`로 고침.
6. **화면 글자는 "비교군"**. DB(`same_role`)·ADR 0015의 정의는 그대로다.
7. **보기 설정은 주소 + 이 브라우저**(DB 변경 없음).
8. **갈래 처음 목록(DQ2의 답)**: 큰 갈래 10개 = 사용자가 고른 추천 8개(리서치 · 기획·문서 · 디자인 · 프론트엔드 · 백엔드·데이터 · 검사·보안 · 배포·운영 · AI 작업 방식) + 카탈로그 표본을 보고 Claude가 더한 2개(업무·서비스 연동, 생활·정보), 세부 갈래 33개와 낱말 규칙. 매일 정기 실행이 갈래가 빈 기술에 규칙으로 갈래를 붙인다(관리자가 정한 것은 안 덮음). 운영 카탈로그 전체로 재 보니 **53%(2,940개)**가 세부 갈래를 받고 47%는 "분류 전"으로 관리자 확인(IA-17)에 남는다. 비긴 것은 같은 큰 갈래 안이어도 비워 둔다(큰 갈래만 저장하면 관리자 목록과 다음 분류에서 빠져 세부 갈래를 영영 못 받음, 코드 검토).

## 바뀌지 않는 것
- 불변 1~6. 수집 오류는 "변화 없음"으로 보이지 않는다(점선 고리와 카드의 "수집 오류"). 시뮬레이터 기술·관계는 시연 계정에만. 본인 데이터만(owner_id + RLS).
- 지도 범위: 프로젝트가 있으면 내 기술 + 확정된 비교군 한 단계(IA-Q5).
- 같은 역할의 확정은 관리자만(ADR 0015).

## 고민한 것
- **확정대로 두기(색 = 등급)**: 보안이 1차 목적이 아니게 된 지금(ADR 0028 제안) 색을 등급에 쓰면 "어떤 분야의 무엇인가"가 안 보인다. 등급은 기호로 남는다.
- **나무 하나로 고정(예: Claude › Claude Code › 스킬 › 디자인)**: 한 기술이 여러 무리에 속하고 축(쓰는 곳·종류·하는 일)이 섞인다. 기준을 골라 묶는 쪽이 같은 데이터로 여러 보기를 만든다.
- **보기 설정을 계정에 저장**: 노션처럼 이름 붙인 보기 여러 개가 좋지만 새 표·권한이 필요해 제출 뒤로.
- **Claude API로 애매한 기술 분류**: 분류율을 올리지만 호출 비용이 들어 승인 뒤에(이번엔 규칙만).
