# 0011. 빈도·손해는 수치화하지 않고, 발표의 "숫자 하나"는 지금 방식과 비교한 작업으로 잰다

- 날짜: 2026-11-18
- 상태: **채택** (2026-11-18 회의). 처음: 제안 (2026-11-17 팀원 판단을 안내서 재검토 뒤 ADR로 남김. 회의 D4와 함께 팀 확인)

안내서는 손해와 빈도(584·614줄), 좋아졌는지 잴 숫자 하나(834·1172줄)를 요구한다. 팀원은 2026-11-17에 "빈도·손해는 수치로 딸 수 있는 값이 아니다"라고 판단했다. 인터뷰에서 빈도(Q14)·판단 시간(Q2)의 지금 값도 얻지 못했다. 안내서 재검토(검토 도우미, 11-18)는 이 결정이 ADR 없이 문제정의 한 줄에만 있고, 문제정의 6절의 "지금 방식과 비교할 작업"을 아직 해 보지 않았다고 짚었다.

## 정한 것
- **빈도·손해는 수치화하지 않는다.** 당사자 말(문제정의 5절)과 공개 사례(P1–P5)로 설명한다. 안내서 요건이지만 이 서비스의 성격상 참작한다.
- **발표의 "숫자 하나"는 실제로 재는 비교 작업**으로 채운다. 같은 저장소 하나를 두고 ① 손으로(파일을 열어 깐 것을 적고, 기술마다 취약점·최근 업데이트를 검색) ② 앱으로(등록 → 내 기술 목록과 등급) **걸린 시간과 찾은 위험 수**를 잰다. 사람이 하고, 잰 것으로 표시한다.
- 앱 안의 주 숫자(회의 D4 후보: 등급과 이유를 확인한 기술의 비율, `grade_views`)는 그대로 둔다. 사용자가 없어 발표 때는 시연 계정의 값만 있다는 한계를 말한다.

## 결과
- plan에 "비교 작업 측정" 조각(사람)을 넣는다.
- 문제정의 11절의 빈도·판단 시간 줄은 이 ADR을 가리킨다.

## 고르지 않은 것
- 인터뷰를 더 해서 빈도를 받기: 남은 5일과 사람 인터뷰 섭외 비용에 비해 얻는 것이 적다.
