# 0016. 관리자도 본인 알림은 판단할 수 있다(남의 알림은 못 한다)

- 날짜: 2026-11-18
- 상태: **채택** (2026-11-18, 기본 문서 점검 D-6을 사용자가 추천안으로 정함. 다른 팀원은 PR 리뷰에서 확인)

기본 문서 점검(`docs/문서점검-20261118.md` D-6)에서 문서와 실제 DB가 다른 것이 나왔다. spec 4.1, 데이터설계 4절, `flow/flow.json`은 "관리자는 판단을 만들 수 없다"고 했다. 그런데 실제 DB 함수 `save_judgment`는 "본인 알림인가"만 확인한다(`supabase/migrations/202611181400_P-2_m0_tables.sql`의 `v_alert.user_id <> v_uid`). 그래서 관리자도 **자기** 알림에는 판단을 저장한다. 함수 위 주석과 시험 `admin_judge_other_blocked`(`supabase/tests/rls_m0.sql`)도 "관리자도 **남의** 알림은 못 한다"는 뜻이다. 이 시험은 P-2 때 26개 모두 통과했다.

## 정한 것
- 관리자는 사용자이기도 하다. **자기 알림에는 판단(적용 후보·보류)을 저장할 수 있다.** 다른 사용자와 같은 규칙(보류 이유 5자 이상, 보안 경고의 적용 후보는 고친 버전 필요, 한 번 저장하면 고칠 수 없음)을 따른다.
- **남의 알림에는 판단을 만들거나 건너뛸 수 없다.** 화면(관리자 알림 현황에 판단 버튼 없음)·서버·DB(`save_judgment`)에서 막는다. 팀 CLAUDE.md의 불변 1("관리자도 승인을 건너뛸 수 없다")은 이렇게 읽는다: 남이 대신 건너뛰는 것을 막는 규칙이지, 관리자가 자기 알림에 판단하는 것을 막는 규칙이 아니다. 불변 1의 문장은 바꾸지 않는다.
- DB는 바꾸지 않는다. 문서와 `flow.json`의 설명 값(`admin_can_judge`)만 맞춘다.

## 이유
- 새 마이그레이션 없이 DB와 문서를 같게 만들 수 있다. 이번 작업은 문서만 고친다.
- 막으려던 것(남이 대신 판단하거나 건너뜀)은 이미 DB와 시험이 막고 있다.

## 결과
- spec 4.1, 데이터설계 4절, `flow/flow.json`의 `admin_can_judge`, plan 13줄·P-8, prd F17, uj UJ-M4·88줄, ia 관리자 화면 머리말, 데이터설계 5절을 "남의 알림은 못 함"으로 맞춘다. 관리자 화면(IA-14·F27·P-18)의 "판단 버튼 없음"은 모든 회원의 알림 목록 화면 이야기라 그대로 둔다. erd 4절의 judgments 줄("본인 알림에만… 관리자 읽기만")은 테이블에 직접 쓰는 권한 이야기라 그대로 맞다.
- 시험은 지금 그대로 맞다: 남의 알림 판단 막힘(`admin_judge_other_blocked`). 관리자 본인 알림 판단이 되는 것을 확인하는 시험은 없다. 더하는 일은 P-8 때 정한다.
- GLOSSARY "관리자" 설명에 한 줄 더한다.

## 고르지 않은 것
- 관리자는 판단 자체를 금지: 새 마이그레이션과 시험이 필요하고(운영 DB와 같은 곳이라 적용 승인도 필요). 남의 알림은 이미 막혀 있어서 얻는 것이 작다.
