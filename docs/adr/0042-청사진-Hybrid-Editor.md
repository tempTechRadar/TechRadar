# 0042. 청사진 Hybrid Editor: 단계 안에 기술 노드, 사용자 표시 관계, 셀 수 있는 것만 검증

- 날짜: 2026-11-22
- 상태: **확정 (사용자 결정, 2026-11-22 밤: 제출 전 전부)**. 조각 P-12j(`feat/P-12j-hybrid-editor`, `I-P-12j-hybrid-editor` · `I-P-12j-links-core`)는 **PR #209(열림, #206 위)** 로 올라갔다 · **같은 밤 사용자 점검 뒤 바뀜:** 왼쪽 Library · 오른쪽 고정 Inspector는 되돌리고 넓은 캔버스 + 아래 패널 탭 넷 + 고를 때만 여는 서랍(아래 1항)
- 관련: ADR 0040(한 화면 · 아래 패널, 아래 패널 탭만 이 ADR로 늘어남), ADR 0035(자유 캔버스 · 단축키 거의 없이, 이 ADR로 일부 바뀜), ADR 0034(관문), ADR 0036(공개 템플릿), 불변 1 · 2 · 5, 계획 사본 `.claude/plans-share/p12j-hybrid-editor.md`

## 배경
- 사용자가 Hybrid Editor 안을 붙였다. 단계를 컨테이너로 두고 그 안에 기술 노드를 넣으며, 왼쪽에 Library, 오른쪽에 Inspector, 아래에 검증 독을 두는 편집기다. 사용자는 이것을 제출 전에 전부 넣기로 했다.
- 붙인 안을 그대로 쓰면 우리에게 없는 데이터를 있는 것처럼 보이게 되는 곳이 있다.
  - "호환 · 의존성 검증"
  - "누락된 의존성 · 충돌"
  - "AI Tool · Framework" 같은 종류

  그래서 Maestro가 데이터 정직성 규칙 5가지를 정했다.

## 결정
1. **레이아웃**
   - 위 막대: 이름 · 되돌리기 · 다시 · ＋단계 · 자동 정렬 · 보기 초기화 │ **검증** · **확정 · 내보내기**
   - **넓은 캔버스 + 아래 패널(높이 조절 · 접기).** 탭은 [기술 | 불러오기 | 검증 | 변경 이력]이다.
     - 기술 · 불러오기는 ADR 0040 그대로다. 카드는 끌어서 단계에 놓거나 [+]로 넣을 단계를 고르고, 이미 판에 넣은 것과 아직 후보인 것을 다르게 표시한다.
     - 검증 탭: 위 작은 줄 = 구성 요약(단계별 · 종류별 수), 아래 = 검증 항목(아래 4항 2). 위 막대 "검증"을 누르면 패널을 펼쳐 이 탭을 연다.
     - 변경 이력 탭: 이 화면에서 판을 바꾼 일(되돌린 것 포함).
   - **Inspector = 고를 때만 겹쳐 여는 오른쪽 서랍.** 탭은 개요 · 관계 · 검증 · 이력이다(ADR 0040 4항의 서랍에 탭을 더함).
   - 좁은 화면(≤860)은 지금 목록 모드 그대로다.
   - **처음 계획과 다른 점(11-22 밤 사용자 점검):** 처음에는 왼쪽 Library(250) · 오른쪽 고정 Inspector(300) · 아래 검증 독(실행 로그 탭 포함)으로 만들었다(H1). 사용자가 써 보고 "캔버스가 좁아 답답"하다고 해 되돌렸다. 실행 로그 탭은 뺐다.
2. **단계 = 컨테이너, 기술 = 자식 노드**(React Flow `parentId`, `extent: 'parent'`)
   - 단계 안에서 끌면 순서가 바뀐다(graph의 `techs` 순서). 안에서의 자리는 자동 흐름 배치라 DB에 남기지 않는다.
   - 다른 단계로 끌어 놓으면 옮긴다. 이때 기존 `putProblem` 검사를 하고, 되돌리기는 한 번이다.
3. **선은 두 가지**
   - 단계 연결: 굵은 실선 화살표, 지금 그대로다.
   - **사용자 표시 관계:** 기술 사이의 가는 점선이다.
     - graph에 `links: [{from, to}]`를 더한다. 끝은 `기술id@단계id`이다.
     - 없는 기술 · 자기 자신 · 겹침은 빼고 100개까지 둔다. 틀린 선만 빼고 판 전체를 거절하지는 않는다.
     - DB `blueprint_graph_clean`이 같은 규칙으로 지킨다(마이그레이션 `202611232200_P-12j_tech_links.sql`).
     - 조합 템플릿에는 관계선이 남는다. 사용자가 그은 표시라 개인 글이 아니다. 틀 템플릿은 기술을 비우므로 관계선도 빠진다.
     - 내보내기(프롬프트 · CLAUDE.md · Mermaid)에 "사용자 표시 관계: A → B" 줄을 넣는다.
4. **데이터 정직성 규칙 5가지**(Maestro, Hybrid 안을 그대로 쓰지 않는 곳)
   1. 기술 사이 관계선은 **사용자가 긋는 표시**다. "검증 · 호환 · 의존성 확인"으로 부르지 않는다. 우리에게는 호환 데이터가 없다.
   2. 검증 탭에는 **실제로 셀 수 있는 것만** 보인다.
      - 보이는 것: 위험 등급, 담지 않은 기술(관문 밖), 수집 오류, 단계 · 같은 순서 · 깊이 한도, 빈 단계, 고리, 기술 없는 단계
      - "누락된 의존성 · 충돌"은 없다.
      - 순수 함수 `validateGraph` 하나가 낸다. 확정 창의 "고칠 것"도 같은 함수를 쓴다.
   3. 노드 종류는 **우리 카탈로그 종류**(`KIND_KO` · `TYPE_KO`)를 따른다. 스킬은 "SKILL.md 패키지"로 적어, 사람의 역량이 아님을 보인다.
   4. Inspector(서랍)는 **근거가 있는 칸만** 보인다(등급 이유 · 출처 · 버전 · 마지막 확인). 근거가 없으면 "정보 없음", 못 읽으면 "읽지 못함"이다(불변 2).
   5. 새 라이브러리(ELK · Zustand)는 쓰지 않는다. React Flow 하위 노드와 지금의 `autoLayout`으로 한다.
5. **단축키는 Ctrl+Z / Ctrl+Shift+Z만 더한다.**
   - 입력칸 안에서는 브라우저 기본 동작을 따른다.
   - Ctrl+S는 넣지 않는다(초안이 자동 저장된다).
   - ADR 0035 / 11-21의 "단축키 거의 없이(Esc · Delete · 스페이스 손 모드만)"를 이 두 키만큼 고친다.
6. **11-23 바뀜(ADR 0044):** 앱은 어두운 "관측소" 테마 한 벌(남색 밤하늘 · 청록 강조). 아래는 11-22 결정. **색은 지금 그대로다.** 다크 테마는 넣지 않는다. 색은 상태에만 쓰고, 종류는 아이콘과 라벨로 보인다.
7. **여러 개 고르기**(상자 고르기 · Shift)로 함께 옮기고 지운다. 지우면 토스트로 되돌릴 수 있다.

## 고민한 것
- **붙인 안을 그대로(호환 검증 · 의존성 경고):** 거짓 경고 위험이 있다. 셀 수 있는 것만 검사하고, 사람이 그은 선은 "표시"라고 부른다.
- **왼쪽 Library · 오른쪽 고정 Inspector(붙인 안 그대로):** 한눈에 다 보이지만 캔버스가 좁아진다. 만들어 보고 사용자가 "답답"하다고 해 ADR 0040의 아래 패널 · 서랍으로 돌아갔다. 대신 아래 패널에 검증 · 변경 이력 탭을 더했다.
- **ELK 자동 배치 · 상태 관리 라이브러리:** 새 라이브러리 금지(H). 지금의 `autoLayout`이 컨테이너 크기를 반영하게 고친다.
- **관계선을 템플릿에서 빼기:** 메모와 달리 개인 글이 아니어서 남긴다(ADR 0036 공개 범위 안).
