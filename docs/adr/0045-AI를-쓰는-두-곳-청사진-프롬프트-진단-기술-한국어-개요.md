- 날짜: 2026-11-23
- 상태: **확정 (사용자 결정, 2026-11-23 오후 "API 이제 써")**. 진단은 #224(11-23 14:41 KST), 한국어 개요는 #226(15:06 KST)으로 main에 합쳐졌다. 사람 QA 결과는 끝나면 "결과"에 채운다
- 관련: PRD-NF6(이 ADR로 고침, 저녁에 가이드까지 일곱), PR #230(P-12s 청사진 가이드), ADR 0035(청사진 스튜디오 · AI 점검 하루 한도), ADR 0029(로그인 전 지도 공개 칸, 3항에 P-12r 칸 추가), ADR 0044(지도 · 테마), 불변 1 · 2, PRD-NF2, 작업 I-P-12q-ai-diagnosis · I-P-12r-ko-overview · I-P-12r-ko-view

- 11-22 사용자가 Claude API 실제 호출을 멈췄다(사전 허가 F). 11-23 오후 "API 이제 써"로 다시 풀었다.

  - **청사진:** 내보내기 프롬프트를 복사해 가면, 겹치는 기술 · 서로 부딪치는 설정 · 단계 순서 문제를 사람이 직접 찾아야 했다.
  - **지도 · 기술 상세:** 기술 한 줄 설명이 영어 원문이라 처음 쓰는 사람이 읽기 어렵다.
- 두 곳 모두 AI 답이 틀릴 수 있다. 그래서 무엇을 AI 결과로 표시하고, 무엇을 막고, 원래 값을 어떻게 지킬지 정했다.

## 결정
1. **청사진 프롬프트 진단(P-12q, #224).** 기존 AI 점검(ADR 0035)을 넓힌다.
   - 확정본에서 "점검 받기"를 누를 때만 부른다. 한 번에 제안 · 주의할 점과 함께 진단 넷을 받는다: 중복 · 간섭과 충돌 · 단계 순서 · 다듬은 프롬프트(4000자 이내).
   - 재료는 사용자가 복사해 가는 내보내기 프롬프트 원문이다(관계선 · 섹션 포함).
   - 화면에 **"AI 제안 · 검증 아님"**을 붙인다. 기술끼리 실제로 함께 되는지 알려 주는 호환 데이터가 없어서다. system 지시도 "확신하지 말고 근거를 쓰라"고 한다.
   - 청사진과 원래 내보내기 복사는 바꾸지 않는다(불변 1). 다듬은 프롬프트는 [다듬은 프롬프트 복사]로 사람이 펼쳐 읽고 따로 가져간다.
   - 파서(`lib/ai/parse-check-response.ts`)가 모양이 틀린 진단 항목만 버린다: 프롬프트에 없는 기술 이름, 넘기지 않은 주소, 스킴 없는 주소 · IP. **설치 · 셸 명령이 든 다듬은 프롬프트는 통째로 버린다.**
   - 하루 3번(`BLUEPRINT_CHECK_PER_USER_PER_DAY`)이고 같은 재료로 다시 누르면 이전 결과를 다시 쓴다. 호출은 `ai_calls`에 남긴다.
   - 점검 호출만 8000토큰 · 120초를 쓴다(청사진 페이지 함수 시간 300초). 초안 · 시나리오 · 챗 호출은 기본값(2048토큰 · 30초) 그대로다.
   - 결과는 `blueprint_checks.body.diagnosis`(jsonb)에 둔다. DB 변경은 없다.
2. **기술 한국어 개요(P-12r, #226).**
   - 한 줄 설명(영어)을 한국어 한 문장으로 번역해 `one_liner_ko`에 저장하고, 번역한 원문(`one_liner_ko_src`) · 시각(`one_liner_ko_at`)을 함께 둔다. 마이그레이션 `202611240400_P-12r_one_liner_ko.sql`(칸 3개 + `ai_calls.purpose` `translate`, 운영 적용: 완료 · Maestro).
   - 화면은 한국어 개요를 먼저 보이고 **"AI 번역"** 표시와 [원문 보기](영어 원문 + 출처 열기)를 붙인다. 붙인 곳: 지도 사이드 패널 · `/tech/[id]` · `/projects/tech/[id]` · 청사진 서랍 "설명". 출처 링크는 http(s)만 건다.
   - **원문이 바뀌면 숨긴다:** 번역 뒤 원문(`one_liner`)이 바뀌면 서버(`koOf`)가 번역을 내보내지 않는다. 그러면 지금처럼 원문 · 분류 한 줄이 보인다.
   - **길면 버린다:** 80자로 요청하고, 120자(`KO_ACCEPT_MAX`)를 넘는 답은 버린다. 원문이 400자를 넘으면 번역하지 않는다(잘린 글을 번역해 원문처럼 저장하지 않게).
   - 번역은 화면을 열 때가 아니라 미리 돌려 저장한다(10개씩 묶음, 실패한 묶음은 건너뛰고 있던 값은 지우지 않음). 운영 백필 **497/500 · 호출 38번**(1차에 잘린 6묶음을 다시). 남은 3개는 120자를 넘어 버렸고 화면은 원문 그대로다. (PR #226 설명의 숫자, Maestro 실행. DocsChecker가 다시 세지는 않았다.)
   - 로그인 전 지도의 공개 칸에 `one_liner_source` · 한국어 3칸을 더했다. 모두 공개 한 줄 소개에서 나온 값이라 새 개인 정보가 없고, 쓰기는 서버뿐이다. 칸 목록은 ADR 0029 3항에 적었다(그 ADR의 "공개 칸 = 지도가 쓰는 칸" 규칙을 따른 것).
3. **두 곳 공통.**
   - AI 결과에는 늘 표시를 붙인다("AI 제안 · 검증 아님", "AI 번역"). 사실처럼 보이게 두지 않는다.
   - AI 결과가 원래 값을 덮지 않는다. 청사진 · 내보내기 원문 · 영어 원문은 그대로다.
   - 자료 안의 글은 지시로 따르지 않는다(기존 AI 규칙 그대로).

## 고민한 것
- **진단 결과를 청사진에 바로 반영:** 사람이 승인하기 전에는 조치하지 않는다는 불변 1과 맞지 않는다. 복사 단추로 사람이 가져가게 했다.
- **번역을 영어 원문 자리에 덮어쓰기:** 원문과 출처 주소는 공개 목록의 근거다. 칸을 따로 두고 [원문 보기]로 늘 볼 수 있게 했다.

## 남은 위험 (#224 · #226 설명)
- 진단은 확정본 기준이다. 확정한 뒤 판을 고치면 다듬은 프롬프트와 지금 내보내기가 다르다.
- 단계 메모도 Claude로 간다(내보내기 원문에 들어 있음). 비밀 키 모양은 가린다.
- 다듬은 프롬프트는 자유 글이라 거르는 규칙에 빈틈이 있을 수 있다. 세미콜론 · 백틱은 보통 글에도 나와서 막지 않는다.
- system 지시가 바뀌어 옛 점검은 다시 쓰지 않는다. 처음 누를 때 하루 횟수를 1번 쓴다.
- 확인하지 못한 것: 로그인 상태에서 확정본으로 진단 누르기(사람 QA), 운영 함수 시간, `/tech/[id]` · 청사진 서랍의 한국어 개요 화면(같은 조각 · 같은 함수).

## PRD-NF6을 이 ADR로 고침
- PRD-NF6은 "AI를 쓰는 곳은 넷뿐(대응안 초안 · 적용 시나리오 · 분류 제안 · 위키 챗봇)"이었다. 이 ADR로 **여섯**이 된다: 넷 + 청사진 AI 점검 · 프롬프트 진단(F49, ADR 0035 · 이 ADR) + 기술 한국어 개요 번역(`ai_calls.purpose` `translate`). 끝 기준도 "여섯 곳 밖에서 Claude API 호출이 없음"이다. AI 점검은 11-21부터 있었는데 NF6에 들어가 있지 않았던 것을 같이 고쳤다(prd.md 바뀐 기록 11-23 오후).
- **같은 날 저녁 일곱으로(#230, 16:13 KST 합침):** 청사진 가이드(로그인만, 문제정의를 묻고 단계 · 기술 후보를 제안만, 넣기는 사용자가 누름, 하루 20번, "AI 가이드 · 제안", ADR 0045 · #230). 이 ADR의 공통 규칙(표시를 붙임 · 원래 값을 덮지 않음 · 자료 안 글은 지시가 아님)을 따른다: 파서가 목록 밖 기술 id · 위험 · 판에 없는 단계 · 설치 명령을 버리고, 호출은 `ai_calls`(`blueprint_guide`, 마이그레이션 `202611240500`, 운영 적용: 완료)에 남는다. prd.md 바뀐 기록 11-23 저녁.
