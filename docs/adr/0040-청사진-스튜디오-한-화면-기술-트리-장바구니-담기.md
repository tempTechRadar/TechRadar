# 0040. 청사진 스튜디오는 한 화면, 기술은 트리로, 지도에서 장바구니처럼 담는다

- 날짜: 2026-11-22
- 상태: **확정 (사용자 결정, 2026-11-22 인터뷰 두 번)**. 청사진 개편 P-12h(S1~S4)와 2차 다듬기 P-12h-2(T1~T4)는 #204로 main에 들어갔다. 지도 장바구니 U1과 청사진 다듬기 U2는 **#206(열림)** 에 있다 · **2026-11-22 밤 ADR 0042:** 왼쪽 Library · 오른쪽 고정 Inspector로 옮겼다가 사용자 점검 뒤 되돌림. 2항 아래 패널 · 4항 서랍은 그대로이고, 아래 패널 탭에 검증 · 변경 이력, 서랍에 탭(개요 · 관계 · 검증 · 이력)이 더해짐
- 관련: ADR 0035(청사진 스튜디오, 이 ADR로 바뀜), ADR 0034(판단 = 청사진으로 가는 관문), ADR 0036(공개 템플릿), ADR 0039(움직임), 불변 1 · 3 · 5, 계획 사본 `.claude/plans-share/p12h-blueprint-revamp.md` · `p12h2-blueprint-polish.md`

## 배경
사용자가 11-21에 만든 스튜디오(ADR 0035)를 써 보고 문제를 짚었다.
- 세 단계(① 단계 구축 · ② 스킬 붙이기 · ③ 결과물)가 거의 다르지 않다. 조사해 보니 단계마다 다른 것은 단계 추가 줄, 결과물 줄, 아래 패널 기본 탭 셋뿐이었다.
- 기술 목록에 우선순위와 분류가 없다.
- 같은 일을 하는 길이 여러 개다(넣기 4길, 빼기 4길, 잇기 4길). 길마다 규칙과 단추 모양이 다르다.
- 카드가 작다. 단계 5개면 이름 글자가 약 8px이고, 속성 패널이 늘 320px를 차지한다.
- 단계에 메모를 남길 자리가 없다.
- "카탈로그에서 찾기"는 로그인 사용자에게는 지도와 겹치는 지름길이다. 손님에게는 기술을 넣는 유일한 길이었다.

## 결정
1. **한 화면으로 합친다.** 단계 칸(스텝퍼)을 없앤다. 위 막대의 주 단추 **"확정 · 내보내기"** 가 결과물 창을 연다. 창 안 차례는 고칠 것 → 내보내기 → 확정 → AI 점검이다. AI 점검은 확정 id가 없으면 최근 확정 이력으로 한다(새로 고침하면 "먼저 확정해 주세요"가 뜨던 문제).
2. **아래 패널은 [기술 | 불러오기] 두 탭.** 불러오기 = 템플릿 + 내 이력 + 질문으로 틀 만들기. → 11-22 밤 ADR 0042: 왼쪽으로 옮겼다가 되돌림, 탭에 검증 · 변경 이력을 더함.
3. **기술 탭은 트리(유니티 프로젝트 창처럼).** 왼쪽 폴더 트리(키보드로 움직임), 오른쪽 카드. 묶기 1 · 2단 기준은 내 판단(기본) · 하는 일 · 세부 갈래 · 내 태그 · 프로젝트이고, 고른 기준은 이 브라우저에 저장한다. 내 판단 폴더 순서는 고정이다. DB는 바꾸지 않는다(`lib/blueprint/tech-tree.ts`).
4. **카드를 키우고, 속성 패널은 서랍으로.** 카드 폭 260~320px, 화면 맞춤 배율 0.75~1.2(단계가 많으면 줄이지 않고 끌어서 본다). 속성 패널은 캔버스 위 오른쪽 서랍이고 기본은 닫혀 있다.(→ 11-22 밤 ADR 0042: 서랍 그대로, 탭 개요 · 관계 · 검증 · 이력) 편집은 카드 위에서 한다: 앞 · 다음 · 나란히 +, 이름 두 번 누르기 · F2로 이름 바꾸기, 메모, 삭제(확인 창 없이 지우고 토스트 되돌리기). 선 위에서는 끊기와 "사이에 단계 끼우기"를 한다.
5. **단계 메모.** 단계마다 메모(200자, 앞뒤 공백 없앰, 비면 없음)를 청사진과 함께 저장하고, 카드에 두 줄로 보이며, 내보내기(프롬프트 · CLAUDE.md · 메타)에 "메모:" 줄로 넣는다. **템플릿에는 넣지 않는다**(남에게 보일 수 있어 개인 글을 싣지 않음). Mermaid 내보내기에도 넣지 않는다.
6. **지도에서 담고, 청사진은 불러오기만.** 청사진의 "카탈로그에서 찾기"를 없앤다(이름 거르기 칸은 남김).
   - **손님:** 지도 사이드 패널의 "청사진에 담기"는 이 브라우저 목록(id만, 30개까지)에 넣는다. 서버에는 아무것도 저장하지 않는다. 청사진 트리의 "지도에서 담은 기술" 폴더는 공개 칸만 읽는다.
   - **로그인(#206):** "청사진에 담기" = **적용 후보 저장**이다. DB는 그대로이고 단추는 늘 켜져 있다. 담긴 뒤에는 "담김 ✓ · 빼기 · 청사진 열기", 빼기는 관심으로 낮춘다. 관심은 이름 옆 별 토글이다. 메뉴 "청사진"에 담은 수 배지가 있고, 못 읽으면 숨긴다(불변 2).
7. **지도에서는 보류를 뺀다(#206).** 보류 단추와 이유 칸을 지도 사이드 패널에서 없앤다. 알림 상세의 판단(적용 후보 · 보류)과 기술 상세의 판단 줄은 그대로다. 그래서 화면 말 "적용 후보"는 알림 판단 쪽에 남고, 지도 · 청사진에서는 "담기"로 말한다(`STUDIO_GATE` / 알림 쪽 `BLUEPRINT_GATE`).
8. **바뀌는 것 미리보기 = 불변 1의 화면 표현.** 결과물 창의 확정 위에 "지난 확정과 달라진 것"(단계 · 이름 · 기술 · 선 · 메모를 더하고 뺀 것, `lib/blueprint/graph-diff.ts`)을 보이고, 단추는 "이대로 확정"이다. 처음이면 "처음 확정이에요", 같으면 "달라진 것이 없어요 · 같은 확정으로 남아요"(불변 3). Terraform plan에서 규칙을 빌렸다.
9. **Mermaid 내보내기.** `flowchart LR`, 따옴표 · 꺾쇠 escape, 기술은 `<br/>` 줄.
10. **같은 일은 같은 규칙으로(S4).** 작은 단추 `.btn-sm`, 글자 링크 `.bp-link`, 눌림은 먹 채움 하나, 막힌 단추는 `aria-disabled` + 누르면 이유. 말은 넣기 / 빼기 / 잇기 / 끊기 / 이름 바꾸기 / 단계 지우기로 맞춘다.

## 고민한 것
- **세 단계를 남기고 차이를 키우기:** 단계마다 할 일이 실제로 달라지지 않아, 사람이 어느 단계에 있는지만 신경 쓰게 된다.
- **트리를 지도와 같은 분류로 고정:** 사람마다 묶고 싶은 기준(판단 · 태그 · 프로젝트)이 달라 고르게 했다. 지도의 보기 기준(`lib/map/view-config.ts` DIMS) 방식을 빌렸다.
- **청사진에 찾기를 남기기:** 손님에게는 편하지만, "지도에서 고르고 청사진으로 옮긴다"(ADR 0032)와 길이 두 개가 된다. 손님도 지도에서 담게 했다.
- **메모를 템플릿에도 싣기:** 쓰는 사람에게는 유용하지만 공개 템플릿으로 개인 글이 나갈 수 있다(불변 5, ADR 0036).
- **담기를 새 상태(장바구니 표)로 만들기:** DB 변경 없이 적용 후보를 그대로 쓰는 쪽이 판단 기록(불변 1)과 설치 프롬프트 기본 목록이 한 곳에 남는다.
- 제출 뒤 목록으로 넘긴 것: 기술 트리 선행(`tech_relations`), Git 비교 화면, 자동 규칙, 확대 단계(C4), 타입 핀.

- 좁은 화면에서 속성 패널이 안 보이는 문제는 제출 뒤로 넘겼다.
- **#206이 병합되기 전 main:** 지도에서 로그인 사용자의 담기 · 별 관심 · 보류 빼기 · 메뉴 배지는 아직 없고, 청사진 말도 "적용 후보로 고르기"다.
