# 0022. 스킬 원본은 SKILL.md 머리 주소를 믿지 않는다: v1은 모두 "출처 모름"

- 날짜: 2026-11-19
- 상태: **채택** (2026-11-19, 사용자가 추천안 "전부 출처 모름"을 골랐다. 작업 `I-P-9e-skills`)

## 배경
SPEC-7.3은 스킬 폴더(`.claude/skills/<이름>/`)의 원본을 "알 수 있으면(폴더 안 README·메타의 GitHub 링크)" `skill:<원본 owner>/<repo>/<이름>`으로 묶으라고 했다.
P-9e 첫 코드는 SKILL.md 머리(`source`·`repository` 등)의 GitHub 주소를 원본으로 읽었다. 코드 검토에서 두 문제가 나왔다.

- **아무나 남의 공용 기술 줄에 끼어든다:** 머리 주소는 저장소 주인이 마음대로 적는 글이다. `source: https://github.com/anthropics/skills`만 쓰면 자기 스킬이 그 원본 스킬의 공용 기술 줄에 묶여 "쓰고 있어요" 수를 부풀리고, 등록 한 번에 아무 `skill:<누구>/<무엇>/<이름>` 카탈로그 줄을 30개까지 만들 수 있다.
- **설치 프롬프트 경로가 틀어진다:** `lib/install/from-my-tech.ts`는 `skill:` 키를 `github.com/<owner>/<repo>/.claude/skills/<이름>`으로 바꾼다. 원본 저장소는 스킬을 다른 폴더(예: `skills/pdf`)에 두는 일이 많아 그 주소가 없다.

## 정한 것
- v1은 머리 주소를 읽지 않고 **모든 스킬을 `skill:<내 owner>/<내 repo>/<이름>` + "출처 모름"**(`unknown_origin = true`)으로 둔다. SPEC-7.3의 "원본을 모름" 줄과 같다.
- 원본으로 묶는 일은 **원본 저장소에 그 스킬 폴더가 정말 있는지 확인하는 단계**가 생길 때 다시 연다(GitHub 요청이 스킬마다 하나 더 든다).

## 결과
- 좋아지는 것: 남이 공용 줄을 부풀릴 수 없다. 설치 프롬프트 경로가 늘 실제로 있는 내 저장소 폴더를 가리킨다. 코드가 줄었다(머리 읽기 삭제).
- 잃는 것: 같은 공개 스킬을 쓰는 프로젝트끼리 묶이지 않아 "쓰고 있어요"·카탈로그 공유가 스킬에는 없다.
- 남은 것: 기술 키는 소문자라(`skillKey`) 대소문자가 섞인 폴더 이름(`MySkill`)은 설치 프롬프트 경로가 맞지 않을 수 있다. 이름만 대소문자가 다른 두 폴더는 한 줄로 합쳐진다. 둘 다 이 결정 전부터 있던 키 규칙의 한계라 따로 다룬다.
