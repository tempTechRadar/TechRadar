# 0041. 현황은 "프로젝트 관리" 보드로: 위젯 캔버스, 내 프로젝트를 흡수

- 날짜: 2026-11-22
- 상태: **확정 (사용자 결정, 2026-11-22 20시 인터뷰)**. **2026-11-23 개정(ADR 0043):** 위젯 10개 → 숫자 띠 + 걸린 판 4개, 보드 전체 필터 → 띠의 기간 하나, 레포 서랍 → 레포 상세 `/projects/[id]`, F22 대응표는 ADR 0043 표로. 조각 P-12i(`feat/P-12i-project-board`, `I-P-12i-project-board`)로 만드는 중이다. 구현 결과(커밋 · 시험 숫자)는 단계가 끝나면 "결과"에 채운다
- 관련: ADR 0037(메뉴 현황 · 지도 · 청사진, 이 ADR로 바뀜), ADR 0034(숫자 요약 자리), ADR 0028(메뉴), ADR 0040(담기), 불변 2 · 4 · 5, 안내서 공통 필수 "사용자 대시보드"(PRD-F22), 계획 사본 `.claude/plans-share/p12i-project-board.md`

## 배경
- 사용자가 11-22 밤에 "현황"을 프로젝트 관리 화면으로 바꾸자고 했다. 세로로 죽 늘어놓은 양산형 대시보드가 아니라 우리 문제에 맞는 보드여야 하고, 사용자가 원하는 것을 원하는 자리에 둘 수 있어야 한다(레퍼런스: Monday).
- 우리 문제(`docs/문제정의.md`)는 "내가 무엇을 깔았는지, 그게 안전한지, 더 나은 것이 나왔는지를 한눈에 볼 수 없다"이다. 레포(프로젝트) 단위로 다섯 가지를 볼 수 있어야 한다.
  - 지금 안전한가
  - 내가 판단할 것
  - 무엇이 바뀌었나
  - 더 나은 대안
  - 옮길 준비
- 계정 메뉴의 "내 프로젝트"(`/projects`, 레포 등록 · 내 기술 표)와 현황이 같은 레포를 두 곳에서 보여 주고 있었다.
- 레포 자체 정보(설명 · 언어 · 마지막 푸시)는 저장하지 않아, 레포를 "파악"했다고 하기 어려웠다.

## 결정
1. **메뉴 "현황"을 "프로젝트"로 바꾼다**(프로젝트 · 지도 · 청사진). 화면 제목은 "프로젝트 관리"이고 주소는 `/dashboard` 그대로다(안내서 필수 대시보드 길). 휴대폰 탭 바도 같게 한다.
2. **"내 프로젝트"를 흡수한다.**
   - 계정 메뉴의 "내 프로젝트"는 뺀다. `/projects`는 거르기 · 결과 코드를 싣고 `/dashboard`로 보낸다.
   - 등록 · 다시 읽기 · 숨기기 · 이름 고치기 · 보관 · 되살리기 · 직접 추가는 보드 위젯이 맡는다.
   - `/projects/install` · `/projects/runs` · `/projects/tech/[id]`는 그대로 둔다.
   - 현황 탭(개요 | 일지 | 소식)을 없앤다. `/history`는 "기록 찾기" 전체 화면으로 남는다.
3. **위젯 캔버스.**
   - 이미 있는 React Flow(`@xyflow/react`)로 위젯을 노드로 두고, 24px 칸에 맞춘다. 새 라이브러리는 없다.
   - 편집 모드에서만 끌기 · 크기 조절 · 넣기 · 빼기가 된다. 키보드로는 화살표가 이동, Shift+화살표가 크기, Delete가 빼기다.
   - 좁은 화면(≤860)은 배치 순서대로 한 줄로 쌓는다.
4. **배치는 이 브라우저에만 저장한다**(localStorage, try/catch, DB 0). 깨진 값이면 기본 배치로 돌아가고, "기본 배치로" 단추를 둔다. 기본 배치는 발표 순서다: 숫자 → 레포 · 판단함 → 바뀐 것 · 옮기기 · 점검 → 소식 · 뜨는 대안 · 기록.
5. **위젯 10개.** 모두 이미 있는 읽기 함수를 다시 쓴다.

   | 위젯 | 하는 일 |
   |---|---|
   | 숫자 4칸 | 안내서 필수 대시보드 |
   | 판단함 | 모든 레포의 판단 대기 |
   | 레포 보드 | 레포 카드와 등급 배터리. 카드를 누르면 오른쪽 레포 서랍(내 기술 표 · 확정 청사진) |
   | 바뀐 것 | "지금 / 추이(주별)"로 바꿔 본다 |
   | 옮기기 진행 | 담은 기술 → 확정 청사진 → 내보내기 |
   | 점검한 비율 | 주요 지표 `grade_views` |
   | 소식 | |
   | 요즘 뜨는 대안 | |
   | 기록 찾기 | |
   | 레포 관리 · 내 기술 | 옛 `/projects` 목록 |

   - 위젯마다 읽는 중 · 없음 · 읽지 못함을 따로 그린다(불변 2).
   - 로그인 전에는 소식 · 뜨는 대안만 실제 값을 보인다.
6. **보드 전체 필터.** 기간 · 상태 · 프로젝트 필터를 모든 위젯에 건다(Linear 방식). 지금의 숫자 폼 주소 값을 다시 쓴다.
7. **레포 기본 정보를 조금 저장한다.** 마이그레이션 `202611232100_P-12i_project_repo_meta.sql`로 `projects`에 다섯 칸을 더한다.
   - 칸: `repo_description`(300자), `repo_language`(60자), `repo_pushed_at`, `repo_meta_at`, `repo_meta_error`(수집 오류 종류 5가지)
   - 값은 등록 · 다시 읽기 때 이미 부르는 GitHub 저장소 API 응답에서 꺼낸다. 새 외부 호출은 없다.
   - 읽기에 실패해도 예전 값을 지우지 않고(불변 4) `repo_meta_error`에 남긴다(불변 2).
   - 읽기 권한은 기존 `projects` RLS 그대로다: 본인과 관리자만 읽고 손님은 못 읽는다(불변 5).
8. **Monday에서 빌린 규칙:**
   - 편집 모드에서만 옮긴다.
   - 위젯 라이브러리로 넣고 뺀다.
   - 상태 색에는 늘 글자를 같이 쓴다.
   - 비율 막대 하나(Battery)를 쓴다.
   - 판단은 한 곳(판단함)에 모은다.

## 안내서 필수 대시보드(PRD-F22)를 채우는 방법
안내서 공통 필수 "사용자 대시보드"의 조건을 숫자 4칸 위젯과 보드 필터가 맡는다. 위젯은 뺄 수 있지만 기본 배치 맨 위에 있고, "기본 배치로"를 누르면 돌아온다.

| 안내서 조건 | 보드에서 |
|---|---|
| 보여 줄 숫자: 내 기술 수, 변경 수, 판단 대기 · 완료 수, 최근 변경 | 숫자 4칸 위젯(`summarizeDashboard`), 최근 변경은 "바뀐 것" 위젯 |
| 실제 DB 값 | 위젯이 서버 읽기 함수로 DB를 읽는다. 미리 정한 값이나 가짜 값은 없다 |
| 기간 · 상태로 거르기 | 보드 전체 필터(기간 · 상태 · 프로젝트) |
| 숫자를 누르면 목록 | 숫자 = 목록 수(기존 `summarize-dashboard` 시험 유지) |
| "데이터 없음"과 "조회 실패" 구분 | 위젯마다 없음 / 읽지 못함 따로(불변 2) |

## 고민한 것
- **지금 현황을 다듬기만:** 세로 목록은 레포가 늘수록 길어진다. 사용자는 레포 단위로 원하는 것만 원하는 자리에 두고 싶어 했다.
- **배치를 DB에 저장:** 기기가 바뀌어도 이어지지만 마이그레이션 · 권한 시험이 하나 더 는다. 제출 전에는 브라우저 저장으로 하고, 발표 노트북은 기본 배치(발표 순서)로 보인다.
- **새 그리드 라이브러리(react-grid-layout 등):** 새 라이브러리 금지(H). 청사진에서 쓰는 React Flow로 충분하다.
- **레포 정보를 더 많이(스타 · 이슈 · 기여자):** 우리 문제는 "깔린 AI 도구가 안전한가"라서, 레포를 알아보는 데 필요한 세 가지만 저장한다.

## 결과와 남은 일
- **DB:** `p12i_project_repo_meta`를 운영에 적용했다(버전 20261122120849).
  - 적용 여부는 DocsChecker가 운영 마이그레이션 목록(SELECT)으로 확인했다.
  - 적용은 Maestro가 사용자 승인으로 했다.
  - 권한 시험 `supabase/tests/project_repo_meta_p12i.sql` 8항목은 **확인함(Maestro 실행)**. 모두 기대값이었다: kept_on_error · bad_error_kind_blocked · long_description_blocked · owner_reads=1 · other_reads=0 · other_update_noop · admin_reads=1 · anon_reads=0.
- **ADR 0037을 바꾸는 곳:**
  - 메뉴 이름 "현황" → "프로젝트"
  - 현황 탭(개요 | 일지 | 소식) → 위젯
  - 계정 메뉴 "내 프로젝트" → 보드로 흡수
  - 메뉴가 셋인 것, 보드(칸반)를 녹인 것, 로그인 전 맛보기는 그대로다.
- **ADR 0034와의 관계:** 숫자 요약은 일지 맨 위가 아니라 보드의 숫자 4칸 위젯에 있다.
- **결과(구현):** PR **#208**(`feat/P-12i-project-board`, #206 위에 쌓음, 열림). 전체 시험 1,740 통과, tsc · build · precheck 통과(Maestro 전달). 사람 QA · 병합 뒤 운영 확인(레포 다시 읽기로 설명 · 언어 · 마지막 푸시가 채워지는지)은 아직이다.
- 배치가 브라우저에만 있어 다른 기기에서는 기본 배치로 보인다. DB 저장은 제출 뒤로 넘겼다.
