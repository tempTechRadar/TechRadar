# 0029. 로그인 전 지도는 RLS를 열지 않고, 서버가 공개 칸만 읽어 보여 준다

- 날짜: 2026-11-20
- 상태: **확정 (사용자 결정, 2026-11-20)**. 팀은 PR 리뷰에서 확인한다
- 관련: `docs/design.md` 6-2행·14절 ①(로그인 전 지도, "RLS는 보안 확인 뒤"), ADR 0027(로그인 뒤 지도는 전체로), ADR 0028(1차 목적), 불변 2·5, 작업 `I-P-12d-public-map`

## 배경
로그인 전에도 누구에게나 같은 카탈로그 지도를 보여 주기로 했다(design.md 14절 ①, 11-20). 시안 명세는 "`technologies`(시뮬레이터 제외) · `categories` · `tech_relations`(확정)만 `anon`에 RLS로 열고, 열기 전에 보안 확인"이라고 적었다.

확인해 보니 `technologies`에는 지도에 필요 없는 내부 칸이 있다: 등급 근거 원문(`grade_evidence`), 두께 이유(`thick_reasons`), 상태 · 갈래를 정한 주체(`status_by`, `category_set_by` = 관리자 id), 등급 규칙 버전, 순위 점수 등. RLS는 줄을 거르지 칸을 거르지 않아, 열면 열 단위 grant를 따로 관리해야 하고 공개 키만 있으면 누구나 7,848줄 전체를 직접 긁어 갈 수 있다. 다른 세션(P-12a2 작업)이 이 점을 짚었다.

## 결정
1. **`anon`의 RLS와 권한은 그대로 닫아 둔다.** 마이그레이션이 없다.
2. **서버가 대신 읽는다**: `app/page.tsx`가 로그인하지 않은 사람에게 `readGuestMapInput`(`lib/server/map-queries.ts`)을 서비스 키로 불러 지도를 그린다. 읽는 표는 공용 표 `technologies` · `categories` 둘뿐이고, 개인 표(내 기술 · 알림 · 판단 · 표시 · 프로필)는 읽지 않는다.
3. **공개 칸 = 지도가 쓰는 칸**(`TECH_COLUMNS`): id, 기술 키, 이름, 종류, 호스트, 갈래, 등급 · 등급 이유, 한 줄 소개, 저장소 주소, 라이선스(2026-11-20 추가: 지도 사이드바의 출처 줄, design.md 17절 3차. GitHub가 공개하는 값), 마지막 활동, 마지막 확인 · 수집 오류 종류, 신호, 상태, 두께, 시뮬레이터 표시, 들어온 날, 공식 표시(`is_official`, 2026-11-21 추가: 사이드 패널 "공식" 배지, 이유는 ADR 0030 10항). 내부 칸은 넣지 않고, 시험(`map-queries.test.ts`)이 칸 목록 전체를 그대로 비교해 칸이 늘면 실패한다(이 ADR과 함께 고치게). 로그인한 사람(누구나 구글로 가입 가능)이 지금 읽는 것과 같은 범위다.
4. **공개 목록에서 온 기술만 보인다**(소개 출처 `one_liner_source`가 있는 것). 저장소를 읽을 때 카탈로그에 없던 기술은 새 줄로 생기는데(`first-read.ts`, 내부 서버 주소·비공개 패키지 이름일 수 있음), 이런 줄은 남의 카탈로그와 로그인 전 지도에 나오지 않는다(코드 리뷰 지적, 불변 5). 운영 11-20 기준 7,847개 중 7,822개가 남고, 저장소에서 생긴 2개와 출처 기록이 없는 23개가 빠진다. 신호(`signals`)는 지도가 쓰는 별 수·주간 내려받기 두 값만 남기고 수집 오류 문장 등은 보내지 않는다.
5. **시뮬레이터 기술과 사라진 기술은 뺀다.** 로그인 전에는 비교군 선(`tech_relations`)도 그리지 않는다(내 기술이 없어 쓸 곳이 없음). 지도 범위는 로그인했지만 프로젝트가 없는 사람의 카탈로그 지도와 같다(최대 300개, 캔버스 지도 조각에서 늘림).
6. **요청 수**: 결과를 10분 동안 서버에 캐시한다(`unstable_cache`, 키에 공개 칸 목록을 넣어 칸이 바뀐 배포는 옛 캐시를 쓰지 않음, 실패는 캐시하지 않음). 관리자가 상태·갈래를 고치면 최대 10분 늦게 보인다. 요청이 몰려도 DB 읽기는 10분에 한 번이다. 그 밖의 요청 수 제한은 Vercel 기본값을 쓴다.
7. **보기 설정 저장**: 로그인 전에는 이 브라우저에 저장하지 않고 주소로만 나눈다(14절 저장 규칙). 로그인 뒤 계정 저장 표는 코드 동결 뒤로 미루고, 그 전에는 로그인한 사람만 브라우저에 저장한다.
8. **새 기술 화면(`/new`)도 같은 방식으로 연다**(2026-11-21 사용자 결정 "같은 메뉴 + 계정 묶기", 로그인 전에도 새 기술 열기): `readNewTechs(db, null, …)`를 서비스 키로 불러 같은 공개 칸 · 같은 공개 목록 규칙으로 7일 안 기술만, 10분 캐시. 내 표시(`tech_marks`)는 읽지 않고 관심 단추도 없다. 로그인이 필요한 다른 화면(내 레이더 · 알림 · 기록)은 열지 않고 그 자리에서 "무엇이 열리는지 + 로그인"을 보인다.

## 고민한 것
- **RLS를 `anon`에 열기(원래 명세):** DB가 직접 지키는 장점이 있지만, 열 단위 grant · 정책 · 시험이 늘고, 공개 키로 전체 목록을 직접 긁는 길이 생긴다. 운영 적용 · 되돌림도 필요하다.
- **서버 읽기(고름):** 마이그레이션이 없고, 내보내는 칸을 코드 한 곳(`TECH_COLUMNS`)과 시험이 지킨다. 대신 서비스 키를 쓰므로 그 함수가 고르는 표와 칸을 리뷰에서 꼭 본다(이 ADR이 기준).

## 결과
- `design.md` 6-2행·14절 ①의 "RLS 열기"는 이 ADR로 바뀐다.
- 보안 점검: `anon` 권한 변화 없음(마이그레이션 없음). 서비스 키 사용처가 하나 늘었다(`app/page.tsx`의 로그인 전 지도).
- **남은 문제(이번에 고치지 않음):** 로그인한 사람은 지금도 `technologies`의 모든 줄을 API로 직접 읽을 수 있다(RLS `using (true)`, m0). 저장소에서 생긴 줄도 포함된다. 화면(카탈로그)에서는 위 4항으로 막았지만, DB에서 막으려면 정책을 "공개 목록에서 왔거나 내가 쓰는 기술"로 좁히는 마이그레이션이 필요하다. 코드 동결 뒤 팀이 정한다.
