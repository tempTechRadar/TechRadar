# 0024. 배포 주소에서는 실패 시연 스위치를 켜지 않고, 진짜로 깨진 입력으로 빨간 상자를 보여 준다

- 날짜: 2026-11-19
- 상태: **제안** (차세일(Claude) 작성, 작업 `I-fail-demo-prod`. 팀이 PR 리뷰에서 정한다)

## 배경
- 과제는 "일부러 실패시킨 실행이 흐름 화면에서 빨간 상자로 보이는 것"을 **배포 주소에서** 보여 주길 요구한다(레드팀 지적 2번).
- 그런데 실패 시연(`/admin/demo` ①②⑤)은 운영에서 꺼진다. `lib/demo/demo-switch.ts`가 `VERCEL_ENV=production`이면 `ENABLE_FAIL_DEMO`와 상관없이 끈다. 테스트 로그인(`lib/env.ts`)과 같은 방식이고, 일부러 틀린 OSV 주소·저장 실패 쿠키 같은 장치가 운영 자료에 섞이지 않게 하려는 설계다(작업 `I-P-20c-fail-demo`, `docs/qa.md` "운영 실패 시연 ①②⑤ No Run(운영은 설계상 꺼짐)").
- 미리보기 배포도 꺼져 있다(ADR 0018). 그래서 지금 스위치를 켤 수 있는 곳은 **로컬뿐**이다.

## 제안
1. **실패 시연 스위치는 운영에서 계속 끈다.** 바꾸지 않는다.
2. **배포 주소에서는 "package.json만 깨진 공개 저장소"를 등록해 빨간 상자를 보여 준다.** 앱 코드는 그대로이고, 사용자가 실수로 깨진 파일을 올린 것과 똑같은 진짜 경로다. 실행 기록도 진짜다(불변 6). 이 길이 바뀌지 않게 시험 1개를 걸었다(`lib/server/first-read.test.ts` "package.json 하나만 깨진 공개 저장소…").
3. 준비물은 **사람이 한 번** 만든다: 공개 저장소 `csaeil/techradar-fail-demo`(11-19 차세일이 만듦: https://github.com/csaeil/techradar-fail-demo)를 쓰고 뿌리에 `package.json` 한 파일(`{ "dependencies": ` 처럼 일부러 끝을 자른 JSON)과 "일부러 깨 둔 시연용"이라는 README만 둔다. 공개 저장소를 새로 만드는 일이라 Claude가 하지 않았다.
4. 저장소를 만들기 전이거나 발표장 인터넷이 안 되면 **로컬 + 녹화**로 대신한다: 로컬에서 `ENABLE_FAIL_DEMO=true`로 ① 수집 오류를 누르고 흐름 화면을 녹화·캡처해 발표 자료에 넣는다. 이때는 "로컬에서 찍은 것"이라고 슬라이드에 적는다.

## 고르지 않은 것 (팀이 원하면 다시 볼 작은 코드 변경)
- **운영에서 ①만 관리자에게 열기:** `isDemoSwitchEnabled`를 버튼별로 나눠 ① 수집 오류(틀린 OSV 경로로 묻고 `fetch_osv` 실패 + `collect_error`)만 운영에서도 허용. 남는 줄은 실행·단계뿐이고 가짜 표시 자료는 만들지 않는다. 하지만 ① 실행은 `trigger=manual`이라 `/admin/runs`의 "지금 실행" 연속 실패와 출처별 연속 실패 강조(`lib/schedule/history.ts`의 `fetch_osv`)에 섞인다. 섞이지 않게 하려면 실행에 가짜 표시를 다는 칸이 필요하고 그것은 마이그레이션이다. 코드 동결(11-20 21:00) 직전이라 운영 동작을 바꾸지 않는다.
- **운영에서 스위치를 통째로 켜기:** ⑤ 저장 실패 쿠키까지 운영에 열린다. 설계 의도와 반대라 고르지 않는다.
- **미리보기 배포 한 번만 켜기:** 한도(ADR 0018)와 미리보기용 환경변수·로그인 주소 설정이 따로 필요하다.
