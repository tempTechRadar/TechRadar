# IA (화면과 메뉴)

> 상태: **초안, 팀 승인 전.** `docs/문제정의.md` 통합안(PR #16, 승인 회의 전)을 바탕으로 Claude가 먼저 그렸다. 회의 결정 D2(알파)·D6(필요 등록)에 걸린 곳은 **[D2]**, **[D6]**으로 표시했다. 팀 인터뷰(7절)로 고친 뒤 승인받는다.
> 화면 ID: `IA-n` (요구·PR·QA에서 이 ID로 부른다) · 용어: `docs/GLOSSARY.md` · 안내서 용어와의 대응: 사건 = **알림**, 사람 승인 = **판단**, 조치 = **적용 시나리오 저장 / 보류 사유 기록**, 직접 입력 = **내 프로젝트 등록**

## 1. 메뉴 구조

```
로그인 / 가입 (IA-1)  ─ [D6] 가입 질문 (IA-1b)
│
├─ 사용자 메뉴 (본인 데이터만)
│   ├─ 대시보드 (IA-5)  ← 프로젝트가 있으면 로그인 뒤 첫 화면
│   ├─ 내 프로젝트
│   │   ├─ 등록·수정 (IA-2)  ← 프로젝트가 없으면 로그인 뒤 첫 화면
│   │   └─ 내 기술 목록 (IA-3) ─ 기술 상세 (IA-4)
│   │                          └─ [D2] 목록 내보내기
│   ├─ 알림 (IA-6) ─ 알림 상세와 판단 (IA-7) ─ 적용 시나리오 (IA-8)
│   ├─ 기록 찾기 (IA-9)
│   ├─ 기술 지도 (IA-10)
│   └─ 내 실행 기록 (IA-11)
│
└─ 관리자 메뉴 (관리자만. 화면·서버·DB 모두에서 막음)
    ├─ 회원별 등록 (IA-12)
    ├─ 수집 자료 (IA-13)
    ├─ 알림과 처리 현황 (IA-14)
    ├─ 수집 실행과 오류 (IA-15)
    ├─ 흐름 화면 (IA-16)
    ├─ 분류 확인 (IA-17)
    └─ 위키 챗봇 (IA-18)
```

## 2. 안내서 화면 요건과의 대응

| 안내서 6장 IA 요건 | 우리 화면 | 안내서 필수 8가지 중 |
|---|---|---|
| 로그인 | IA-1 | 7 웹앱 |
| 직접 입력 | IA-2 내 프로젝트 등록·수정 (+ IA-3에서 읽어 낸 결과 확인) | 7 웹앱 |
| 대시보드 | IA-5 | 7 웹앱 |
| 사건 상세와 승인 | IA-6 알림 목록, IA-7 알림 상세와 판단, IA-8 적용 시나리오 | 3 사건, 4 대응 |
| 기록 찾기 | IA-9 (IA-7 안의 "비슷한 과거 판단"도 같은 기능) | 5 기록과 찾기 |
| 관리자 | IA-12 – IA-18 | 7 웹앱, 8 흐름 화면 |
| (안내서 2장) 흐름 화면은 관리자 페이지의 한 탭, 일반 사용자는 자기 실행만 | IA-16, IA-11 | 8 흐름 화면 |
| (안내서 6장) 위키 챗봇은 팀원·관리자만 | IA-18 | — |
| 우리 서비스에만 있는 것 | IA-3 내 기술 목록, IA-4 기술 상세(보안 등급), IA-10 기술 지도, IA-17 분류 확인 | 2 지켜보기의 결과를 보여 줌 |

## 3. 사용자 화면

| ID | 화면 | 보여 주는 것 | 하는 일 | 꼭 지킬 것 | 출처 |
|---|---|---|---|---|---|
| IA-1 | 로그인 / 가입 | 로그인 폼 | 가입, 로그인, 로그아웃 | 로그인은 Supabase 또는 Appwrite(무엇을 쓸지는 PRD) | 안내서 3장 |
| IA-1b | **[D6]** 가입 질문 | 어떤 작업을 할 예정인지 선택지 | 고르거나 건너뛰기 | D6에서 "v1에서 뺌"이면 이 화면은 없음 | 강사 11-17 제안 |
| IA-2 | 내 프로젝트 등록·수정 | 내 프로젝트 목록 | **공개 GitHub 저장소 주소** 등록·수정·삭제, 프로젝트 이름, 메모 | 작성자·시각 저장, 새로고침·재로그인 뒤에도 남음. 잘못된 주소·비공개 저장소는 막고 이유를 보여 줌 | 문제정의 2절, ADR 0002, 안내서 2장 |
| IA-3 | 내 기술 목록 | 저장소에서 읽어 낸 기술(`package.json`, `requirements.txt`, `CLAUDE.md`, `.mcp.json`, `.claude/skills/`), 기술마다 **보안 등급과 한 줄 이유**, 어느 파일에서 읽었는지, 마지막으로 읽은 시각 | 다시 읽기, 등급으로 거르기, 기술 누르면 IA-4, **[D2]** 목록 내보내기 | 읽기에 실패한 기술·파일은 **"수집 오류"**로 표시하고 "통과"나 "없음"으로 보이지 않음(불변 규칙 2) | 문제정의 1·2·6절 우선순위 1–2 |
| IA-4 | 기술 상세 | 보안 등급과 **쉬운 말의 이유**, 근거 링크(OSV 등), 최근 활동·라이선스, 같은 역할의 기술(연결선), 평판 요약(참고), 이 기술에 대한 내 판단 기록 | 근거 링크 열기, 판단 기록 보기 | 출처가 없으면 "찾지 못함". 평판 요약은 등급을 대신하지 않음(ADR 0003) | 문제정의 2절, 강사 11-16 |
| IA-5 | 대시보드 | **내 기술 수**, **변경 수**(기간 안에 보안 등급이 바뀌었거나 맞춘 소식이 생긴 수), **판단 대기 / 완료 수**, 최근 변경 | 기간·상태로 거르기, 숫자 누르면 해당 목록(IA-3, IA-6)으로 | 실제 DB 값. **"데이터 없음"과 "조회 실패"를 다르게** 보여 줌 | 안내서 2장 |
| IA-6 | 알림 목록 | 알림 2종류(**보안 경고**, **적용 기회**), 상태(판단 대기 / 적용 후보 / 보류), 관련된 내 기술, 생긴 시각 | 종류·상태·기간으로 거르기, 누르면 IA-7 | 같은 변경을 다시 읽어도 알림이 두 번 생기지 않음(불변 규칙 3) | 문제정의 2절 |
| IA-7 | 알림 상세와 판단 | 무엇이 바뀌었나(**이전 값 → 현재 값**, 출처, 시각), 관련된 내 기술, Claude가 만든 대응안 초안과 참고한 출처, **비슷한 과거 판단** | **적용 후보** 또는 **보류**(이유 필수) | **판단 전에는 아무것도 바뀌지 않음.** 저장에 실패하면 이전 상태를 그대로 두고 "처리 완료"로 보이지 않음(불변 규칙 1·4) | 안내서 4장 대응, 문제정의 2절 |
| IA-8 | 적용 시나리오 | 적용 후보로 판단한 뒤 Claude가 만든 비교표, 적용 단계, 위험과 되돌리는 방법, 참고한 출처 | 저장된 시나리오 보기 | 실제 설치·적용은 하지 않음(사용자가 직접). 출처 표시 | 문제정의 2·9절, 강사 11-16 비교 근거 |
| IA-9 | 기록 찾기 | 지난 판단(적용 후보 / 보류)과 이유, 관련 기술, 날짜 | 기술 이름·종류·판단 결과·기간으로 찾기 | 본인 기록만 | 안내서 5 기록과 찾기 |
| IA-10 | 기술 지도 | **내 기술을 가운데**에 두고, 같은 갈래와 같은 역할의 기술을 둘레에 | 기술 누르면 IA-4, 펼치기·접기 | 만드는 순서는 마지막(문제정의 6절 우선순위 5). 강사 피드백: 빨리 펼쳐져야 함(숫자는 PRD) | 문제정의 2절, 강사 11-16 |
| IA-11 | 내 실행 기록 | 내 저장소를 읽은 실행마다 언제, 무엇으로 시작했는지, 성공·실패, 걸린 시간, 처리 건수 | 실행 누르면 단계별 상태 | 본인 실행만. 실제 실행 기록(`runs`, `run_steps`)에서 그림(불변 규칙 6) | 안내서 2장 흐름 화면 |

## 4. 관리자 화면

일반 사용자가 주소나 API로 직접 요청해도 막는다(화면·서버·DB, 불변 규칙 5). 관리자가 무언가를 고치면 **담당자, 시각, 사유**가 남는다. **관리자도 사용자의 판단을 대신하거나 건너뛸 수 없다**(불변 규칙 1).

| ID | 화면 | 보여 주는 것 | 하는 일 | 출처 |
|---|---|---|---|---|
| IA-12 | 회원별 등록 | 회원마다 등록한 프로젝트·저장소 주소, 읽어 낸 기술 수, 마지막으로 읽은 시각 | 회원·기간으로 거르기 | 안내서 2장 |
| IA-13 | 수집 자료 | 출처별로 모은 자료(시각, 대상, 지표, 값, 바뀐 정도, 출처), 이전 값·현재 값 | 출처·기간으로 거르기 | 안내서 2·4장 |
| IA-14 | 알림과 처리 현황 | 모든 회원의 알림, 판단 상태, 처리한 사람과 시각 | 거르기. 판단 버튼은 없음 | 안내서 2장 |
| IA-15 | 수집 실행과 오류 | 수집 실행 기록(언제, 어디를, 몇 건, 성공 여부), **수집 오류와 연속 실패** | **"지금 한 번 실행"** 버튼 | 안내서 4장 실패 처리·정기 실행 |
| IA-16 | 흐름 화면 | `flow/flow.json`의 상자와 화살표, 시작 노드(예약, 지금 실행, 시뮬레이터), 상자 색(대기·실행 중·성공·실패·판단 대기), 화살표 위 건수, 실행 목록 | 시작 노드 누르면 그 길만 굵게, 상자 누르면 들어온 것·나간 것·호출 내용·오류 | 안내서 2·9장 |
| IA-17 | 분류 확인 | 지도 분류의 확신이 낮은 기술, Claude가 제안한 갈래 | 갈래 확정·고치기(담당자·시각·사유 남음) | 문제정의 2절 기술 지도 |
| IA-18 | 위키 챗봇 | 질문, 찾은 위키 쪽, 답과 출처 | 질문하기 | 안내서 6장 (일반 사용자에게는 보이지 않음) |

## 5. 모든 화면의 공통 상태

| 상태 | 보여 줄 것 | 출처 |
|---|---|---|
| 데이터 없음 | "아직 등록한 프로젝트가 없어요" 등 + 다음 할 일 버튼 | 안내서 2장 |
| 조회 실패 | "불러오지 못했어요" + 다시 시도. 데이터 없음과 다른 모양 | 안내서 2장 |
| 수집 오류 | 해당 기술·출처에 "수집 오류" 표시. "변화 없음"·"삭제됨"으로 단정하지 않음 | 불변 규칙 2 |
| 권한 없음 | 다른 사람 데이터나 관리자 주소에 들어오면 막고 안내 | 불변 규칙 5 |
| 판단 대기 | 알림·대시보드에서 눈에 띄게 | 불변 규칙 1 |

## 6. 첫 흐름 (시연에 쓰는 길)

가입·로그인(IA-1) → 공개 저장소 등록(IA-2) → 내 기술 목록과 보안 등급(IA-3) → 시뮬레이터로 내 기술에 새 취약점(IA-16) → 보안 경고 알림(IA-6) → 알림 상세에서 판단(IA-7) → 적용 시나리오 저장(IA-8) 또는 보류 사유 기록 → 대시보드 숫자가 바뀜(IA-5) → 기록 찾기에서 다시 봄(IA-9)

자세한 하루 흐름은 다음 문서 `docs/uj.md`에서 쓴다.

## 7. 팀 인터뷰로 정할 것

추천은 Claude 제안이다. 팀이 다르게 정하면 위 표를 고치고 "바뀐 기록"에 이유를 적는다.

| # | 질문 | 추천과 이유 | 정한 것 |
|---|---|---|---|
| IA-Q1 | 로그인 뒤 첫 화면 | **프로젝트가 없으면 IA-2, 있으면 IA-5.** 문제정의의 "첫 화면은 내 기술 목록"과 안내서의 대시보드를 둘 다 살림. 대시보드의 최근 변경에서 IA-3으로 한 번에 감 | |
| IA-Q2 | 한 사람이 프로젝트를 몇 개 등록하나 | **여러 개.** 대시보드 숫자는 합계, 거르기는 프로젝트별. 시연은 1개로 | |
| IA-Q3 | 등록할 때 "프로젝트 목표 한 줄"을 받을까 | **받지 않음(v1).** 적용 기회는 "같은 역할"만으로 판단. 목표 맞추기는 기준을 숫자로 적기 어려움(문제정의 11절) | |
| IA-Q4 | 읽어 낸 기술 목록을 사용자가 직접 더하거나 뺄 수 있나 | **읽기만(v1).** 강사 제안 ③의 "설치한 기능"은 저장소에서 읽은 것으로 먼저 채움. 직접 추가는 다음 버전 | |
| IA-Q5 | 기술 지도를 어디까지 보여 주나 | **내 기술 + 같은 역할의 기술 한 단계까지.** 근거가 가장 약하고 순서도 마지막이라 작게 | |
| IA-Q6 | 내 실행 기록(IA-11)을 메뉴로 둘지, IA-3 안의 탭으로 둘지 | **IA-3 안의 탭.** 메뉴가 줄고, "내 저장소를 언제 읽었나"와 같은 자리 | |
| IA-Q7 | 알림을 앱 밖(메일·메신저)으로도 보낼지 | **v1은 앱 안만.** 바깥 발송은 외부 알림 규칙(팀 CLAUDE.md 7절)과 테스트 계정 준비가 필요 | |
| IA-Q8 | 휴대폰 화면까지 맞출지 | **보는 화면(대시보드, 알림)만 휴대폰에서 깨지지 않게.** 지도·흐름 화면은 PC 기준 | |
| D2 | 알파 (회의) | ⓐ 목록 내보내기 → IA-3에 버튼 하나 | |
| D6 | 필요 등록 (회의) | v1에서 뺌 → IA-1b 없음 | |
