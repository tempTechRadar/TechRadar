# IA (화면과 메뉴)

> **승인: 2026-11-18 회의**(김영식·차세일·황재웅, 바뀐 것 없음 — 회의 중 팀원이 전달). 이후 바뀌면 "바뀐 기록"에 이유를 적는다.

> 처음 상태(11-18 승인 전에 적은 것, 지금은 위 승인 줄이 맞음): **초안, 팀 인터뷰 1차 반영(2026-11-17), 팀 승인 전.** `docs/문제정의.md` 통합안(PR #16, 승인 회의 전)을 바탕으로 Claude가 먼저 그리고, 팀원 1명과 인터뷰해 7절 질문에 답을 받았다. 회의 결정에 걸린 곳은 **[D2]**(알파), **[D6]**(필요 등록), **[D8]**(첫 화면)으로 표시했다. 회의(11-18)에서 팀 확인 후 승인받는다.
> 화면 ID: `IA-n` (요구·PR·QA에서 이 ID로 부른다) · 용어: `docs/GLOSSARY.md` · 안내서 용어와의 대응: 사건 = **변경**(공용 한 줄, 그 기술을 쓰는 사람마다 **알림**이 생김), 사람 승인 = **판단**, 조치 = **판단 저장**(적용 후보 기록 / 보류 사유 기록, ADR 0010). 적용 시나리오는 참고 자료, 직접 입력 = **내 프로젝트 등록**

## 1. 메뉴 구조

```
로그인 / 가입 (IA-1)  ─ [D6] 가입 질문 (IA-1b)
│
├─ 사용자 메뉴 (본인 데이터만)  ← 11-21 바뀜(ADR 0034): 위 메뉴는 로고 · 지도 · 청사진, 오른쪽 찾기 · 넣기 · 종 · 아바타
│   ├─ 지도 (IA-10)  ← [D8] 첫 화면. 로그인 전에도 공개 칸만으로 보임(ADR 0029). 판단 대기 · 최근 변경 칩은 11-21에 뺌(일지로). "새 기술"은 지도의 기간 칩 이름
│   │   └─ 보는 곳 줄 "지도 | 보드 | 일지"  ← 지도 화면 맨 위에서 오감. 위 메뉴 "지도"는 셋 다에서 켜짐
│   │       ├─ 보드 (`/views`, 옛 "내 레이더")  ← 4칸(쓰는 중 · 관심 · 적용 후보 · 보류), 칸 안을 갈래 또는 내 태그로 묶기. 끌어 놓기 없음(불변 1)
│   │       └─ 일지 (IA-9, `/history`, 옛 "기록 찾기")  ← 맨 위 대시보드 숫자(IA-5) → 판단 대기 알림 → 알림 · 판단 · 변경 시간순 + 찾기
│   ├─ 청사진 스튜디오 (IA-24, `/blueprint`)  ← 11-21 바뀜(ADR 0035): ① 단계 구축 → ② 스킬 붙이기 → ③ 결과물. 적용 후보만 들어감(판단 = 청사진으로 가는 관문, 관문 밖은 점선 후보 칩). 설치 프롬프트로 내보내고 실제 설치는 사람이 Claude Code에서
│   │   └─ 템플릿 갤러리 (IA-25, `/blueprint/gallery`)  ← 공개 템플릿(틀 · 조합)을 둘러보고 불러오기(ADR 0036)
│   └─ 오른쪽: 찾기 · 넣기 · ~~(11-23 찾기 · 넣기 빠짐, ADR 0043)~~ 종(알림 IA-6 ─ 알림 상세와 판단 IA-7 ─ 적용 시나리오 IA-8) · 아바타(대시보드 IA-5 · 내 프로젝트 · 설정 IA-19 · 관리자 · 로그아웃)
│       ├─ 위 메뉴 없음: 새 기술 (`/new`, 링크 없이 주소만. 같은 일은 지도의 "새 기술" 기간 칩), [D6] 추천 (IA-20, `/recommend`, 3순위. 보드 탭 줄과 취향 저장 뒤 "추천 보기"에서 들어감)
│       ├─ 휴대폰: 아래 탭 바 지도 · 보드 · 일지 · 청사진
│       └─ 내 프로젝트 등록·수정 (IA-2)  ← "프로젝트 밖(내 컴퓨터)" 칸은 자동
│           └─ 내 기술 목록 (IA-3)  ─ 기술 상세 (IA-4)
│               ├─ 탭: 내 실행 기록 (IA-11)
│               ├─ [D2] 설치 프롬프트 만들기 (IA-22)
│               └─ [D2] 내 컴퓨터 목록 가져오기 (IA-22)
│
└─ 관리자 메뉴 (관리자만. 화면·서버·DB 모두에서 막음)
    ├─ 회원과 권한 (IA-12)
    ├─ 수집 자료 (IA-13)
    ├─ 알림과 처리 현황 (IA-14)
    ├─ 수집 실행과 오류 (IA-15)
    ├─ 흐름 화면 (IA-16)
    ├─ 분류 확인 (IA-17)
    └─ 위키 챗봇 (IA-18)
```

## 2. 안내서 화면 요건과의 대응

| 안내서 6장 IA 요건 | 우리 화면 | 안내서 필수 8가지 중 |
|---|---|---|
| 로그인 | IA-1 | 7 웹앱 |
| 직접 입력 | IA-2 내 프로젝트 등록·수정 (+ IA-3에서 읽어 낸 결과 확인) | 7 웹앱 |
| 대시보드 | IA-5 (`/dashboard`, 일지 맨 위 숫자 · 아바타 메뉴로 감, ADR 0034) | 7 웹앱 |
| 사건 상세와 승인 | IA-6 알림 목록, IA-7 알림 상세와 판단, IA-8 적용 시나리오 | 3 사건, 4 대응 |
| 일지(옛 기록 찾기) | IA-9 (IA-7 안의 "비슷한 과거 판단"도 같은 기능) | 5 기록과 찾기 |
| 관리자 | IA-12 – IA-18 | 7 웹앱, 8 흐름 화면 |
| (안내서 2장) 흐름 화면은 관리자 페이지의 한 탭, 일반 사용자는 자기 실행만 | IA-16, IA-11 | 8 흐름 화면 |
| (안내서 6장) 위키 챗봇은 팀원·관리자만 | IA-18 | — |
| 우리 서비스에만 있는 것 | IA-3 내 기술 목록, IA-4 기술 상세(보안 등급), IA-10 기술 지도, IA-17 분류 확인 | 2 지켜보기의 결과를 보여 줌 |

## 4. 관리자 화면

일반 사용자가 주소나 API로 직접 요청해도 막는다(화면·서버·DB, 불변 규칙 5). 관리자가 무언가를 고치면 **담당자, 시각, 사유**가 남는다. **관리자도 남의 알림에는 판단을 대신하거나 건너뛸 수 없다**(불변 규칙 1. 본인 알림은 사용자 메뉴의 IA-7에서 판단, ADR 0016).

## 5. 모든 화면의 공통 상태

| 상태 | 보여 줄 것 | 출처 |
|---|---|---|
| 데이터 없음 | "아직 등록한 프로젝트가 없어요" 등 + 다음 할 일 버튼 | 안내서 2장 |
| 조회 실패 | "불러오지 못했어요" + 다시 시도. 데이터 없음과 다른 모양 | 안내서 2장 |
| 수집 오류 | 해당 기술·출처에 "수집 오류" 표시. "변화 없음"·"삭제됨"으로 단정하지 않음 | 불변 규칙 2 |
| 권한 없음 | 다른 사람 데이터나 관리자 주소에 들어오면 막고 안내 | 불변 규칙 5 |
| 판단 대기 | 첫 화면(지도 위 띠)·알림·대시보드에서 눈에 띄게 | 불변 규칙 1, IA-Q1-3 |

**화면 크기:** 대시보드(IA-5)와 알림(IA-6, IA-7)만 휴대폰에서 깨지지 않게 맞춘다. 나머지는 PC 기준(IA-Q8). **알림은 앱 안에서만** 보여 주고 메일·메신저로 보내지 않는다(IA-Q7).

## 6. 첫 흐름 (시연에 쓰는 길)

가입·로그인(IA-1) → 첫 화면 기술 지도, 아직 프로젝트가 없어 전체 갈래(IA-10) → 공개 저장소 등록(IA-2) → 내 기술 목록과 보안 등급, 전역으로 깐 MCP 하나를 "프로젝트 밖"에 직접 추가(IA-3) → 지도 가운데에 내 기술(IA-10) → 시뮬레이터로 내 기술에 새 취약점(IA-16) → 보안 경고 알림(IA-6) → 알림 상세에서 판단(IA-7) → 판단 저장(적용 후보 / 보류 사유, ADR 0010), 필요하면 적용 시나리오(IA-8, 참고 자료) → 대시보드 숫자가 바뀜(IA-5) → 기록 찾기에서 다시 봄(IA-9)

자세한 하루 흐름은 다음 문서 `docs/uj.md`에서 쓴다.

## 7. 팀 인터뷰로 정할 것

추천은 Claude 제안이다. 팀이 다르게 정하면 위 표를 고치고 "바뀐 기록"에 이유를 적는다.

| # | 질문 | 추천과 이유 | 정한 것 |
|---|---|---|---|
| IA-Q1 | 로그인 뒤 첫 화면 | **프로젝트가 없으면 IA-2, 있으면 IA-5.** 문제정의의 "첫 화면은 내 기술 목록"과 안내서의 대시보드를 둘 다 살림. 대시보드의 최근 변경에서 IA-3으로 한 번에 감 | **바꿈: 첫 화면은 기술 지도(IA-10)**, 프로젝트 등록·대시보드는 따로 메뉴. 프로젝트 없음 → 전체 갈래 + 등록 버튼(Q1-1), 여러 개 → 합쳐 보여 주고 거르기(Q1-2), 위에 판단 대기·최근 변경 띠(Q1-3), 만드는 순서 충돌은 회의 D8(Q1-4) (2026-11-17, 팀원 1명 답, 회의에서 팀 확인) |

| IA-Q3 | 등록할 때 "프로젝트 목표 한 줄"을 받을까 | **받지 않음(v1).** 적용 기회는 "같은 역할"만으로 판단. 목표 맞추기는 기준을 숫자로 적기 어려움(문제정의 11절) | 추천대로 (2026-11-17, 팀원 1명 답, 회의에서 팀 확인) |
