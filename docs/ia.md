# IA (화면과 메뉴)

> 상태: **초안, 팀 인터뷰 1차 반영(2026-11-17), 팀 승인 전.** `docs/문제정의.md` 통합안(PR #16, 승인 회의 전)을 바탕으로 Claude가 먼저 그리고, 팀원 1명과 인터뷰해 7절 질문에 답을 받았다. 회의 결정에 걸린 곳은 **[D2]**(알파), **[D6]**(필요 등록), **[D8]**(첫 화면)으로 표시했다. 회의(11-18)에서 팀 확인 후 승인받는다.
> 화면 ID: `IA-n` (요구·PR·QA에서 이 ID로 부른다) · 용어: `docs/GLOSSARY.md` · 안내서 용어와의 대응: 사건 = **알림**, 사람 승인 = **판단**, 조치 = **적용 시나리오 저장 / 보류 사유 기록**, 직접 입력 = **내 프로젝트 등록**

## 1. 메뉴 구조

```
로그인 / 가입 (IA-1)  ─ [D6] 가입 질문 (IA-1b)
│
├─ 사용자 메뉴 (본인 데이터만)
│   ├─ 기술 지도 (IA-10)  ← [D8] 로그인 뒤 첫 화면 (위에 판단 대기·최근 변경 숫자 띠)
│   ├─ 대시보드 (IA-5)
│   ├─ 내 프로젝트 등록·수정 (IA-2)  ← "프로젝트 밖(내 컴퓨터)" 칸은 자동
│   ├─ 내 기술 목록 (IA-3)  ─ 기술 상세 (IA-4)
│   │   ├─ 탭: 내 실행 기록 (IA-11)
│   │   └─ [D2] 노션으로 보내기
│   ├─ 알림 (IA-6) ─ 알림 상세와 판단 (IA-7) ─ 적용 시나리오 (IA-8)
│   ├─ 기록 찾기 (IA-9)
│   └─ 설정·노션 연결 (IA-19)
│
└─ 관리자 메뉴 (관리자만. 화면·서버·DB 모두에서 막음)
    ├─ 회원별 등록 (IA-12)
    ├─ 수집 자료 (IA-13)
    ├─ 알림과 처리 현황 (IA-14)
    ├─ 수집 실행과 오류 (IA-15)
    ├─ 흐름 화면 (IA-16)
    ├─ 분류 확인 (IA-17)
    └─ 위키 챗봇 (IA-18)
```

## 2. 안내서 화면 요건과의 대응

|---|---|---|
| 로그인 | IA-1 | 7 웹앱 |
| 직접 입력 | IA-2 내 프로젝트 등록·수정 (+ IA-3에서 읽어 낸 결과 확인) | 7 웹앱 |
| 대시보드 | IA-5 | 7 웹앱 |
| 사건 상세와 승인 | IA-6 알림 목록, IA-7 알림 상세와 판단, IA-8 적용 시나리오 | 3 사건, 4 대응 |
| 기록 찾기 | IA-9 (IA-7 안의 "비슷한 과거 판단"도 같은 기능) | 5 기록과 찾기 |
| 관리자 | IA-12 – IA-18 | 7 웹앱, 8 흐름 화면 |
| (안내서 2장) 흐름 화면은 관리자 페이지의 한 탭, 일반 사용자는 자기 실행만 | IA-16, IA-11 | 8 흐름 화면 |
| (안내서 6장) 위키 챗봇은 팀원·관리자만 | IA-18 | — |
| 우리 서비스에만 있는 것 | IA-3 내 기술 목록, IA-4 기술 상세(보안 등급), IA-10 기술 지도, IA-17 분류 확인 | 2 지켜보기의 결과를 보여 줌 |

| IA-5 | 대시보드 | **내 기술 수**, **변경 수**(기간 안에 보안 등급이 바뀌었거나 맞춘 소식이 생긴 수), **판단 대기 / 완료 수**, 최근 변경. 숫자는 모든 프로젝트 합계 | 기간·상태·프로젝트로 거르기, 숫자 누르면 해당 목록(IA-3, IA-6)으로 | 실제 DB 값. **"데이터 없음"과 "조회 실패"를 다르게** 보여 줌. 첫 화면은 아니지만 메뉴에 둠(안내서 요건) | 안내서 2장, IA-Q1·Q2 |
| IA-6 | 알림 목록 | 알림 2종류(**보안 경고**, **적용 기회**), 상태(판단 대기 / 적용 후보 / 보류), 관련된 내 기술, 생긴 시각 | 종류·상태·기간으로 거르기, 누르면 IA-7 | 같은 변경을 다시 읽어도 알림이 두 번 생기지 않음(불변 규칙 3) | 문제정의 2절 |
| IA-7 | 알림 상세와 판단 | 무엇이 바뀌었나(**이전 값 → 현재 값**, 출처, 시각), 관련된 내 기술, 적용 기회면 **내 기술과의 비교표**(무엇이 다른지, 항목마다 출처, `docs/uj.md` UJ-6), Claude가 만든 대응안 초안과 참고한 출처, **비슷한 과거 판단** | **적용 후보** 또는 **보류**(이유 필수) | **판단 전에는 아무것도 바뀌지 않음.** 저장에 실패하면 이전 상태를 그대로 두고 "처리 완료"로 보이지 않음(불변 규칙 1·4) | 안내서 4장 대응, 문제정의 2절 |

## 4. 관리자 화면

일반 사용자가 주소나 API로 직접 요청해도 막는다(화면·서버·DB, 불변 규칙 5). 관리자가 무언가를 고치면 **담당자, 시각, 사유**가 남는다. **관리자도 사용자의 판단을 대신하거나 건너뛸 수 없다**(불변 규칙 1).

| IA-13 | 수집 자료 | 출처별로 모은 자료(시각, 대상, 지표, 값, 바뀐 정도, 출처), 이전 값·현재 값 | 출처·기간으로 거르기 | 안내서 2·4장 |

## 5. 모든 화면의 공통 상태

| 상태 | 보여 줄 것 | 출처 |
|---|---|---|
| 데이터 없음 | "아직 등록한 프로젝트가 없어요" 등 + 다음 할 일 버튼 | 안내서 2장 |
| 조회 실패 | "불러오지 못했어요" + 다시 시도. 데이터 없음과 다른 모양 | 안내서 2장 |
| 수집 오류 | 해당 기술·출처에 "수집 오류" 표시. "변화 없음"·"삭제됨"으로 단정하지 않음 | 불변 규칙 2 |
| 권한 없음 | 다른 사람 데이터나 관리자 주소에 들어오면 막고 안내 | 불변 규칙 5 |
| 판단 대기 | 첫 화면(지도 위 띠)·알림·대시보드에서 눈에 띄게 | 불변 규칙 1, IA-Q1-3 |

**화면 크기:** 대시보드(IA-5)와 알림(IA-6, IA-7)만 휴대폰에서 깨지지 않게 맞춘다. 나머지는 PC 기준(IA-Q8). **알림은 앱 안에서만** 보여 주고 메일·메신저로 보내지 않는다(IA-Q7).

## 6. 첫 흐름 (시연에 쓰는 길)

가입·로그인(IA-1) → 첫 화면 기술 지도, 아직 프로젝트가 없어 전체 갈래(IA-10) → 공개 저장소 등록(IA-2) → 내 기술 목록과 보안 등급, 전역으로 깐 MCP 하나를 "프로젝트 밖"에 직접 추가(IA-3) → 지도 가운데에 내 기술(IA-10) → 시뮬레이터로 내 기술에 새 취약점(IA-16) → 보안 경고 알림(IA-6) → 알림 상세에서 판단(IA-7) → 적용 시나리오 저장(IA-8) 또는 보류 사유 기록 → 대시보드 숫자가 바뀜(IA-5) → 기록 찾기에서 다시 봄(IA-9)

자세한 하루 흐름은 다음 문서 `docs/uj.md`에서 쓴다.

## 7. 팀 인터뷰로 정할 것

추천은 Claude 제안이다. 팀이 다르게 정하면 위 표를 고치고 "바뀐 기록"에 이유를 적는다.

| # | 질문 | 추천과 이유 | 정한 것 |
|---|---|---|---|
| IA-Q1 | 로그인 뒤 첫 화면 | **프로젝트가 없으면 IA-2, 있으면 IA-5.** 문제정의의 "첫 화면은 내 기술 목록"과 안내서의 대시보드를 둘 다 살림. 대시보드의 최근 변경에서 IA-3으로 한 번에 감 | **바꿈: 첫 화면은 기술 지도(IA-10)**, 프로젝트 등록·대시보드는 따로 메뉴. 프로젝트 없음 → 전체 갈래 + 등록 버튼(Q1-1), 여러 개 → 합쳐 보여 주고 거르기(Q1-2), 위에 판단 대기·최근 변경 띠(Q1-3), 만드는 순서 충돌은 회의 D8(Q1-4) (2026-11-17, 팀원 1명 답, 회의에서 팀 확인) |
| IA-Q2 | 한 사람이 프로젝트를 몇 개 등록하나 | **여러 개.** 대시보드 숫자는 합계, 거르기는 프로젝트별. 시연은 1개로 | 추천대로 (2026-11-17, 팀원 1명 답, 회의에서 팀 확인) |
| IA-Q3 | 등록할 때 "프로젝트 목표 한 줄"을 받을까 | **받지 않음(v1).** 적용 기회는 "같은 역할"만으로 판단. 목표 맞추기는 기준을 숫자로 적기 어려움(문제정의 11절) | 추천대로 (2026-11-17, 팀원 1명 답, 회의에서 팀 확인) |
| IA-Q4 | 읽어 낸 기술 목록을 사용자가 직접 더하거나 뺄 수 있나 | **읽기만(v1).** 강사 제안 ③의 "설치한 기능"은 저장소에서 읽은 것으로 먼저 채움. 직접 추가는 다음 버전 | **바꿈: 직접 고칠 수 있음.** 모은 기술에서 검색해 고르기, 없으면 이름만(등급 "찾지 못함")(Q4-1). 빼면 "직접 숨김"으로 남기고 다시 읽어도 안 되살아남, 되돌리기 가능(Q4-2). 사람마다 "프로젝트 밖(내 컴퓨터)" 칸(Q4-3) (2026-11-17, 팀원 1명 답, 회의에서 팀 확인) |
| IA-Q5 | 기술 지도를 어디까지 보여 주나 | **내 기술 + 같은 역할의 기술 한 단계까지.** 근거가 가장 약하고 순서도 마지막이라 작게 | 추천대로 (2026-11-17, 팀원 1명 답, 회의에서 팀 확인) |
| IA-Q6 | 내 실행 기록(IA-11)을 메뉴로 둘지, IA-3 안의 탭으로 둘지 | **IA-3 안의 탭.** 메뉴가 줄고, "내 저장소를 언제 읽었나"와 같은 자리 | 추천대로 (2026-11-17, 팀원 1명 답, 회의에서 팀 확인) |
| IA-Q7 | 알림을 앱 밖(메일·메신저)으로도 보낼지 | **v1은 앱 안만.** 바깥 발송은 외부 알림 규칙(팀 CLAUDE.md 7절)과 테스트 계정 준비가 필요 | 추천대로 (2026-11-17, 팀원 1명 답, 회의에서 팀 확인) |
| IA-Q8 | 휴대폰 화면까지 맞출지 | **보는 화면(대시보드, 알림)만 휴대폰에서 깨지지 않게.** 지도·흐름 화면은 PC 기준 | 추천대로 (2026-11-17, 팀원 1명 답, 회의에서 팀 확인) |
| D2 | 알파 (회의) | ⓐ 목록 내보내기 = **노션 데이터베이스로 보내기** → IA-3 버튼, IA-19 | |
| D6 | 필요 등록 (회의) | v1에서 뺌 → IA-1b 없음 | |
| D8 | 첫 화면 (회의) | 기술 지도, 작게. 받아들이면 문제정의 6절의 지도 순서를 앞당김 | |
