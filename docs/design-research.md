## 2. 원문으로 확인한 것 (근거)
- **Obsidian Graph view**(obsidian.md/help/plugins/graph): 필터(Search files, Tags, Attachments, Existing files only, **Orphans**), **Groups**(검색어에 색 짝짓기), **Local graph 깊이 조절**, Display(Arrows, Text fade threshold, Node size, Link thickness, Animate), Forces(Center·Repel·Link force, Link distance).
- **Kumu Focus**(docs.kumu.io/guides/focus): 요소를 길게 눌러 이웃을 N단계까지만 보이기, `+`/`-`로 단계 조절, 숫자 키로 단계 지정, `esc`로 전체 지도 복귀.
- **WCAG 2.5.7 끌기 동작**(W3C, 레벨 AA): 끌기로 하는 기능은 끌지 않는 한 번 누르기 대안이 필요(끌기가 필수인 경우 등 예외). 지도의 방향 버튼을 예로 든다. 경로 기반 제스처(쓸기)만으로는 안 된다.
- **Thoughtworks Radar FAQ**: 링은 Adopt, Trial, Assess, **Caution**(Hold 아님). 새 블립은 다르게 표시.
- **GitHub Dependabot**: 알림 기본 정렬 "Most important"(CVSS, 범위, 취약 함수 호출 여부). 닫을 때 사유 선택과 선택 댓글, 고치지 않은 알림은 다시 열 수 있음.
- **Snyk 무시**: 사유와 추가 설명, "수정판이 나올 때까지" 또는 만료일, 누가 무시했는지 표시, 되돌리기.
- **skills.sh 감사**: Gen·Socket·Snyk 결과를 열로 나란히 보이고 **합산 점수가 없음**. 검사 전은 "Pending". (라벨 뜻 설명은 없음.)
- **Socket**: 분류 5가지(공급망·품질·유지보수·취약점·라이선스)와 심각도 4단계.

### 시안에 반영한 것 (2026-11-18)
R1·R2·R3·R4·R6, 그리고 **R7(키보드로 점 사이 이동)·R8(표 정렬·거르기)**은 `docs/wireframes/map.html`(+`map.js`)에 반영했고 실제 클릭·키보드로 점검했다(`docs/design.md` 3·9절). **이후 정합성 점검에서 R2는 "수집 오류는 등급이 아니라 덧붙는 상태"로, R4(중심 보기)는 PRD 5-1 "안 할 것"(깊이 슬라이더)과 부딪히는 것으로 밝혀져 `design.md` 10절 결정 대기로 올렸다. 지도 확장은 확정이 아니라 제안이다(`design.md` 3절 "확정과 제안").** R5는 점 카드의 "이유" 한 줄(예시 문구)만 했다. 아직 안 한 것: R9·R10(알림·판단 기록, spec 변경), R11~R14(팀 결정 뒤).

### 나중에 할 것: 획기적 후보 (보류, 2026-11-18)
"다른 서비스에 없는 것"은 **지도가 실제로 일어난 일을 그대로 보여 준다**는 점이다. 장식이 아니라 데이터에서 나오는 움직임만 쓴다(3D는 "플래시게임 같다"로 뺐다). 지금은 만들지 않고, 아래 조건이 풀린 뒤에 시안부터 만든다.

| # | 후보 | 장면 | 바탕 데이터 |
|---|---|---|---|
| 1 | **사건 파문**(추천) | 시뮬레이터가 새 취약점을 넣으면 그 점이 붉어지고 이어진 점과 "이걸 쓰는 내 프로젝트"로 파문이 번진다. 화면 밖이면 카메라가 따라간다 | `changes`, `alerts`, `runs` |
| 2 | 실행 중 지도 | 수집 중에는 도는 선이 실제 진행을 따라가며 읽힌 순서대로 점이 켜지고, 실패하면 바로 ✕ | `run_steps`, `last_checked_ok_at` |
| 3 | 시간 되감기 | 슬라이더로 그날의 지도와 그 뒤 바뀐 점 | `changes`, `observations`(등급 이력 테이블은 확인 못 함) |
| 4 | 지도에서 바로 판단 | 판단 대기 점이 숨 쉬듯 표시, 카드에서 [적용 후보]·[보류], 고리와 숫자가 바뀜 | `alerts`, `judgments` |
| 5 | 영향 반경 | 점을 고르면 그 기술을 쓰는 프로젝트가 가운데에서 선으로 이어져 빛남 | `projects`, `my_technologies` |

**3분 데모 줄기(1+4):** 평소 레이더 → 시뮬레이터 → 파문 → 알림 → 지도에서 판단 → 고리·숫자가 바뀜. UJ의 시뮬레이터 → 알림 → 판단 → 대시보드 숫자와 같다.
**시작 전에 풀려야 할 조건:** `design.md` 10절 9번(중심 보기 대 "안 할 것"), 10번(지도 확장 조각과 순서), 11번(갈래 개수), 6번("검사 전" 정의). 불변 6(연출은 실제 실행 기록에서, 시안의 버튼 시연은 "샘플 시연" 표시), P-9d "이어지는 위험"(이어지는 위험은 새 변경이 없어 파문도 없음), SQ1(v1은 판단을 고칠 수 없음), 접근성(움직임 줄이기면 카메라 이동 없이 표시만, 번쩍임 초당 3회 이하, `aria-live` polite 한 줄).

## 4. 가져오지 않는 것과 이유
- **자동 차단·자동 닫기**(Socket Block, Dependabot 자동 닫기 규칙): 불변 1(사람이 승인하기 전엔 조치 없음)과 충돌. 숨기기 전용 Ignore도 같은 이유로 안 맞고, "보류" 기록이 남아야 한다.
- **가중치를 숨긴 점수 하나**(Snyk 우선순위 점수): 우리는 근거를 보여 준다(Scorecard처럼 항목별).
- **합산 점수**: skills.sh처럼 출처별로 나란히 두는 쪽이 맞다.
- **Obsidian 힘 설정 슬라이더**, Gephi·Cosmograph 같은 분석 도구: 일반 사용자 화면에는 과하다.
- **군집 노드(Kumu Clustering)**: 우리는 갈래(사분면)로 이미 나눈다.
- **WebGL**: 문헌은 노드 수백 개부터 느려진다고 하나 요소 수 기준이고(도우미 보고), 우리 시안은 점 700개에서 메인 스레드 4~7%(25fps로 제한된 브라우저, 실측)였다. 점 상한(1200)을 올릴 때 다시 잰다.

## 5. 팀 결정이 필요한 것
1. R10: 보류에 "다시 열릴 조건"을 넣을지(spec·ADR 0010 변경).
2. R11: 신규·변경 표시 모양, 등급 표시 기호(design.md 10절 3번과 묶음).
3. R14: 내용 해시 비교 알림을 사건 기준(spec)에 넣을지.
4. R1·R3·R4를 IA-10 요구로 올릴지(지금 PRD-F23은 "프로젝트로 거르기", "검색", "갈래 접기"까지).

## 6. 한계
