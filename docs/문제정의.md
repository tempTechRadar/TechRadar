## 1. 문제 한 문장

**AI 코딩 도구로 직접 무언가를 만드는 사람**(v1 대표: 바이브코딩 부트캠프 수강생)은 스킬·MCP·플러그인을 소식(쇼츠·유튜브)이나 그때그때의 필요로 하나씩 깔다 보니, **내가 무엇을 깔았는지, 그게 안전한지, 더 나은 것이 나왔는지를 한눈에 볼 수 없다.** 그래서 유명세만 보고 검증 안 된 도구를 쓰고, 컴퓨터를 바꿀 때는 쌓은 세팅을 옮기지 못해 처음부터 다시 쌓는다.
지금은 휴대폰 캡처, "생각나면 다시 보기", "유명한가"·사례 확인으로 버틴다.

| 요소 | 내용 | 근거 | 확인 정도 |
|---|---|---|---|
| 누가 | AI 코딩 도구로 직접 만드는 사람. v1은 부트캠프 수강생(초심자 포함) | [그룹1], [대표1] | 사람 인터뷰 |
| 언제 | 새 도구를 깔 때(소식을 봤거나 막혔을 때), 그리고 **컴퓨터를 바꿀 때**(과정 종료 → 노트북 초기화·반납) | [대표1] Q1·Q3, [그룹1 P1] | 사람 인터뷰. 컴퓨터를 바꾸는 장면은 아직 일어나기 전 |
| 못 하는 것 | 깐 것의 목록이 없다("중구난방 다 깔려 있다"). 안전한지는 유명세로만 판단한다 | [그룹1 P1], [대표1] Q8 | 사람 인터뷰 (각 1–2명) |
| 잃는 것 | 쌓은 세팅(처음부터 다시 쌓음), 안전(검증 안 된 도구 사용). 손해 크기는 모름 | [그룹1 P3, 추정], P1–P5 | 당사자 말 + 공개 자료 |
| 지금 방법 | 캡처해 두고 생각나면 다시 봄, 사례·유명세 확인, 막히면 MCP·API를 직접 검색 | [대표1] | 사람 인터뷰 (1명) |
| 사람이 승인할 것 | 알림마다 **적용 후보 / 보류** 판단. 판단 전에는 아무것도 바꾸지 않는다 | 불변 규칙 1, ADR 0003 | 설계 |

## 2. 서비스가 하는 일

```
공개 저장소 등록 → 내 기술 목록 만들기 → 보안 점검(등급 + 쉬운 이유) → 기술 지도에 내 기술 표시
→ 기술 소식 수집 → 내 기술 목록과 맞춰 보기 → 알림 → 사용자 판단(적용 후보 / 보류) → 적용 시나리오 또는 보류 사유 기록
```

| 단계 | v1에서 정한 것 |
|---|---|
| 내 프로젝트 | **공개 GitHub 저장소 주소만** 등록. `package.json`, `requirements.txt`, `CLAUDE.md`, `.mcp.json`, `.claude/skills/`를 읽어 **내 기술 목록**을 만든다 (ADR 0002). 첫 화면 |
| 보안 점검 | 코드 규칙으로 **통과 / 주의 / 위험**: 라이선스, 최근 활동, 알려진 취약점, 스킬·MCP 코드의 위험 패턴. 등급마다 **이유를 쉬운 말로** 붙인다(사용자가 지금은 유명세로 판단하므로). 커뮤니티 평판 요약은 참고만, 보안 사고 제보는 "주의" (ADR 0003) |
| 기술 지도 | 깊이 제한 없는 분류 나무 + 갈래를 가로지르는 연결선(대체 · 함께 씀 · 의존 · 같은 역할). **"내 기술이 어디에 있고 무엇과 같은 역할인가"를 먼저** 보여 주고, 생태계 전체는 그 둘레로 펼친다. 분류는 규칙 먼저, 애매하면 Claude API 제안, 확신 낮으면 관리자 확인 |
| 지켜볼 분야 | AI 코딩 도구 생태계: LLM 모델, Claude Code 확장(스킬·MCP·플러그인·훅), 하네스 패턴, 개발 도구 (ADR 0002) |
| 소식 출처 | 소식: GitHub 릴리스 피드, HF 블로그, OpenAI 뉴스, GeekNews / 인기: GitHub 검색, HF 인기 순위, HN 점수 / 레지스트리: 공식 MCP 레지스트리 / 보안: OSV, deps.dev, GitHub Advisories. 2순위: Anthropic 뉴스(크롤링). 전체 후보는 `docs/data-sources.md` |
| 알림 (2종류) | **보안 경고:** 내 기술 목록의 기술이 "위험"으로 바뀜 / **적용 기회:** 새 기술이 내 기술과 같은 역할이거나 프로젝트 목표와 맞음. 둘 다 바깥 변화로 생긴다 |
| 사용자 판단 | **적용 후보** → Claude API가 근거와 함께 적용 시나리오(비교표, 적용 단계, 위험과 되돌리기) 생성·저장 / **보류** → 이유 기록, 비슷한 기술이 나오면 과거 판단을 함께 보여 줌 |
| 규칙 [팀원] | 모든 추천·비교에 출처 링크. 출처가 없으면 "찾지 못함" (v5) |
| 도구 정보 (후보) | 무료/유료 표시(MCP 없이 유료 API뿐인지) — [대표1] |

**Claude에게 "찾아봐"라고 시키기와 다른 점:** 묻지 않아도 내 기술에 맞는 변화가 생기면 먼저 알린다 / 보안 등급과 이유가 있다 / 내 기술 목록과 판단 기록이 쌓인다. (팀 밖 인터뷰에서 Q5를 묻지 못해 아직 확인 전)

## 3. 어떻게 여기에 왔나

### 검토한 가설 3개
| 가설 | 한 줄 | 출처 |
|---|---|---|
| A 소식 지켜보기 | 매일 쏟아지는 소식 가운데 무엇이 내 프로젝트에 필요하고 안전한지 판단할 기준과 큰 그림이 없어, 검증 안 된 도구를 깔거나 필요한 것을 늦게 안다 | [우리] 2026-11-16 승인 |
| B 필요 → 검색·추천 | 비전공 초심자가 막히거나 결과물이 마음에 안 들 때 "분명 쓸 수 있는 기능이 있을 텐데" 이름도 위치도 몰라 검색에 시간을 쓰거나 포기한다. 필요를 문장으로 등록하고, ⓐ 새 도구 ⓑ 몰랐던 기존 도구가 맞으면 알린다 | [팀원] v5 §1–5, 인터뷰 A |
| C 합친 안 | 공개 저장소 + 필요를 함께 등록하고, 보안 점검을 통과한 기술이 맞으면 알린다 | ADR 0005 |

### 인터뷰 판정 (2026-11-17)
**판정 규칙:** 팀 밖 사람 **2명 이상**에게서 같은 쪽 장면이 나오면 그쪽을 중심으로 C를 고친다. 팀원 본인(인터뷰 A)과 AI 인터뷰는 세지 않는다.
**판정을 약하게 만드는 것:** ① 그룹1은 **전사 끝부분만** 있어 Q1–Q14·M1–M4 답이 없다. ② 그룹1 발화자는 **말투로 추정**했다(진행자 확인 전). ③ 초심자 1:1이 없어 초심자 근거는 그룹1뿐이다. ④ 대표1 전사에 "일부러 삐딱하게 답변"이 있다. ⑤ 대표1은 숙련자이고 인터뷰 전에 우리 주제를 알고 있었다.

| 장면 | 가리키는 쪽 | 나온 사람 (팀 밖) | 인원 |
|---|---|---|---|
| 작업하다 막혀서 도구를 찾았다 | B | [대표1] 안 풀리면 MCP·API를 찾음(스스로 해결) | 1 |
| 몰라서 포기했다 / "그때 알았으면" | B | 없음. [대표1] "먼저 검색해서 있는 줄 모른 경우는 별로 없다" | **0** |
| 소식을 보고 깔았다 | A | [대표1] 쇼츠·유튜브 → 휴대폰 캡처 → 사례·유명세 보고 씀 | 1 |
| 깐 뒤 문제가 생겼다 | A | [그룹1 P1] "중구난방 다 깔려 있다 → 큰일 났다"(무슨 문제인지는 전사에 없음) | 1 (약함) |
| 저장해 두고 다시 못 찾는다 | A | [대표1] 캡처해 두고 "생각나면 다시 봄"(못 찾은 장면은 없음) | 0 (신호만) |
| 보안은 신경 안 쓴다 | 보안 점검 비중 | [대표1] 캡처 당시 신경 안 씀, 확인은 유명세·사례 | 1 |
| 깐 것을 정리하지 못했다 / 정리하려 한다 | 지도 (내 기술 목록) | [그룹1 P1] 정리해 둔 것 없음, 노트북 반납 전에 정리해 옮길 계획 / [그룹1 P3, 추정] "막막해서 제로부터 시작할 생각" | **2 (추정)** |
| "필요한 것 하나만" / 정리를 그만둠 | 지도 반대 | P3의 "제로부터"는 정리 대신 버리기로도 읽힘. [대표1]은 목적을 먼저 정하고 그것만 찾음 | 애매 |
| "Claude에게 시키면 충분" / "정해 주는 사람이 있어 충분" | 반대 | Q5·Q12를 묻지 못함 | 모름 |

**결과:**
- **2명 이상 같은 쪽:** 지도(내 기술 목록) 2명, A 2명(둘 다 약함). **B의 핵심 장면 0명.**
- **v5 중단 기준 점검:** "구체 사례 2명 미만 → 사용자 그룹·문제 재정의"에 B가 걸린다 → B를 중심에서 내린다. "팀 밖 확인된 사람 3명 미만 → 범위 확대"는 3명(대표1, P1, P3 추정)이라 걸리지 않지만 P3는 추정이다. "새 기능 10개 중 쓸 것 평균 1개 미만", "출처 2곳 중 하나라도 읽기·약관 불가"는 인터뷰로 판정하는 기준이 아니라 이번엔 점검하지 않았다.
- **지도 수요는 "생태계 전체"가 아니라 "내 기술 목록"에서 나왔다.** 그래서 C에 이미 있던 공개 저장소 등록을 첫 화면으로 올리고, 지도는 내 기술을 중심에 둔다(1절·2절). 강사 11-17 제안 ③ "설치한 기능의 새 버전까지 추적"과 같은 방향이다.
- **B의 필요 등록은 보조로 내린다.** 가입 때 묻는 질문(강사 11-17 제안 ①) 정도로 두거나 v1에서 뺀다. 팀 밖 근거가 생기면 다시 올린다.
- **B의 ⓑ "몰랐던 기존 도구 발견"**은 바깥 변화가 아니라서 사건으로 쓰지 않는다(아래 6질문 5번).

| 채점 | 알림이 맞았는지(맞힘·놓침·잘못 울림) | "필요 → 맞는 도구" 정답표 (v5 §7) | 필요 등록을 보조로 내리면 알림 채점이 주 |

| 구분 | 사람 | 이번에 보는 이유 | 인터뷰에서 본 것 |
|---|---|---|---|
| 대상 | AI 코딩 도구로 직접 개발하는 사람 | 공통으로 쓰는 것이 AI 코딩 도구 생태계 | — |

## 5. 놓치면 잃는 것

- **쌓은 세팅:** 깐 것의 목록이 없어 컴퓨터를 바꿀 때 옮기지 못하고 처음부터 다시 쌓는다 ([그룹1], 당사자 말, 앞으로의 계획이라 크기는 모름)
- **안전:** 유명세·사례만 보고 깐 스킬·MCP가 비밀값 유출이나 의도치 않은 명령 실행으로 이어질 수 있다 ([대표1] 확인 방식 + P1–P5 실제 사례)
- **시간·기회:** 내 기술보다 나은 것이 나와도 모르고 지나간다 (가설. 팀 밖 인터뷰에서는 나오지 않음)
- **결과물 포기 [팀원]:** 있는 줄 몰라서 원하는 결과물을 만들지 못하고 끝냄 (인터뷰 A, 팀원 본인 → 힌트. 팀 밖 사람 인터뷰에서는 나오지 않음)

## 7. 잴 숫자

- **주 숫자 (제안, 팀 승인 때 확정):** 내 기술 목록 가운데 **보안 등급과 이유를 확인한 기술의 비율.** 지금 값은 [대표1] 기준 "확인 안 함(유명세만)". 앱에서는 등록한 저장소의 기술 수 대비 등급을 열어 본 수로 잰다.
- **보조 숫자:** 알림 받은 시각부터 판단(적용 후보 / 보류)까지 걸린 시간. 원래 주 숫자였으나 인터뷰에서 지금 값을 얻지 못했다([대표1]: 필요하면 "바로", 아니면 "생각나면 다시").
- **보조 숫자:** 설치 전에 보안을 확인한 비율.

## 8. 강사 피드백

사용자 인터뷰 근거가 아니라 **평가자 요구·제안**으로 읽는다. 날짜마다 따로 적고, 승인된 결정과 섞지 않는다.

### 2026-11-16 15:10 · 주제 컨펌

주제·페인포인트·사용할 API를 설명하고 **주제 확정 허가**를 받았다. 아래는 그때 들은 말을 팀원이 옮겨 적은 것(당사자 말, 녹음 아님, 2026-11-17 기록)이다.

| 강사 말 | 이 문서에서 닿는 곳 | 아직 정할 것 |
|---|---|---|
| 기술을 누적해서 보여 주는 데서 그치면 안 된다 | 판단(적용 후보 / 보류), 내 기술 중심 지도. v5가 접은 "뉴스형"과 같은 경계 | 지도에 "쌓인 것"이 아니라 "판단 근거"가 보이는 화면 구성 → IA |

| 비슷한 기능의 기존 기술과 비교해 우위를 따질 근거를 제시해야 한다 | 근거 표 "비슷한 도구 중 고르기가 어렵다"(Q10), 적용 시나리오의 비교표 | 비교 기준(관리 상태, 보안 등급, 같은 역할, 인기, 무료/유료)을 무엇으로 할지 → PRD |
