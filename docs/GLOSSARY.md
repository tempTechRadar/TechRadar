# TechRadar

AI 코딩 도구 생태계의 새 기술 소식을 보안으로 거르고, 기술 지도에 배치하고, 사용자가 자기 프로젝트에 적용할지 판단하도록 돕는 서비스의 용어집.

## 기술과 지도

**기술**:
지도에 노드 하나로 올라가는 것. LLM 모델, 스킬, MCP 서버, 플러그인, 훅, 하네스 패턴, 개발 도구가 모두 기술이다.
_Avoid_: 툴, 아이템, 항목

**기술 소식**:
기술이 새로 나왔거나 바뀌었다는 바깥 출처의 글 한 건(릴리스, 블로그 글, 인기 급상승 등).
_Avoid_: 뉴스, 피드, 이벤트

**기술 지도**:
기술을 갈래와 연결선으로 엮어 큰 그림을 보여 주는 화면.
_Avoid_: 그래프, 맵, 마인드맵(전체를 부를 때)

**갈래**:
기술을 묶는 분류 나무의 가지. 깊이에 제한이 없다.
_Avoid_: 카테고리, 폴더, 태그

**연결선**:
갈래를 가로질러 두 기술의 관계(대체 · 함께 씀 · 의존 · 같은 역할)를 나타내는 선.
_Avoid_: 엣지, 링크

## 판단

**보안 등급**:
보안 점검 결과로 기술에 붙는 통과 / 주의 / 위험 세 단계.
_Avoid_: 안전도, 점수

**평판 요약**:
커뮤니티 리뷰를 모아 만든 긍정 / 섞임 / 부정 요약과 대표 의견. 참고 정보이며 보안 등급을 대신하지 않는다.
_Avoid_: 리뷰 점수, 평점

**내 프로젝트**:
사용자가 공개 GitHub 저장소 주소로 등록한 프로젝트와, 거기서 읽어 낸 기술 목록.
_Avoid_: 레포, 워크스페이스

**필요**:
사용자가 작업하다 막혔거나 포기한 일을 한 문장으로 등록한 것. 예: "업무 흐름을 마인드맵으로 보고 싶은데 방법을 모르겠다". (가설 B·합친 안 C, 팀 합의 전)
_Avoid_: 니즈, 요구사항(PRD 요구와 헷갈림), 불만

**발견**:
원래 있었지만 사용자가 몰랐던 기술이 그 사용자의 필요에 맞는다고 처음 찾아낸 것. 새로 나온 기술과 구분한다. (가설 B의 알림 ⓑ, 팀 합의 전)
_Avoid_: 추천, 신규

**알림**:
사용자에게 판단을 요청하는 한 건. 적용 기회와 보안 경고 두 종류가 있다.
_Avoid_: 사건, 인시던트, 노티

**적용 기회**:
새 기술이 내 프로젝트의 기술과 같은 역할이거나 프로젝트 목표와 맞아 생기는 알림.
_Avoid_: 추천

**보안 경고**:
내 프로젝트가 쓰는 기술의 보안 등급이 위험으로 바뀌어 생기는 알림.
_Avoid_: 취약점 알림

**판단**:
알림에 대해 사용자가 내리는 적용 후보 또는 보류 결정. 판단 전에는 아무것도 바뀌지 않는다.
_Avoid_: 승인, 결재

**적용 시나리오**:
적용 후보로 판단한 기술을 내 프로젝트에 넣는 방법. 비교표, 적용 단계, 위험과 되돌리는 방법이 들어간다.
_Avoid_: 가이드, 추천안

**판단 기록**:
판단과 그 이유를 남긴 것. 비슷한 기술이 나오면 근거로 다시 보여 준다.
_Avoid_: 히스토리, 로그
