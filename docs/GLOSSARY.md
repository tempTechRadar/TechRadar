# TechRadar

내가 깐 AI 코딩 도구를 **지키고(보안 등급·경고), 고르고(판단), 옮기는(설치 프롬프트)** 서비스의 용어집. (머리말 2026-11-17 고침. 처음엔 "새 기술 소식을 보안으로 거르고 지도에 배치")

## 기술과 지도

**기술**:
지도에 노드 하나로 올라가는 것. LLM 모델, 스킬, MCP 서버, 플러그인, 훅, 하네스 패턴, 개발 도구가 모두 기술이다. (v1 카탈로그 종류: MCP·스킬·플러그인·SDK·모델·연동 서비스·개념. 훅은 다음 버전, 2026-11-17)
_Avoid_: 툴, 아이템, 항목

**기술 소식**:
기술이 새로 나왔거나 바뀌었다는 바깥 출처의 글 한 건(릴리스, 블로그 글, 인기 급상승 등).
_Avoid_: 뉴스, 피드, 이벤트

**기술 지도**:
기술을 갈래와 연결선으로 엮어 큰 그림을 보여 주는 화면.
_Avoid_: 그래프, 맵, 마인드맵(전체를 부를 때)

**갈래**:
기술을 "하는 일"로 묶는 분류 나무의 가지. v1은 2단계(큰 갈래 > 작은 갈래)다. 종류(MCP·스킬…)나 쓰는 곳(Claude Code…)으로 나누지 않는다. (2026-11-17 바뀜, 처음엔 깊이 제한 없음. ADR 0008)
_Avoid_: 카테고리, 폴더, 태그

**연결선**:
갈래를 가로질러 두 기술의 관계(대체 · 함께 씀 · 의존 · 같은 역할)를 나타내는 선. (v1은 **같은 역할** 하나만 쓴다. 나머지 종류는 다음 버전, 2026-11-17)
_Avoid_: 엣지, 링크

## 판단

**보안 등급**:
보안 점검 결과로 기술에 붙는 통과 / 주의 / 위험 세 단계.
_Avoid_: 안전도, 점수

**평판 요약**:
커뮤니티 리뷰를 모아 만든 긍정 / 섞임 / 부정 요약과 대표 의견. 참고 정보이며 보안 등급을 대신하지 않는다. **v1에서는 하지 않는다**(prd 5-2, ADR 0003 개정 2026-11-18).
_Avoid_: 리뷰 점수, 평점

**내 프로젝트**:
사용자가 공개 GitHub 저장소 주소로 등록한 프로젝트와, 거기서 읽어 낸 기술 목록.
_Avoid_: 레포, 워크스페이스

**내 기술 목록**:
내 프로젝트에서 읽어 낸 기술과 사용자가 직접 더한 기술을 합친, 사용자가 깔아 쓰는 기술의 목록. 인터뷰에서 "깐 것"이라고 부른 것. 기술마다 출처(저장소에서 읽음 / 직접 추가 / 직접 숨김)를 단다. 첫 화면은 기술 지도로 바뀌었다(`docs/ia.md` IA-Q1, 회의 D8에서 정함). (2026-11-17, 11-18 승인)
_Avoid_: 설치 목록, 도구함, 내 도구

**직접 추가**:
사용자가 내 기술 목록에 손으로 더한 기술. 모은 기술에서 골랐으면 보안 등급과 지도 연결이 붙고, 이름만 썼으면 등급은 "찾지 못함", 지도에는 관리자 분류 확인 뒤에 올라간다. (2026-11-17 IA 인터뷰)
_Avoid_: 수동 등록, 커스텀

**직접 숨김**:
저장소에서 읽은 기술을 사용자가 목록에서 뺀 상태. 지우지 않고 남겨 두어 다시 읽어도 되살아나지 않고, 되돌릴 수 있다. (2026-11-17 IA 인터뷰)
_Avoid_: 삭제, 제외

**프로젝트 밖(내 컴퓨터)**:
저장소에 없는 기술(전역으로 깐 MCP·스킬 등)을 담는 칸. 사람마다 하나씩 자동으로 생기고, 내 프로젝트처럼 다룬다. (2026-11-17 IA 인터뷰, 그룹1 인터뷰 근거)
_Avoid_: 기타, 전역 프로젝트

**목록 내보내기**:
내 기술 목록을 다른 컴퓨터로 들고 갈 수 있게 밖으로 내보내는 것. 설치는 하지 않는다. 알파 후보 ⓐ. v1에서는 **설치 프롬프트**로 한다(ADR 0009). 노션으로 보내기는 다음 버전 (2026-11-17, 11-18 회의 D2에서 정함)
_Avoid_: 이사, 세팅 옮기기(대신 설치로 들림), 백업

**노션으로 보내기** (다음 버전):
사용자가 버튼을 누르고 미리보기를 확인한 뒤, 내 기술 목록(숨긴 기술 제외)을 자기 노션 데이터베이스에 한 방향으로 쓰는 것. 기술마다 같은 행을 고쳐 두 번 생기지 않는다. (ADR 0007)
_Avoid_: 노션 동기화(양방향으로 들림), 자동 백업

**노션 연결** (다음 버전):
사용자의 노션 계정과 이 서비스를 이어 노션으로 보내기를 할 수 있게 한 상태. 노션으로 로그인하면 바로 생기고, 구글로 가입한 사용자는 설정에서 만든다. 끊으면 토큰을 지운다. (ADR 0007)
_Avoid_: 노션 로그인(로그인 방법과 헷갈림), 연동 키

**알파**:
안내서 필수 기능 외에 우리 사용자에게 도움이 되는 기능 하나. v1 알파는 **설치 프롬프트 + 내 컴퓨터 목록 가져오기**(회의 D2, ADR 0009). 처음 후보는 `docs/문제정의.md` 6절

**필요**:
사용자가 작업하다 막혔거나 포기한 일을 한 문장으로 등록한 것. 예: "업무 흐름을 마인드맵으로 보고 싶은데 방법을 모르겠다". (접은 가설 B·합친 안 C의 용어. 지금 서비스에서는 쓰지 않는다)
_Avoid_: 니즈, 요구사항(PRD 요구와 헷갈림), 불만

**발견**:
원래 있었지만 사용자가 몰랐던 기술이 그 사용자의 필요에 맞는다고 처음 찾아낸 것. 새로 나온 기술과 구분한다. (접은 가설 B의 알림 ⓑ. 지금 서비스에서는 쓰지 않는다)
_Avoid_: 추천, 신규

**알림**:
사용자에게 판단을 요청하는 한 건. 적용 기회와 보안 경고 두 종류가 있다.
_Avoid_: 사건, 인시던트, 노티

**적용 기회**:
새 기술이 내 프로젝트의 기술과 같은 역할이라 생기는 알림. (프로젝트 목표와 맞추기는 v1에서 뺌, `docs/ia.md` IA-Q3)
_Avoid_: 추천

**보안 경고**:
내 프로젝트가 쓰는 기술의 보안 등급이 위험으로 바뀌어 생기는 알림.
_Avoid_: 취약점 알림

**판단**:
알림에 대해 사용자가 내리는 적용 후보 또는 보류 결정. 판단 전에는 아무것도 바뀌지 않는다.
_Avoid_: 승인, 결재, 도구함 추가 (팀원 v5의 "내 도구함에 추가할까요?"와 같은 자리. 판정 후 하나로 통일)

**적용 후보**:
판단의 한 가지. 적용 기회 알림에서는 "그 기술을 써 볼 후보", 보안 경고에서는 "고친 버전으로 올리기"다(고친 버전 번호를 함께 저장). 적용 후보가 된 기술은 설치 프롬프트 기본 목록에 들어가고, 보안 경고에서 고른 것은 고친 버전으로 고정된다. 위험한 버전은 적용 후보가 될 수 없다. (ADR 0010·0012, 2026-11-18)
_Avoid_: 승인, 채택, 설치(우리는 설치하지 않는다)

**보류**:
판단의 다른 한 가지. 지금은 쓰지 않거나 올리지 않겠다는 결정과 그 이유(5자 이상). 설치 프롬프트 기본 목록에서 빠진다. (SPEC-4.1)
_Avoid_: 거절, 무시, 삭제

**조치**:
안내서의 "조치"에 해당하는 일. 우리 서비스에서는 **판단 저장**(적용 후보 기록 / 보류 사유 기록)이다. 우리는 사용자 대신 설치하거나 바꾸지 않는다. (ADR 0010)
_Avoid_: 실행, 적용(대신 바꿔 주는 것처럼 들림)

**별명**:
가입 때 정하는 이름. "쓰고 있어요"에 보이는 유일한 사람 정보다. 구글 이름·이메일은 보이지 않는다. (회의 D11, ADR 0009)
_Avoid_: 이름, 실명

**시연 계정**:
발표와 시뮬레이터용으로 만든 계정. 시뮬레이터 알림은 이 계정에만 간다. (SPEC-3.5)
_Avoid_: 테스트 계정(개발용 이메일 로그인 계정과 헷갈림)

**적용 시나리오**:
그 기술을 내 프로젝트에 넣는 방법을 Claude가 쓴 **참고 자료**. 비교표, 적용 단계, 위험과 되돌리는 방법이 들어간다. 요청할 때만, 판단 전후 언제든 만든다. 조치가 아니다(조치는 판단 저장, ADR 0010).
_Avoid_: 가이드, 추천안

**판단 기록**:
판단과 그 이유를 남긴 것. 비슷한 기술이 나오면 근거로 다시 보여 준다.
_Avoid_: 히스토리, 로그

**기술 키**:
기술의 신분증. 생태계와 이름으로 정한다(`npm:…`, `pypi:…`, `github:owner/repo`, `mcp:…`, `hf:…`, `skill:owner/repo/이름`). 이름이 비슷한지로 같은 기술을 가리지 않는다. (ADR 0008)
_Avoid_: 기술 이름(같은 이름이 여럿일 수 있음), 별칭

**변경**:
바깥에서 생긴 변화 한 건(예: 보안 등급 통과 → 위험). 모두가 같이 쓰는 한 줄이고, 그 기술을 쓰는 사람마다 알림이 하나씩 생긴다. (`docs/데이터설계.md`)
_Avoid_: 사건(알림과 헷갈림), 이벤트

**인기 신호**:
기술이 얼마나 주목받는지 보여 주는 숫자. 주간 다운로드(npm·PyPI), 스킬은 skills.sh 설치 수, GitHub 별과 7일 증가, HN 점수, HF 순위. 갈래 안 점수(두껍게 할지)와 적용 기회의 "상위 절반" 조건에 쓰고, 등급을 대신하지 않는다. (2026-11-17)
_Avoid_: 평판(댓글 요약과 헷갈림), 순위

**취향**:
가입할 때 고른 만드는 것·쓰는 도구·관심 분야. 추천에만 쓰고 관리자는 볼 수 없다. (3순위, 회의 D6)
_Avoid_: 필요(접은 후보 B의 "막힌 일 한 문장"과 다름), 프로필

**추천**:
취향과 인기 신호로 고른, 아직 내 기술이 아닌 기술. 알림이 아니고 판단을 요구하지 않는다. 반응은 관심 있음 / 없음뿐이다. (3순위, 회의 D6)
_Avoid_: 적용 기회(내 기술과 같은 역할일 때의 알림), 발견

**외톨이**:
지도에서 같은 역할 관계가 하나도 없는 내 기술. 대안을 모르는 기술이 한눈에 보인다. (IVGraph 참고, 3순위)
_Avoid_: 고아 노드

**얇은 기술 / 두꺼운 기술**:
카탈로그에 얼마나 깊게 모으는지. 얇은 기술은 이름·키·한 줄 설명·출처만 있고, 두꺼운 기술은 보안 등급·인기 신호·비교·정기 확인까지 한다. 사용자 중 한 명 이상이 쓰는 기술, 그와 같은 역할, 공식, 갈래 안 인기 상위 20개가 두꺼워진다. (`docs/데이터설계.md` 8절)
_Avoid_: 전체 수집, 관심 기술

**갈래 안 점수**:
사용량(주간 다운로드)·성장(7일 증가, HF 인기 점수)·화제(HN 점수)·별의 같은 갈래 안 순위 평균. 별 하나로 자르지 않으려고 쓴다. (2026-11-17)
_Avoid_: 인기 순위(전체 순위로 들림), 별 순

**종류**:
기술이 어떤 모양인지: MCP 서버, 스킬, 플러그인, SDK, 모델. 갈래가 아니라 기술의 칸이고 지도에서 거르기로 쓴다. (2026-11-17)
_Avoid_: 타입, 카테고리

**쓰는 곳**:
기술을 어디에서 쓰는지: Claude Code, Claude 앱, Cursor, Codex 등. 한 기술이 여러 곳일 수 있다. 갈래가 아니라 칸이다. (2026-11-17)
_Avoid_: 호스트, 플랫폼

**기술 상태**:
카탈로그 기술의 지금 모습: 활동 중 / 쉬는 중(12개월 활동 없음) / 중단(출처가 사용 중단이라고 함) / 출처에서 사라짐(성공한 읽기 2번 연속 못 찾음). 수집 오류(읽기 실패)는 상태와 **따로** 표시한다(상태를 바꾸지 않음, erd `collect_error_kind`). 카탈로그 줄은 지우지 않고 상태만 바꾼다. (2026-11-17, 11-18 erd와 맞춤)
_Avoid_: 삭제됨(읽기 실패와 헷갈림), 만료

**첫 점검**:
저장소를 처음 읽거나 다시 읽어 내 기술이 새로 들어왔을 때의 점검. 위험인 기술만 "처음 확인한 위험" 보안 경고를 1번 만들고, 나머지는 등급만 보여 준다. 적용 기회는 만들지 않는다. (2026-11-17)
_Avoid_: 초기 스캔, 온보딩 알림

**설치 프롬프트**:
고른 내 기술을 다른 컴퓨터의 Claude에 붙여 넣으면 하나씩 확인받으며 설치하게 하는 글. 정해진 틀로만 만들고, 비밀값은 빼고, 위험 등급은 기본으로 뺀다. 우리는 글만 만들고 설치는 사용자가 한다. 알파(ADR 0009)
_Avoid_: 자동 설치, 이사(대신 깔아 주는 것으로 들림), 백업

**내 컴퓨터 목록 가져오기**:
사용자가 자기 Claude Code에 붙여 넣으면 전역으로 깐 MCP·스킬 목록을 정해진 형식으로 출력하게 하는 글. 그 출력을 앱에 붙여 넣으면 "프로젝트 밖(내 컴퓨터)" 칸이 채워진다. (ADR 0009)
_Avoid_: 스캔, 에이전트 설치

**쓰고 있어요**:
그 기술을 쓰는 사용자의 수와 **별명**(실명 아님). 내 기술 목록은 기본 공개이고 설정에서 숨길 수 있다. (3순위, ADR 0009)
_Avoid_: 팔로워, 인기

**사용기**:
사용자가 그 기술을 무엇에 써서 어떤 결과를 냈는지 남긴 짧은 글. 등급에 영향을 주지 않고 Claude에 넣지 않는다. "도움이 됐어요"를 받을 수 있다. (3순위)
_Avoid_: 리뷰(평점으로 들림), 평판

**소식판**:
공식 출처의 일반 소식(새 버전, 모델 출시, 공식 보안 공지)을 쌓는 화면. 알림이 아니고 판단 대기 수에 들어가지 않는다. (3순위)
_Avoid_: 뉴스 피드, 알림함

**연동 서비스**:
Vercel·Supabase처럼 앱이 쓰는 바깥 서비스 중, 공식 MCP·커넥터로 AI 도구와 연결할 수 있는 것. 카탈로그 종류의 하나. (3순위)
_Avoid_: 인프라, 클라우드

**개념**:
하네스, 반복 루프, 서브에이전트 패턴처럼 설치물이 아닌 작업 방식. 등급·알림 없이 지도 노드로만 두고, 그 개념을 구현한 기술과 잇는다. (3순위)
_Avoid_: 패턴 기술, 방법론

**내 레이더**:
내 기술을 판단 상태의 고리(쓰는 중 · 적용 후보 · 관심 · 보류·중단)에 놓은 보기. Thoughtworks 기술 레이더에서 빌린 모양. (3순위)
_Avoid_: 레이더 차트

**대응안 초안**:
알림 상세에서 Claude가 쓰는 짧은 대응 제안(고친 버전으로 올리기 / 다른 기술 / 빼기)과 출처. 변경마다 한 번 만들어 그 변경의 모든 알림이 같이 쓴다. 적용 시나리오(요청할 때 만드는 긴 안내)와 다르다. (SPEC-9)
_Avoid_: 조치, 추천

**판단 대기 / 완료**:
알림의 상태 두 가지. 판단(적용 후보 / 보류)이 저장되면 완료가 된다. 저장에 실패하면 판단 대기 그대로다. "처리 완료"라는 말은 쓰지 않는다. (SPEC-4.1)
_Avoid_: 처리 중, 처리 완료, 승인됨

**수집 오류**:
읽기에 실패한 상태. "변화 없음"·"삭제됨"으로 단정하지 않고 따로 표시한다. 종류: 시간 초과 / 네트워크 / 한도 초과 / 상태 코드 / 해석 실패. (불변 2, SPEC-8)
_Avoid_: 없음, 사라짐

**수집 자료**:
출처에서 읽은 값 중 **바뀐 것**만 남긴 한 줄(이전 값 → 현재 값, 출처, 시각). 실제 수집인지 시뮬레이터인지 표시한다. (데이터설계 D절)
_Avoid_: 로그, 스냅샷

**실행 기록**:
수집·다시 읽기·시뮬레이터·채점이 한 번 돌 때마다 남는 기록(`runs`)과 그 단계(`run_steps`). 흐름 화면과 내 실행 기록은 이것만 읽어 그린다. (불변 6)
_Avoid_: 잡, 배치

**시뮬레이터**:
가짜 취약점·가짜 새 기술을 넣어 알림 흐름을 시연하는 장치. 가짜 변경은 **시연 계정에만** 알림을 만들고 지울 수 있다. (PRD-F29, SPEC-3.5)
_Avoid_: 테스트 데이터(실데이터와 섞여 보임)

**영역**:
팀원 한 명이 맡는 기능 묶음. A 지키기(내 기술·보안), B 고르기(알림·판단·기록), C 옮기기·운영(흐름·관리자·설치 프롬프트). 맡은 사람은 그 안의 화면·서버·데이터·QA를 모두 한다. (plan 1절)
_Avoid_: 파트, 프론트/백엔드 담당

**조각**:
한 사람이 한 브랜치에서 하루 안에 끝낼 일 하나. `P-n`으로 부르고 브랜치는 `feat/P-n-…`. (plan 4절, 안내서 7장)
_Avoid_: 태스크, 이슈, 티켓

**이정표**:
여러 조각이 합쳐져 "여기까지 된다"를 보여 주는 지점. M0 얇은 한 줄, M1 1·2순위 끝, M2 3순위·코드 동결. (plan 3절)
_Avoid_: 마일스톤(같은 뜻이지만 우리 말로), 스프린트

**얇은 한 줄**:
자료 한 곳(OSV), 사건 한 종류(보안 경고), 조치 한 가지(판단 저장)를 배포 앱에서 처음부터 끝까지 이은 가장 작은 흐름. M0. (안내서 287–290줄, prd 만드는 순서 1-0)
_Avoid_: MVP, 프로토타입

**코드 동결**:
새 기능을 더 넣지 않고 고치기만 하는 때. 2026-11-20 21:00부터. (plan 3절)
_Avoid_: 마감(제출 마감과 헷갈림)
