# TechRadar

내가 깐 AI 코딩 도구를 **지키고(보안 등급·경고), 고르고(판단), 옮기는(설치 프롬프트)** 서비스의 용어집. (머리말 2026-11-17 고침. 처음엔 "새 기술 소식을 보안으로 거르고 지도에 배치")

## 기술과 지도

**기술**:
지도에 노드 하나로 올라가는 것. LLM 모델, 스킬, MCP 서버, 플러그인, 훅, 하네스 패턴, 개발 도구가 모두 기술이다. (v1 카탈로그 종류: MCP·스킬·플러그인·SDK·모델·연동 서비스·개념. 훅은 다음 버전, 2026-11-17)
_Avoid_: 툴, 아이템, 항목

**입문 세트**:
교육생 · 처음 쓰는 사람에게 맞춰 카탈로그에 직접 넣는 기술 묶음(Claude Code 개념 · 공식 스킬 · 공식 플러그인 · 새 개발 도구). 공식 페이지를 열어 확인한 주소를 한 줄 설명의 근거로 둬 공개 목록에 든다. 오래된 도구라 NEW가 아니다(`signals.starter_set`, ADR 0031, `docs/starter-set.md`).
_Avoid_: 추천 목록(추천은 내 기술 · 취향으로 고르는 다른 화면), 큐레이션

**NEW**:
지도 · 새 기술 화면에서 "이번 주(7일 안) 카탈로그에 새로 들어온 기술" 표시. 카탈로그를 처음 채운 날(11-20)과 **레지스트리 첫 전체 읽기(대량 채우기) 동안 들어온 기술은 NEW가 아니다**: 들어온 날이 새로 나온 날이 아니라서(2026-11-20, I-P-12d-new-bulk). 레지스트리 "발표 시각"은 버전마다라 쓰지 않는다.
_Avoid_: 새로, 신규

**기술 소식**:
기술이 새로 나왔거나 바뀌었다는 바깥 출처의 글 한 건(릴리스, 블로그 글, 인기 급상승 등).
_Avoid_: 뉴스, 피드, 이벤트

**기술 지도**:
기술을 갈래와 연결선으로 엮어 큰 그림을 보여 주는 화면.
_Avoid_: 그래프, 맵, 마인드맵(전체를 부를 때)

**갈래**:
기술을 "하는 일"로 묶는 분류 나무의 가지. v1은 2단계(큰 갈래 > 작은 갈래)다. 종류(MCP·스킬…)나 쓰는 곳(Claude Code…)으로 나누지 않는다. (2026-11-17 바뀜, 처음엔 깊이 제한 없음. ADR 0008)
_Avoid_: 카테고리, 폴더, 태그

**연결선**:
갈래를 가로질러 두 기술의 관계(대체 · 함께 씀 · 의존 · 같은 역할)를 나타내는 선. (v1은 **같은 역할** 하나만 쓴다. 나머지 종류는 다음 버전, 2026-11-17)
_Avoid_: 엣지, 링크

**같은 역할**:
같은 작은 갈래에서 같은 일을 하는 두 기술의 관계(연결선의 v1 종류, `tech_relations`). **후보 → 확정** 두 단계다. 같은 작은 갈래면 후보이고(Claude가 제안한 관계는 근거 인용이 원문에 있을 때만 저장), **확정은 관리자 확인만** 한다(담당자·시각·사유). 처음 짝 목록(20쌍 정도)은 팀이 시드로 넣는다(SPEC-4.4). 적용 기회 알림과 두껍게는 확정된 관계만 쓴다. (ADR 0008 9번 개정, ADR 0015, 2026-11-18)
_Avoid_: 유사 기술(이름이 비슷한 것으로 들림), 대체(연결선의 다른 종류)

## 판단

**보안 등급**:
보안 점검 결과로 기술에 붙는 통과 / 주의 / 위험 / 찾지 못함 네 가지. 근거를 하나도 확인하지 못하면 "찾지 못함"이다. (SPEC-1, 2026-11-18 점검 Y-6)
_Avoid_: 안전도, 점수

**찾지 못함**:
값이나 근거를 확인하지 못했을 때 쓰는 말. 보안 등급에서는 OSV 조회·저장소 정보 같은 근거를 하나도 확인하지 못한 네 번째 등급이고, 출처가 없는 정보는 지어내지 않고 이 말로 둔다. 이름만 직접 추가한 기술은 읽기에 실패하지 않아도 "찾지 못함"이다. 수집 오류(읽기 자체가 실패)와 다르다. (SPEC-1, 2026-11-18)
_Avoid_: 없음, 통과(확인하지 못한 것을 통과로 보이게 하지 않는다)

**고친 버전**:
보안 경고의 취약점이 고쳐진 버전. OSV가 알려 준 값이다. 보안 경고에서 적용 후보("고친 버전으로 올리기")로 판단하면 이 번호를 판단과 함께 저장하고(`judgments.fixed_version`), 설치 프롬프트에는 그 버전으로 고정해 넣는다. 고친 버전이 없으면 [보류]만 고를 수 있다. (ADR 0012, 2026-11-18)
_Avoid_: 안전한 버전(그 버전에 다른 문제가 없다는 뜻이 아니다), 최신 버전

**위험 패턴**:
스킬 폴더의 파일과 MCP 저장소의 코드에서 문구로 찾는 위험한 모양. v1은 P1 원격 실행(위험), P2 비밀값 밖으로 보내기(읽는 곳과 15줄 안이면 위험, 같은 파일에서 더 멀면 주의), P3 넓은 권한(주의) 셋이고, 찾은 파일과 줄 번호를 이유로 보여 준다. 찾지 못했다고 안전하다는 뜻은 아니다. 목록은 관리자가 고친다(규칙 목록). (SPEC-2, 2026-11-18)
_Avoid_: 악성 코드, 바이러스

**평판 요약**:
커뮤니티 리뷰를 모아 만든 긍정 / 섞임 / 부정 요약과 대표 의견. 참고 정보이며 보안 등급을 대신하지 않는다. **v1에서는 하지 않는다**(prd 5-2, ADR 0003 개정 2026-11-18).
_Avoid_: 리뷰 점수, 평점

**내 프로젝트**:
사용자가 공개 GitHub 저장소 주소로 등록한 프로젝트와, 거기서 읽어 낸 기술 목록.
_Avoid_: 레포, 워크스페이스

**내 기술 목록**:
내 프로젝트에서 읽어 낸 기술과 사용자가 직접 더한 기술을 합친, 사용자가 깔아 쓰는 기술의 목록. 인터뷰에서 "깐 것"이라고 부른 것. 기술마다 출처(저장소에서 읽음 / 직접 추가 / 내 컴퓨터 목록 가져오기)를 달고, 직접 숨긴 것은 숨김 표시를 따로 단다. 첫 화면은 기술 지도로 바뀌었다(`docs/ia.md` IA-Q1, 회의 D8에서 정함). (2026-11-17, 11-18 승인)
_Avoid_: 설치 목록, 도구함, 내 도구

**직접 추가**:
사용자가 내 기술 목록에 손으로 더한 기술. 모은 기술에서 골랐으면 보안 등급과 지도 연결이 붙고, 이름만 썼으면 등급은 "찾지 못함", 지도에는 관리자 분류 확인 뒤에 올라간다. (2026-11-17 IA 인터뷰)
_Avoid_: 수동 등록, 커스텀

**직접 숨김**:
저장소에서 읽은 기술을 사용자가 목록에서 뺀 상태. 지우지 않고 남겨 두어 다시 읽어도 되살아나지 않고, 되돌릴 수 있다. (2026-11-17 IA 인터뷰)
_Avoid_: 삭제, 제외

**프로젝트 밖(내 컴퓨터)**:
저장소에 없는 기술(전역으로 깐 MCP·스킬 등)을 담는 칸. 사람마다 하나씩 자동으로 생기고, 내 프로젝트처럼 다룬다. (2026-11-17 IA 인터뷰, 그룹1 인터뷰 근거)
_Avoid_: 기타, 전역 프로젝트

**목록 내보내기**:
내 기술 목록을 다른 컴퓨터로 들고 갈 수 있게 밖으로 내보내는 것. 설치는 하지 않는다. 알파 후보 ⓐ. v1에서는 **설치 프롬프트**로 한다(ADR 0009). 노션으로 보내기는 다음 버전 (2026-11-17, 11-18 회의 D2에서 정함)
_Avoid_: 이사, 세팅 옮기기(대신 설치로 들림), 백업

**노션으로 보내기** (다음 버전):
사용자가 버튼을 누르고 미리보기를 확인한 뒤, 내 기술 목록(숨긴 기술 제외)을 자기 노션 데이터베이스에 한 방향으로 쓰는 것. 기술마다 같은 행을 고쳐 두 번 생기지 않는다. (ADR 0007)
_Avoid_: 노션 동기화(양방향으로 들림), 자동 백업

**노션 연결** (다음 버전):
사용자의 노션 계정과 이 서비스를 이어 노션으로 보내기를 할 수 있게 한 상태. 노션으로 로그인하면 바로 생기고, 구글로 가입한 사용자는 설정에서 만든다. 끊으면 토큰을 지운다. (ADR 0007)
_Avoid_: 노션 로그인(로그인 방법과 헷갈림), 연동 키

**알파**:
안내서 필수 기능 외에 우리 사용자에게 도움이 되는 기능 하나. v1 알파는 **설치 프롬프트 + 내 컴퓨터 목록 가져오기**(회의 D2, ADR 0009). 처음 후보는 `docs/문제정의.md` 6절

**필요**:
사용자가 작업하다 막혔거나 포기한 일을 한 문장으로 등록한 것. 예: "업무 흐름을 마인드맵으로 보고 싶은데 방법을 모르겠다". (접은 가설 B·합친 안 C의 용어. 지금 서비스에서는 쓰지 않는다)
_Avoid_: 니즈, 요구사항(PRD 요구와 헷갈림), 불만

**발견**:
원래 있었지만 사용자가 몰랐던 기술이 그 사용자의 필요에 맞는다고 처음 찾아낸 것. 새로 나온 기술과 구분한다. (접은 가설 B의 알림 ⓑ. 지금 서비스에서는 쓰지 않는다)
_Avoid_: 추천, 신규

**알림**:
사용자에게 판단을 요청하는 한 건. 적용 기회와 보안 경고 두 종류가 있다. 같은 변경이라도 그 기술을 쓰는 사람마다 알림이 하나씩 생긴다.
_Avoid_: 사건(안내서의 사건은 우리 말로 변경이다), 인시던트, 노티

**적용 기회**:
새 기술이 내 프로젝트의 기술과 **확정된** 같은 역할이라 생기는 알림. v1 조건은 셋이다: 확정된 같은 역할 · 내 등록 이후에 들어옴 · 위험이 아님(ADR 0014). (프로젝트 목표와 맞추기는 v1에서 뺌, `docs/ia.md` IA-Q3)
_Avoid_: 추천

**보안 경고**:
내 프로젝트가 쓰는 기술의 보안 등급이 위험으로 바뀌어 생기는 알림.
_Avoid_: 취약점 알림

**모델 종료**:
내 저장소 코드에 문자열로 쓴 모델 이름이 공식 지원 종료 공지(Anthropic · OpenAI · Google)에 있어 생기는 알림. 종료일 · 공식 추천 대체 · 찾은 파일을 보여 준다(PRD-F38, SPEC-3.3, 2026-11-20). 이미 종료된 모델도 알린다.
_Avoid_: 모델 지원 중단, 단종, deprecation 알림

**판단**:
알림에 대해 사용자가 내리는 적용 후보 또는 보류 결정. 판단 전에는 아무것도 바뀌지 않는다.
**11-20(ADR 0028):** 알림이 없어도 지도 패널·새 기술·내 레이더에서 기술에 **판단 상태**를 남길 수 있다(알림 없는 판단, `tech_marks`). 상태는 넷: **쓰는 중**(저장소에서 읽은 것만, 사람이 누르지 않음) · **적용 후보** · **관심** · **보류**(이유 5자 이상). 그 기술에 판단 대기 알림이 있으면 그 알림의 판단으로 함께 저장한다(같은 서버 길, 두 번 저장 안 함). 판단은 기록일 뿐 설치·변경하지 않는다(ADR 0010)
_Avoid_: 승인, 결재, 도구함 추가 (팀원 v5의 "내 도구함에 추가할까요?"와 같은 자리. 판정 후 하나로 통일)

**적용 후보**:
판단의 한 가지. 적용 기회 알림에서는 "그 기술을 써 볼 후보", 보안 경고에서는 "고친 버전으로 올리기"다(고친 버전 번호를 함께 저장). 적용 후보가 된 기술은 설치 프롬프트 기본 목록에 들어가고, 보안 경고에서 고른 것은 고친 버전으로 고정된다. 위험한 버전은 적용 후보가 될 수 없다. (ADR 0010·0012, 2026-11-18) **11-22(ADR 0040):** 지도 · 청사진에서는 같은 저장을 **청사진에 담기**라고 부른다. 화면 말 "적용 후보"는 알림 판단(알림 상세)과 기술 상세의 판단 줄에 남는다.
_Avoid_: 승인, 채택, 설치(우리는 설치하지 않는다)

**보류**:
판단의 다른 한 가지. 지금은 쓰지 않거나 올리지 않겠다는 결정과 그 이유(5자 이상). 보류한 새 기술(보안 경고면 고친 버전)은 설치 프롬프트 기본 목록에 들어가지 않는다. (SPEC-4.1) 불변 4의 "승인 거절"이 우리 말로 보류다. 보류해도 지금 쓰는 설치 프롬프트 목록과 그 버전은 그대로 둔다.
_Avoid_: 거절(불변 4의 "거절"은 "보류"로 바꿔 쓴다), 무시, 삭제

**조치**:
안내서의 "조치"에 해당하는 일. 우리 서비스에서는 **판단 저장**(적용 후보 기록 / 보류 사유 기록)이다. 우리는 사용자 대신 설치하거나 바꾸지 않는다. (ADR 0010)
_Avoid_: 실행, 적용(대신 바꿔 주는 것처럼 들림)

**별명**:
가입 때 정하는 이름. "쓰고 있어요"에 보이는 유일한 사람 정보다. 구글 이름·이메일은 보이지 않는다. (회의 D11, ADR 0009)
_Avoid_: 이름, 실명

**시연 계정**:
발표와 시뮬레이터용으로 만든 계정. 시뮬레이터 알림은 이 계정에만 간다. (SPEC-3.5)
_Avoid_: 테스트 계정(개발용 이메일 로그인 계정과 헷갈림)

**관리자**:
DB의 역할 칸이 admin인 팀원. 관리자를 정하는 화면은 없다. 회원들의 프로젝트·기술·알림을 읽고(취향은 못 봄) 갈래·같은 역할·규칙 목록을 고치지만(담당자·시각·사유가 남음), **남의 알림에는 판단을 만들거나 건너뛸 수 없다.** 본인 알림에는 다른 사용자와 같은 규칙으로 판단할 수 있다. (PRD-F3, 불변 1·5, ADR 0016, 2026-11-18)
_Avoid_: 운영자, 슈퍼유저

**적용 시나리오**:
그 기술을 내 프로젝트에 넣는 방법을 Claude가 쓴 **참고 자료**. 비교표, 적용 단계, 위험과 되돌리는 방법이 들어간다. 요청할 때만, 판단 전후 언제든 만든다. 조치가 아니다(조치는 판단 저장, ADR 0010).
_Avoid_: 가이드, 추천안

**판단 기록**:
판단과 그 이유를 남긴 것. 비슷한 기술이 나오면 근거로 다시 보여 준다.
_Avoid_: 히스토리, 로그

**기술 키**:
기술의 신분증. 생태계와 이름으로 정한다(`npm:…`, `pypi:…`, `github:owner/repo`, `mcp:…`, `hf:…`, `skill:owner/repo/이름`, 원격 MCP 주소는 `url:호스트`, 연동 서비스는 `service:이름`(3순위)). 이름이 비슷한지로 같은 기술을 가리지 않는다. (ADR 0008)
_Avoid_: 기술 이름(같은 이름이 여럿일 수 있음), 별칭

**변경**:
바깥에서 생긴 변화 한 건(예: 보안 등급 통과 → 위험). **안내서의 "사건"은 우리 말로 변경이다**(사건 = 변경, 모두가 같이 쓰는 한 줄). 그 변경을 알리는 것이 알림이고 사람마다 하나씩 생긴다. (`docs/데이터설계.md`, 2026-11-18 점검 Y-6)
_Avoid_: 사건(안내서와 짝지을 때만 쓴다), 이벤트

**인기 신호**:
기술이 얼마나 주목받는지 보여 주는 숫자. 주간 다운로드(npm·PyPI), 스킬은 skills.sh 설치 수, GitHub 별과 7일 증가, HN 점수, HF 순위. 갈래 안 점수(두껍게 할지)에 쓰고, 등급을 대신하지 않는다. 적용 기회 조건으로는 v1에서 쓰지 않는다(ADR 0014). (2026-11-17)
_Avoid_: 평판(댓글 요약과 헷갈림), 순위

**취향**:
가입할 때 고른 만드는 것·쓰는 도구·관심 분야. 추천에만 쓰고 관리자는 볼 수 없다. (3순위, 회의 D6)
_Avoid_: 필요(접은 후보 B의 "막힌 일 한 문장"과 다름), 프로필

**추천**:
취향과 인기 신호로 고른, 아직 내 기술이 아닌 기술. 알림이 아니고 판단을 요구하지 않는다. 반응은 관심 있음 / 없음뿐이다. (3순위, 회의 D6) **11-20:** 지금은 취향의 관심 분야 갈래 안에서 주간 다운로드가 많은 기술을 고른다(P-23). "관심 있음"은 알림 없는 판단의 **관심**으로 합친다(ADR 0028)
_Avoid_: 적용 기회(내 기술과 같은 역할일 때의 알림), 발견

**외톨이**:
지도에서 같은 역할 관계가 하나도 없는 내 기술. 대안을 모르는 기술이 한눈에 보인다. (IVGraph 참고, 3순위)
_Avoid_: 고아 노드

**얇은 기술 / 두꺼운 기술**:
카탈로그에 얼마나 깊게 모으는지. 얇은 기술은 이름·키·한 줄 설명·출처만 있고, 두꺼운 기술은 보안 등급·인기 신호·비교·정기 확인까지 한다. 사용자 중 한 명 이상이 쓰는 기술, 그와 같은 역할, 공식, 갈래 안 인기 상위 20개가 두꺼워진다. (`docs/데이터설계.md` 8절)
_Avoid_: 전체 수집, 관심 기술

**관문**:
카탈로그에 기술을 넣을 때 거치는 세 물음. ① 우리 분야인가(통과하면 얇게 한 줄) ② 누군가와 관련 있나(하나라도 맞으면 두껍게) ③ 근거가 있나(출처 링크가 없으면 저장하지 않고 "찾지 못함"). (`docs/데이터설계.md` 8절, ADR 0008 8번, 2026-11-18)
_Avoid_: 필터, 심사

**필터 (지도 보기)**:
지도에서 보고 싶은 기술만 남기는 조건: 종류 · 하는 일 · 위험·주의만 · 수집 오류만 · NEW만 · 내 기술과 비교군(한 단계, 로그인 뒤, ADR 0027)(값마다 개수). 화면 글자는 "필터"(사용자 11-20, 전에는 "거르기"). 보기 초기화를 누르면 묶기·색과 함께 처음으로 돌아간다. 카탈로그에 넣을 때 거치는 **관문**과는 다르다. (`docs/design.md` 17절)
_Avoid_: 거르기(옛 화면 글자), 관문

**빠른 칩**:
지도 위에 늘 보이는 필터 단추: 들어온 때(오늘 · 이번 주 · 이번 달 = 들어온 지 1 · 7 · 30일 안, 처음 채운 날 · 대량 채우기분은 빠짐) · 위험·주의 · 내 관심(로그인) · 내 기술과 비교군 · 수집 오류. 다시 누르면 꺼진다. 옛 "NEW만(7일)"은 "이번 주"가 맡는다. (ADR 0030 11항, 2026-11-21)

**보기 묶음**:
묶기 · 색 · 필터를 한 번에 바꾸는 이름 붙은 보기(노션의 보기 탭처럼). 기본 묶음(입문자 추천 · 이번 주 새 기술 · 보안 위험 · 내 관심 · 내 기술과 비교군)과 "지금 보기 저장"으로 만든 것(로그인했을 때 이 브라우저에 5개까지). (ADR 0030 11항, 2026-11-21)
_Avoid_: 프리셋(화면 글자로는 쓰지 않음)

**배율 단계**:
지도를 가까이 볼수록 더 자세히 보이는 규칙(네이버 지도처럼). 처음 보기 대비 배율로 멀리 · 처음 보기 · 가까이(모든 이름) · 아주 가까이(한국어 한 줄 · 인기 · 보안) 네 단계. (ADR 0030 11항, 2026-11-21)

**새로 들어온 것 보기**:
이번 주에 들어온 기술이 화면 밖에서 날아와 제자리에 꽂히는 다시 보기. 이미 모은 것을 보여 줄 뿐 수집을 새로 하지 않는다(수집은 관리자 · 정기 실행). (ADR 0030 11항, 2026-11-21)
_Avoid_: 크롤 버튼, 지금 수집

**이 분류만 보기**:
지도에서 묶음 하나를 골라 그 안의 기술만 원반 전체로 다시 펼쳐 보는 것. 위에 경로 칩(전체 › 리서치 › MCP)이 생기고, 쓴 기준은 묶기에서 빠진다. 주소 `in=field:리서치|kind:MCP`로 공유된다. (`docs/design.md` 17절, 2026-11-20)
_Avoid_: 드릴다운, 확대

**규칙 목록**:
관리자가 고치는 목록. 허용 패키지, GitHub 주제 태그, Hacker News 키워드, 위험 패턴 네 가지(`rule_lists`). 분류 확인 화면(IA-17)에서 고치고 담당자·시각·사유가 남는다. (erd 2.3, 2026-11-18)
_Avoid_: 설정

**갈래 안 점수**:
사용량(주간 다운로드)·성장(7일 증가, HF 인기 점수)·화제(HN 점수)·별의 같은 갈래 안 순위 평균. 별 하나로 자르지 않으려고 쓴다. 적용 기회의 "상위 절반" 조건은 v1에서 뺐고, 점수가 만들어지는 P-21 뒤에 다시 넣는다(ADR 0014). (2026-11-17)
_Avoid_: 인기 순위(전체 순위로 들림), 별 순

**종류**:
기술이 어떤 모양인지: MCP 서버, 스킬, 플러그인, SDK, 모델, 연동 서비스, 개념(일곱 가지). 갈래가 아니라 기술의 칸이고 지도에서 필터로 쓴다. (2026-11-17)
_Avoid_: 타입, 카테고리

**쓰는 곳**:
기술을 어디에서 쓰는지: Claude Code, Claude 앱, Cursor, Codex 등. 한 기술이 여러 곳일 수 있다. 갈래가 아니라 칸이다. (2026-11-17)
_Avoid_: 호스트, 플랫폼

**기술 상태**:
카탈로그 기술의 지금 모습: 활동 중 / 쉬는 중(12개월 활동 없음) / 중단(출처가 사용 중단이라고 함) / 출처에서 사라짐(성공한 읽기 2번 연속 못 찾음). 수집 오류(읽기 실패)는 상태와 **따로** 표시한다(상태를 바꾸지 않음, erd `collect_error_kind`). 카탈로그 줄은 지우지 않고 상태만 바꾼다. (2026-11-17, 11-18 erd와 맞춤)
_Avoid_: 삭제됨(읽기 실패와 헷갈림), 만료

**첫 점검**:
저장소를 처음 읽거나 다시 읽어 내 기술이 새로 들어왔을 때의 점검. 위험인 기술만 "처음 확인한 위험" 보안 경고를 1번 만들고, 나머지는 등급만 보여 준다. 적용 기회는 만들지 않는다. (2026-11-17)
_Avoid_: 초기 스캔, 온보딩 알림

**설치 프롬프트**:
고른 내 기술을 다른 컴퓨터의 Claude에 붙여 넣으면 하나씩 확인받으며 설치하게 하는 글. 정해진 틀로만 만들고, 비밀값은 빼고, 위험한 버전은 어떤 경우에도 넣지 않는다(고친 버전이 있으면 그 버전으로 고정해 넣는다, ADR 0012). 우리는 글만 만들고 설치는 사용자가 한다. 알파(ADR 0009)
_Avoid_: 자동 설치, 이사(대신 깔아 주는 것으로 들림), 백업

**내 컴퓨터 목록 가져오기**:
사용자가 자기 Claude Code에 붙여 넣으면 전역으로 깐 MCP·스킬 목록을 정해진 형식으로 출력하게 하는 글. 그 출력을 앱에 붙여 넣으면 "프로젝트 밖(내 컴퓨터)" 칸이 채워진다. (ADR 0009)
_Avoid_: 스캔, 에이전트 설치

**청사진 스튜디오**:
청사진(`/blueprint`)을 짜는 화면. 자유 캔버스에 단계를 두고 연결선으로 순서를 정하며, ① 단계 구축 → ② 스킬 붙이기 → ③ 결과물로 나아간다(ADR 0035, 11-21). 코드 이름은 그대로 `blueprint`. **11-22 바뀜(ADR 0040):** 단계 칸 없이 한 화면이다. 위 막대의 "확정 · 내보내기"가 결과물 창(고칠 것 · 내보내기 · 바뀌는 것 미리보기 · 확정 · AI 점검)을 열고, 아래 패널은 [기술 | 불러오기] 두 탭이다.
_Avoid_: 에디터, 보드(보드는 지도의 다른 보기)

**틀**:
단계와 연결선만 담은 청사진 템플릿. 기술은 비어 있다. 내 기술을 붙여 쓴다(ADR 0035).
_Avoid_: 뼈대, 스켈레톤

**조합**:
단계와 기술까지 담은 청사진 템플릿. 남의 조합을 불러오면 내가 판단하지 않은 기술은 점선 **후보 칩**으로 보이고, "적용 후보로 고르기"를 눌러야 청사진에 들어간다(판단 = 관문, ADR 0034 · 0035). 11-22부터 이 단추의 화면 말은 "청사진에 담기"다(동작은 같음, ADR 0040).
_Avoid_: 세트, 번들(입문 세트와 헷갈림)

**AI 점검**:
확정한 청사진에 "점검 받기"를 누를 때만 하는 점검. 코드가 찾은 사실(출처 포함)과 Claude 제안을 보여 주고 청사진은 바꾸지 않는다. 하루 3번(ADR 0035).
_Avoid_: 자동 수정, 검수(바꿔 주는 것으로 들림), 대응안 초안(알림 쪽 말)

**청사진에 담기**:
지도에서 기술을 청사진으로 가져갈 몫에 넣는 일(장바구니처럼, ADR 0040). 로그인한 사람에게는 **적용 후보 저장과 같다**(DB는 그대로, 판단 = 관문, 불변 1). 손님은 이 브라우저 목록에만 넣는다(id만 · 30개까지, 서버 저장 없음). 담긴 뒤 "빼기"는 관심으로 낮춘다. (11-22 사용자 결정, 로그인 쪽은 #206)
_Avoid_: 장바구니에 넣기(화면 말 아님), 추가, 설치

**담은 기술**:
청사진에 담긴 기술 모음. 청사진 기술 트리의 폴더와 메뉴 "청사진" 옆 배지가 같은 셈이다(로그인 = 적용 후보, 손님 = "지도에서 담은 기술" 폴더). 못 읽으면 배지를 숨긴다(0으로 보이지 않음, 불변 2). (ADR 0040)
_Avoid_: 장바구니, 후보 목록

**단계 메모**:
청사진 단계마다 남기는 짧은 글(200자, 앞뒤 공백 없앰). 청사진 graph 안에 함께 저장되어 본인만 읽고, 카드에 두 줄로 보이며 내보내기에 "메모:" 줄로 들어간다. **템플릿과 Mermaid 내보내기에는 넣지 않는다.** (ADR 0040, 마이그레이션 `p12h_stage_note`)
_Avoid_: 코멘트(사용기 · 댓글과 헷갈림), 사용기

**바뀌는 것 미리보기**:
확정하기 전에 "지난 확정과 달라진 것"(더하고 뺀 단계 · 이름 · 기술 · 선 · 메모)을 보여 주는 목록. 처음이면 "처음 확정이에요", 같으면 "달라진 것이 없어요". 사람이 보고 "이대로 확정"을 누를 때만 저장한다(불변 1의 화면 표현, Terraform plan에서 빌린 규칙). (ADR 0040)
_Avoid_: 미리 적용, 시뮬레이션(적용 시나리오와 헷갈림), diff(화면 말 아님)

**프로젝트 관리**:
메뉴 "프로젝트"(`/dashboard`)의 화면 이름. 레포(프로젝트) 단위로 안전 · 판단할 것 · 바뀐 것 · 대안 · 옮길 준비를 한 판에서 본다. 옛 "현황"과 계정 메뉴의 "내 프로젝트"를 합쳤다. 안내서 필수 대시보드는 이 화면의 숫자 4칸 위젯이 맡는다. (ADR 0041, 11-22)
_Avoid_: 현황(옛 메뉴 이름), 대시보드(화면 말 아님, 주소와 안내서 용어로만), 내 프로젝트

**위젯**:
프로젝트 관리 보드 위의 칸 하나(숫자 4칸 · 판단함 · 레포 보드 · 바뀐 것 · 옮기기 진행 · 점검한 비율 · 소식 · 요즘 뜨는 대안 · 기록 찾기 · 레포 관리, 10개). 편집 모드에서만 옮기고 크기를 바꾸고 넣고 뺀다. 배치는 이 브라우저에만 저장한다. 위젯마다 읽는 중 · 없음 · 읽지 못함을 따로 보인다(불변 2). (ADR 0041)
_Avoid_: 카드(레포 카드와 헷갈림), 패널

**레포 서랍**:
레포 보드에서 레포 카드를 누르면 오른쪽에 열리는 패널. 그 레포의 내 기술 표(이름 · 종류 · 출처 파일 · 등급 · 판단 상태 · 최근 바뀜 · 마지막 확인)와 확정 청사진을 보인다. 행을 누르면 기술 상세로 간다. (ADR 0041)
_Avoid_: 상세 페이지, 모달

**검증 탭**:
청사진 아래 패널(높이 조절)의 탭 하나. 위 막대 "검증"을 누르면 열린다. 위 작은 줄은 구성 요약(단계별 · 종류별 수)이고 아래는 검증 항목이다. 항목에는 **실제로 셀 수 있는 것만** 보인다(위험 등급, 담지 않은 기술, 수집 오류, 한도, 빈 단계, 고리). 확정 창의 "고칠 것"과 같은 검사다. (ADR 0042)
_Avoid_: 검증 독(11-22 밤 계획 때 이름, 따로 붙은 패널은 되돌림), 호환성 검사, 의존성 검사(우리에게 그 데이터가 없음), 콘솔

**사용자 표시 관계**:
청사진에서 사람이 두 기술 노드 사이에 그은 가는 점선. 사람이 남긴 표시일 뿐이고, 앱이 호환 · 의존을 확인한 것이 아니다. 청사진 graph의 `links`에 저장되고(100개까지), 내보내기에 "사용자 표시 관계: A → B" 줄로 들어간다. 조합 템플릿에도 남는다. (ADR 0042, 마이그레이션 `202611232200_P-12j_tech_links`)
_Avoid_: 의존성, 호환, 연결선(단계 사이 순서 선과 헷갈림)

**쓰고 있어요**:
그 기술을 쓰는 사용자의 수와 **별명**(실명 아님). 내 기술 목록은 기본 공개이고 설정에서 숨길 수 있다. (3순위, ADR 0009)
_Avoid_: 팔로워, 인기

**사용기**:
사용자가 그 기술을 무엇에 써서 어떤 결과를 냈는지 남긴 짧은 글. 등급에 영향을 주지 않고 Claude에 넣지 않는다. "도움이 됐어요"를 받을 수 있다. (3순위)
_Avoid_: 리뷰(평점으로 들림), 평판

**소식판**:
공식 출처의 일반 소식(새 버전, 모델 출시, 공식 보안 공지)을 쌓는 화면. 알림이 아니고 판단 대기 수에 들어가지 않는다. (3순위)
_Avoid_: 뉴스 피드, 알림함

**연동 서비스**:
Vercel·Supabase처럼 앱이 쓰는 바깥 서비스 중, 공식 MCP·커넥터로 AI 도구와 연결할 수 있는 것. 카탈로그 종류의 하나. (3순위)
_Avoid_: 인프라, 클라우드

**개념**:
하네스, 반복 루프, 서브에이전트 패턴처럼 설치물이 아닌 작업 방식. 등급·알림 없이 지도 노드로만 두고, 그 개념을 구현한 기술과 잇는다. (3순위) — 2026-11-21: 앱 화면의 개념 이름 "하네스(에이전트 지시 파일)"는 "지침 파일(CLAUDE.md · AGENTS.md)"로 바꿈(공식 용어집에서 harness는 Claude Code 자체, 키 `concept:harness`는 그대로, 사용자 결정). 팀 문서의 "하네스" 말은 그대로 쓴다
_Avoid_: 패턴 기술, 방법론

**청사진**:
단계(순서 · 나란히)마다 쓸 기술을 붙여 만드는 내 작업 설계 판(`/blueprint`, design.md 14절 ⑤). 확정하면 내 이력에 쌓이고, 프롬프트 · CLAUDE.md 글로 내보낸다(AI 호출 없음). 서비스 흐름 "지도에서 고르고, 청사진으로 옮긴다"의 뒤쪽. 화면 이름은 "청사진", **코드 · 주소 · DB 이름은 `blueprint`**(바꾸지 않음). (11-21 사용자 결정)
_Avoid_: 블루프린트(옛 화면 이름), 설계도, 도구함

**보드** (옛 이름 "내 레이더"):
2026-11-21 사용자 결정: 이름을 **보드**로, 역할은 지도와 청사진을 잇는 다리. 칸은 그대로(쓰는 중 · 관심 · 적용 후보 · 보류, 쓰는 중은 읽기만), 칸 안을 **갈래 또는 내 태그로 묶고**, 적용 후보 카드에 "청사진에 넣기". 끌어 놓기는 안 함(옮기면 판단 대기 알림까지 판단되는 문제, 불변 1). 대시보드 숫자는 **일지** 맨 위로 옮김. 아래는 11-20 기록.
내 기술을 판단 상태별 **칸반**(관심 → 적용 후보 → 쓰는 중, 보류)에 놓은 화면(`/views`). 위에는 대시보드 숫자(내 기술 수 · 변경 수 · 판단 대기 / 완료)가 있어 **대시보드(IA-5)를 이 화면이 맡는다**. 처음엔 고리(과녁) 모양에 "중단"까지 다섯 칸이었으나 "과녁판 같다"는 의견으로 칸반으로, 중단은 보류에 합침. (ADR 0028, 11-20)
_Avoid_: 레이더 차트, 내 레이더(옛 화면 이름)

**일지**:
옛 "기록" 화면(`/history`)의 새 이름이자 모양(11-21 사용자 결정). 맨 위에 대시보드 숫자 요약(누르면 /dashboard나 그 목록), 그 아래 판단 대기 알림, 그 아래 알림 · 판단 · 변경을 시간순 한 흐름. 찾기(기간 · 상태 · 기술)는 안내서 필수 "기록과 찾기"라 그대로. 지도 위의 판단 대기 · 최근 변경 칩은 여기로 옮김
_Avoid_: 기록 찾기(옛 화면 이름), 로그

**보는 곳 줄**:
지도 · 보드 · 일지 맨 위의 "지도 | 보드 | 일지" 줄(`app/nav/space-switch.tsx`). 세 화면이 한 공간이라는 뜻이고, 위 메뉴에는 로고 · 지도 · 청사진만 둔다(11-21 사용자 결정)
_Avoid_: 탭(보기 묶음 탭과 헷갈림)

**내 태그**:
사용자가 기술에 직접 붙이는 자기만의 말(= "내 묶음", 11-21 사용자 결정). 본인만 보고 공개하지 않는다(RLS). 지도 사이드 패널에서 붙이고 떼며, 보기(필터)에서 거르고, 보드에서 묶는 기준이 된다. 같은 기술에 대소문자만 다른 태그는 하나로 본다. 갈래(관리자가 정한 분류)와 다르다
_Avoid_: 카테고리, 갈래, 라벨

**대응안 초안**:
알림 상세에서 Claude가 쓰는 짧은 대응 제안(고친 버전으로 올리기 / 다른 기술 / 빼기)과 출처. 변경마다 한 번 만들어 그 변경의 모든 알림이 같이 쓴다. 적용 시나리오(요청할 때 만드는 긴 안내)와 다르다. (SPEC-9)
_Avoid_: 조치, 추천

**판단 대기 / 완료**:
알림의 상태 두 가지. 판단(적용 후보 / 보류)이 저장되면 완료가 된다. 저장에 실패하면 판단 대기 그대로다. "처리 완료"라는 말은 쓰지 않는다. 완료는 판단을 마쳤다는 뜻이지 조치를 실행했다는 뜻이 아니다. (SPEC-4.1)
_Avoid_: 처리 중, 처리 완료, 승인됨

**수집 오류**:
읽기에 실패한 상태. "변화 없음"·"삭제됨"으로 단정하지 않고 따로 표시한다. 종류: 시간 초과 / 네트워크 / 한도 초과 / 상태 코드 / 해석 실패. (불변 2, SPEC-8)
_Avoid_: 없음, 사라짐

**최근 확인**:
우리가 그 기술을 마지막으로 읽는 데 **성공**한 시각(`last_checked_ok_at`)이 기준 시간(시안 36시간, 팀 추정) 안인 상태. 지도에서 선이 지나가면 밝아지고 이름이 뜬다. 수집 오류가 난 점과 검사 전인 점은 최근 확인이 아니다. 그 기술이 새로 바뀌었다는 뜻(**최근 변경**)과 다르다. (`docs/design.md`, 불변 2)
_Avoid_: 최신, 방금 점검, 실시간

**펼치기**:
지도에서 점선 고리가 있는 점을 눌러, 그 점과 같은 역할의 기술(관리자가 확인한 관계만)을 더 보이게 하는 것. 새 점은 같은 갈래 안에 놓이고 점선 고리는 사라진다. (제안, 팀 확인 전: `docs/design.md` 3·10절, IA-Q5, ADR 0015)
_Avoid_: 확장(기능 확장과 헷갈림), 로딩

**검사 전**:
아직 한 번도 읽지 않아 마지막 확인 성공 시각이 없고 수집 오류도 아닌 기술의 상태. 지도에서 점선 원으로 보이고 밝아지지 않는다. 수집 오류(읽기에 실패함. **등급이 아니라 등급 옆에 덧붙는 상태**, spec 1절), 찾지 못함(출처에 없음), 오래됨(읽은 적은 있으나 기준 시간이 지남)과 다르다. (제안, 팀 확인 전: `docs/design.md` 3·10절. 이전 문서의 "확인 전"과 같은 뜻이나 관리자 확인 전인 같은 역할 후보의 "확인 전"과 헷갈려 "검사 전"으로 적었다)
_Avoid_: 확인 전(같은 역할 후보와 혼동), 대기 중

**중심 보기**:
지도에서 한 점을 골라 그 점과 1~3단계 이웃만 남기고 나머지를 감추는 보기. `Esc`로 들어오기 직전 화면으로 돌아간다. (제안, 팀 확인 전: `docs/design.md` 3절)
_Avoid_: 포커스 모드(키보드 포커스와 혼동)

**수집 자료**:
출처에서 읽은 값 중 **바뀐 것**만 남긴 한 줄(이전 값 → 현재 값, 출처, 시각). 실제 수집인지 시뮬레이터인지 표시한다. (데이터설계 D절)
_Avoid_: 로그, 스냅샷

**실행 기록**:
예약·지금 실행·처음 등록 읽기·다시 읽기·시뮬레이터·채점(시작 방식 6가지)이 한 번 돌 때마다 남는 기록(`runs`)과 그 단계(`run_steps`). 흐름 화면과 내 실행 기록은 이것만 읽어 그린다. (불변 6)
_Avoid_: 잡, 배치

**시뮬레이터**:
가짜 취약점·가짜 새 기술을 넣어 알림 흐름을 시연하는 장치. 가짜 변경은 **시연 계정에만** 알림을 만들고 지울 수 있다. (PRD-F29, SPEC-3.5)
_Avoid_: 테스트 데이터(실데이터와 섞여 보임)

**영역**:
팀원 한 명이 맡는 기능 묶음. A 지키기(내 기술·보안), B 고르기(알림·판단·기록), C 옮기기·운영(흐름·관리자·설치 프롬프트). 맡은 사람은 그 안의 화면·서버·데이터·QA를 모두 한다. (plan 1절)
_Avoid_: 파트, 프론트/백엔드 담당

**조각**:
한 사람이 한 브랜치에서 하루 안에 끝낼 일 하나. `P-n`으로 부르고 브랜치는 `feat/P-n-…`. (plan 4절, 안내서 7장)
_Avoid_: 태스크, 이슈, 티켓

**이정표**:
여러 조각이 합쳐져 "여기까지 된다"를 보여 주는 지점. M0 얇은 한 줄, M1 1·2순위 끝, M2 3순위·코드 동결. (plan 3절)
_Avoid_: 마일스톤(같은 뜻이지만 우리 말로), 스프린트

**얇은 한 줄**:
자료 한 곳(OSV), 사건 한 종류(보안 경고), 조치 한 가지(판단 저장)를 배포 앱에서 처음부터 끝까지 이은 가장 작은 흐름. M0. (안내서 287–290줄, prd 만드는 순서 1-0)
_Avoid_: MVP, 프로토타입

**코드 동결**:
새 기능을 더 넣지 않고 고치기만 하는 때. 2026-11-23(월) 21:00부터(11-19에 11-20 21:00에서 18:00으로 늦췄고, 11-21에 다시 21:00으로. 병합 마감은 20:00, 제출은 같은 날 23:59). (plan 3절)
_Avoid_: 마감(제출 마감과 헷갈림)


**이어지는 위험**:
같은 기술·같은 버전의 보안 위험이 아직 끝나지 않은 상태. 같은 원인의 변경이 있고 그 뒤로 "위험이 아니다"라고 등급을 매긴 적이 없으면 이어지는 중이라, 정기 OSV 재확인이 새 변경(회차)을 만들지 않고 그 변경에 알림을 잇는다. 변경 뒤에 위험이 아니라고 매긴 기록이 있으면 고쳐졌다 다시 위험해진 것이라 회차를 하나 올린 새 변경이 된다(SPEC-3.1). 같은 취약점의 별칭(CVE·GHSA·PYSEC)은 같은 위험으로 본다.

**상태를 정한 출처 (`status_by`)**:
기술의 상태(활동 중·쉬는 중·중단·출처에서 사라짐)를 **누가 정했는지**와 그때의 상태. `github:dormant`·`mcp_registry:deprecated`처럼 적고 비면(null) 모른다. 상태를 더 나쁘게 바꾸는 것은 건드릴 수 있는 수집기만 하고, 되돌리는 것은 **자기가 정한 상태만** 한다. 적힌 상태가 지금 상태와 다르면 다른 쪽이 고친 것이다(ADR 0021).

**공식 조직**:
기술을 두껍게 보는 이유 "공식"의 기준. 서버 이름의 이름공간(`/` 앞쪽 전체, 레지스트리가 검증함)이 `rule_lists`의 `official_org` 목록의 값(이름공간 전체 `io.github.openai`·`com.openai` 꼴, 처음 값: `io.github.` 아래 modelcontextprotocol·anthropics·openai, 관리자가 고침)과 **전체가 같을 때** 공식이다. 조직 낱말만 맞는 이름(`dev.openai`)과 게시자가 적는 저장소 주소는 증거가 아니다. **공식 MCP 레지스트리에 등재됐다는 것만으로는 공식이 아니다**: 레지스트리 항목은 모두 등재돼 있다(ADR 0019).
