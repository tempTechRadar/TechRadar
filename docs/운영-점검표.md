# 운영 점검표 (main에 합친 뒤)

**왜:** 11-18–11-19 운영 장애 8건은 모두 내 컴퓨터·가짜 DB 시험은 통과했는데 운영 주소에서만 깨졌다. 가짜 DB 시험은 환경변수·DB 열 권한·마이그레이션 적용 여부를 모른다(`docs/debug-note.md` 11-18 `alerts.run_id`, 11-19 `CRON_SECRET`·Supabase 주소·Site URL·서비스 키·#133 마이그레이션·`NEXT_REDIRECT`, #153 시나리오 열 권한).

**언제:** 코드가 바뀐 PR을 main에 합치고 운영 배포가 Ready가 된 뒤, 합친 사람이 돈다. 문서만 바뀐 병합은 빌드를 건너뛰니(`vercel.json` `ignoreCommand`) 돌지 않는다. 코드 동결(11-20 21:00)과 발표 리허설 전에는 한 바퀴 전부.

**어떻게:** 그 PR이 건드린 줄만 돌아도 된다. 실패하면 `docs/debug-note.md`에 한 줄 쓰고 팀에 알린다. 화면 전체가 깨졌으면 고칠 PR을 기다리지 말고 팀과 이전 배포로 되돌릴지 먼저 정한다. 값(키·비밀번호)은 보지도 적지도 않는다.
