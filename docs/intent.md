작업을 시작할 때마다 맨 위에 덧붙인다. 끝나면 "결과"를 채운다. 5칸: 문제 · 기대 결과 · 영향 범위 · 제약 · 열린 질문.

## I-002 · 2026-11-17 · 팀원 문서와 통합해 인터뷰 준비하기
- 브랜치: `docs/integrate-problem-interview`
- 출처: 안내서 5장(문제 정의), 팀원 PR #1(`docs/가이드라인.md`, `docs/작업기록-20261116.md`, `interviews/인터뷰-A-비전공수강생.md`)

| 칸 | 내용 |
|---|---|
| 문제 | 서비스 방향이 두 갈래다. 우리 쪽은 "새 기술 소식 지켜보기형", 팀원 쪽은 "작업 중 막힘 → 검색·추천형"이다. 이대로 오늘 인터뷰를 하면 어느 쪽을 확인할지 흐려진다 |
| 기대 결과 | ① `docs/문제정의.md`에 가설 A·B와 합친 안 C, 인터뷰 판정 기준이 있음 ② `interviews/질문지.md`가 두 가설을 가를 수 있고 30분 안에 끝남 ③ `interviews/인터뷰-계획.md`에 분담, 동의 문구, 하나로 통일한 기록 양식이 있음 |
| 영향 범위 | `docs/문제정의.md`, `interviews/질문지.md`, `interviews/인터뷰-계획.md`(새 파일), `docs/GLOSSARY.md`, `docs/adr/`, 기록 파일들. 팀원 PR #1의 파일은 고치지 않음 |
| 제약 | 인터뷰는 오늘(11/17). 저장소가 공개 상태(ADR 0004)라 실명·연락처를 쓰지 않음. 팀원 문제정의 v4는 아직 공유되지 않아 PR #1과 작업기록에 있는 내용만 반영 |
| 열린 질문 | 가이드라인 ↔ CLAUDE.md 충돌 2건(안내서 우선 여부, 비공개 유지)은 팀이 결정해야 함 → 이번 작업 범위 밖. 팀원 v4가 오면 다시 맞춰야 함 |

**결과:** 세 문서 완료(문제정의 통합본, 질문지 통합본 Q1–Q14, 인터뷰 계획). ADR 0005, 용어 2개 추가. 충돌 2건과 팀원 v4 반영은 남음. 브랜치 `docs/integrate-problem-interview`.
