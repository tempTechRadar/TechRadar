# 관리자 사용설명서

> TechRadar 관리자 화면(`/admin`)을 처음 쓰는 사람을 위한 쉬운 설명입니다. 화면 문구는 2026-11-19 main 코드에서 옮겼습니다(`app/admin/`).
> 관리자는 DB 프로필의 역할 칸(`role = admin`)으로 정합니다. 관리자를 정하는 화면은 없습니다(PRD-F3).

## 먼저 알아 둘 것

- **관리자만 열립니다.** 일반 계정으로 열면 "관리자만 볼 수 있어요."가 나옵니다. 버튼을 누르는 서버 동작도 매번 관리자인지 다시 확인하고, DB 권한 규칙(RLS)도 한 번 더 막습니다(불변 5).
- **남의 알림은 판단하지 않습니다.** 관리자 화면에는 판단 버튼이 없습니다. 관리자도 **자기** 알림은 일반 사용자와 같은 규칙으로 판단할 수 있습니다(ADR 0016).
- **고치면 기록이 남습니다.** 같은 역할 확정·규칙 고치기·갈래 정하기는 사유를 꼭 적어야 하고, 누가·언제·왜 했는지가 바꾼 기록(`audit_logs`)에 남습니다. 이 기록은 아무도 고치거나 지울 수 없습니다.
- **비밀값은 어디에도 쓰지 않습니다.** 사유 칸에 키처럼 보이는 글을 쓰면 거절됩니다.

## 탭 8개 한눈에

| 탭 | 무엇을 보나 | 고칠 수 있나 |
|---|---|---|
| 회원별 등록 | 회원마다 프로젝트·저장소·기술 수·마지막 읽은 시각 | 보기만 |
| 수집 자료 | 출처에서 모은 값(이전 값과 현재 값) | 보기만 |
| 알림과 처리 현황 | 모든 회원의 알림과 판단 상태 | 보기만 |
| 수집 실행과 오류 | 실행 기록, 연속 실패, 수집 오류 종류 | 보기만 |
| 흐름 화면 | 실제 실행 기록으로 칠한 지켜보는 길 | 보기만(여기서 지금 실행·시뮬레이터·실패 시연으로 감) |

## 1. 회원별 등록 (`/admin/members`)
- **무엇:** "회원마다 등록한 프로젝트와 저장소 주소, 읽어 낸 기술 수(숨긴 것 제외), 마지막으로 읽은 시각이에요."
- **언제:** 누가 무엇을 등록했는지, 읽기가 오래 멈춘 회원이 있는지 볼 때.
- **표시:** "관리자"·"시연" 표시가 붙은 계정은 각각 관리자·시연 계정입니다. "등록 없음"은 프로젝트가 아직 없다는 뜻입니다.

## 2. 수집 자료 (`/admin/observations`)
- **무엇:** "출처에서 모은 값이에요. 이전 값과 현재 값을 나란히 보여 줘요."
- **주의:** 시뮬레이터가 만든 줄에는 **"가짜"** 표시가 붙습니다. 진짜 자료와 섞어 판단하지 않습니다.

## 3. 알림과 처리 현황 (`/admin/alerts`)
- **무엇:** "모든 회원의 알림과 판단 상태예요. 이 화면에서는 보기만 해요: 판단은 알림을 받은 본인만 할 수 있어요."
- **거르기:** 전체 · 판단 대기 · 처리됨 · 적용 후보 · 보류.
- **언제:** 판단이 오래 밀린 알림이 있는지 볼 때. 대신 판단해 주는 버튼은 일부러 없습니다(불변 1).

## 4. 수집 실행과 오류 (`/admin/runs`)
- **무엇:** "언제 무엇이 돌았고 몇 건을 처리했는지, 실패가 몇 번 이어졌는지 보여 줘요. 수집 실패는 '변화 없음'이 아니라 '수집 오류'로 남아요."
- **연속 실패:** 같은 출처가 연달아 실패하면 여기에 나옵니다. 비어 있으면 "지금 이어지고 있는 실패는 없어요."
- **지금 한 번 실행:** 이 탭 위의 "지금 한 번 실행" 링크를 누르면 `/admin/run-now`로 갑니다(아래 5-1). 예전에는 꺼진 자리("…조각(P-17)이 붙으면 켜져요")였는데 고침(PR #145).

## 5. 흐름 화면 (`/admin/flow`)
- **무엇:** "앱이 실제로 돈 기록(`runs`·`run_steps`)대로 칠해집니다. 기록이 없는 상자는 회색으로 남습니다." 미리 칠해 둔 그림이 아닙니다(불변 6).
- **쓰는 법:** 아래 "실행 목록"에서 한 줄을 고르면 그 실행의 길만 칠해집니다. 상자를 누르면 "설정과 이 실행의 기록(들어온 것·나간 것·호출·오류)"이 아래에 나오고, 화살표 위 숫자는 넘어간 건수입니다.
- **색:** 안 켜짐(회색)·실행 중·성공·실패(빨강)·판단 대기(주황 점선)·꺼 둠.
- **비어 있으면:** "아직 실행 기록이 없어요. 시뮬레이터(P-5)나 지금 실행(P-17)을 한 번 돌리면 여기에 생겨요."
- 위쪽 링크: 시뮬레이터 · 지금 한 번 실행 · 실패 시연.

### 5-1. 지금 한 번 실행 (`/admin/run-now`)
- **무엇:** "매일 06:00(한국 시간)에 저절로 도는 수집을 지금 한 번 돌려요. 출처 하나가 실패해도 나머지는 계속하고, 실패는 '수집 오류'로 남아요."
- **언제:** 정기 실행이 실패했을 때 다시 돌리거나, 시연 전에 최신 자료를 받을 때. 무료 플랜 예약은 하루 한 번이라 "다시 돌리는 건 이 버튼으로 해요."
- **남는 것:** 실행 기록 1개(흐름 화면에서 볼 수 있음). 수집기 4개를 다 돌면 1분 넘게 걸릴 수 있습니다(11-19 지금 실행: 1분 4초, 3,200건).
- **막히면:** "서비스 키가 없어요. 서버 설정(.env.local)을 확인해 주세요." → 서버 환경변수는 사람이 직접 넣습니다.

### 5-2. 실패 시연 (`/admin/demo`)
- **무엇:** 일부러 실패 5가지(수집 오류·사건 아님·중복·판단 대기·저장 실패)를 만들어 흐름 화면에 실제 기록으로 남깁니다. 같은 화면에 정답 사례 G1–G9 **채점** 버튼도 있습니다("저장해 둔 조회 결과만 써서 바깥 호출은 없어요").
- **켜야 쓸 수 있음:** 운영 배포에서는 꺼져 있습니다. "꺼짐 — 운영 배포이거나 ENABLE_FAIL_DEMO가 true가 아니에요. ①②⑤는 눌러도 아무 일도 없어요." → 미리보기 배포는 꺼 두었으니(ADR 0018) 지금은 **로컬에서만** 씁니다. 배포 주소에서는 아래 5-3을 씁니다.
- **⑤ 저장 실패:** 켜면 **이 브라우저**에서 **시연 계정**의 다음 판단 저장 1번이 실패합니다(10분 뒤 저절로 꺼짐). 끝나면 "끄기"를 누릅니다.
- **누가 판단하나:** 관리자도 자기 알림은 판단할 수 있지만 남의 알림은 판단할 수 없습니다(ADR 0016). 시연 알림은 시연 계정 것이라, ⑤를 켠 뒤 같은 브라우저에서 시연 계정으로 판단합니다. 예전 안내의 "관리자는 판단할 수 없으니"는 고침(PR #145).

### 5-3. 배포 주소에서 실패 보여 주기
실패 시연 스위치를 켜지 않고, **진짜로 깨진 입력**을 넣어 빨간 상자를 만듭니다. 앱 코드는 사용자가 깨진 파일을 올렸을 때와 똑같이 돌고, 흐름 화면은 그 실행 기록대로 칠합니다(불변 6, ADR 0024 제안).
- **준비(사람이 한 번만):** 공개 저장소 `csaeil/techradar-fail-demo`(11-19 차세일이 만듦: https://github.com/csaeil/techradar-fail-demo)를 쓰고, 뿌리에 `package.json` 한 파일만 둡니다. 내용은 일부러 끝을 자른 JSON(`{ "dependencies": `)입니다. README에 "일부러 깨 둔 시연용"이라고 적습니다. `.mcp.json`·`requirements.txt`·`.claude/skills/`는 두지 않습니다(있으면 읽은 것이 생겨 "일부 실패"가 됩니다). 2026-11-19 현재 이 저장소는 **아직 없습니다.**
- **누르는 순서:**
  1. 배포 주소에 관리자 계정으로 로그인합니다(운영은 테스트 로그인이 꺼져 있습니다).
  2. `/projects`에서 저장소 주소 칸에 `https://github.com/csaeil/techradar-fail-demo`를 넣고 등록합니다. 처음이면 "처음 등록 읽기", 이미 등록했으면 "다시 읽기"로 돕니다.
  3. `/projects`로 돌아오면 그 프로젝트에 "마지막 읽기가 실패했어요. 목록이 비었거나 일부만 보일 수 있어요(없다는 뜻이 아니에요)."가 보입니다.
  4. `/admin/flow`를 엽니다. 실행 목록 맨 위(그 사이 다른 실행이 없었다면)에 시작 "처음 등록 읽기"(또는 "다시 읽기 버튼")·상태 **실패** 줄이 있습니다. 그 줄을 고릅니다.
  5. 시작 상자와 **"내 기술 뽑기 (기술 키)"가 빨강**, "내 저장소 파일 읽기"는 성공(초록)입니다. 빨간 상자를 누르면 오류 종류 "응답 읽기 실패"(parse)와 `package.json: …JSON…` 오류 글이 아래에 나옵니다. 취약점 가져오기·등급 등 뒤 상자는 0건 성공입니다.
- **남는 것:** 실행 1줄과 단계 줄, 등록한 계정의 프로젝트 1줄(기술 0개). 변경·알림·수집 자료·기술 카탈로그는 생기지 않습니다. 같은 주소로 다시 등록하면 실행만 늘고 프로젝트는 늘지 않으니 **되풀이해도 됩니다.** 프로젝트를 지우는 화면은 없으니 이름으로 알아볼 수 있게 그냥 둡니다. `/admin/runs`의 연속 실패에 "처음 등록 읽기·다시 읽기"가 잡히는 것은 진짜 실패라 맞는 표시입니다.
- **이렇게 보이면:** "이 저장소를 열 수 없어요. 주소가 틀렸거나 비공개일 수 있어요…"가 뜨고 실행이 안 생기면 → 저장소가 비공개이거나 주소가 틀린 것(실행을 만들기 전에 막는 설계). "내 저장소 파일 읽기"까지 빨강이면 → GitHub 무인증 한도(시간당 60번)에 걸린 것일 수 있습니다. 그래도 실패 실행이라 시연은 됩니다.
- **안 될 때(저장소 준비 전·인터넷 끊김):** 로컬에서 `ENABLE_FAIL_DEMO=true`로 5-2의 ① 수집 오류를 누르고 흐름 화면을 녹화·캡처해 둔 것을 보여 줍니다. "로컬에서 찍은 것"이라고 말합니다.

## 6. 분류 확인 (`/admin/classify`) — 고치는 탭
"지도 분류가 비어 있거나 사람이 확인해야 하는 것들이에요. 갈래 정하기, 같은 역할 확정, 규칙 고치기는 사유를 남겨야 해요."

| 할 일 | 버튼 | 사유 | 남는 기록 | 되돌리기 |
|---|---|---|---|---|
| 갈래 정하기 | 작은 갈래 고르기 → "갈래 정하기" | 5자 이상 | 정한 사람·시각, `audit_logs`(`category_set`) | 다른 작은 갈래로 다시 정할 수 있음(비우기는 안 됨) |
| 같은 역할 확정 | 후보 줄의 "같은 역할로 확정" | 5자 이상 | 확정한 사람·시각, `audit_logs`(`relation_confirm`) | **안 됨** |
| 규칙 끄기·켜기 | 규칙 줄의 "끄기"/"켜기" | 5자 이상 | 고친 사람, `audit_logs`(`rule_disable`/`rule_enable`) | 반대로 한 번 더 |
| 규칙 더하기 | "새 규칙 더하기" → 종류·생태계·값 → "더하기" | 5자 이상 | 고친 사람, `audit_logs`(`rule_add`) | 지우지 않고 "끄기" |

- **같은 역할 확정은 되돌릴 수 없습니다.** "확정한 관계만 적용 기회 알림에 쓰여요(ADR 0015). 확정은 되돌릴 수 없으니 근거를 확인한 뒤 눌러 주세요." 확정하면 그 관계로 **적용 기회 알림**이 만들어질 수 있습니다(PR #139).
- **위험 패턴**은 "코드 규칙(SPEC-2)과 짝이라 여기서 새로 만들지 않고 켜기·끄기만 해요."
- **허용 목록(패키지)** 을 더할 때는 생태계(npm·PyPI)를 꼭 고릅니다. 값은 공백 없이 100자 이하.
- **작은 갈래가 없으면:** "작은 갈래가 아직 없어 고를 수 없어요. 갈래의 처음 목록은 팀이 정해요(데이터설계 DQ2)."
- **맨 아래 "최근 바꾼 기록"**: 시각 · 한 일 · 나/다른 관리자 · 사유가 10줄까지 보입니다.

자주 보는 안내:

| 문구 | 뜻 / 할 일 |
|---|---|
| "사유를 5자 이상 300자 이하로 써 주세요(비밀값은 쓰지 마세요)." | 사유를 다시 씁니다 |
| "같은 규칙이 이미 있어요. 꺼져 있다면 켜기를 쓰세요." | 새로 더하지 말고 기존 줄을 켭니다 |
| "이미 그 상태라 바꾸지 않았어요." | 아무것도 바뀌지 않음, 기록도 없음 |
| "그 줄을 찾지 못했어요. 새로고침해 주세요." | 다른 관리자가 먼저 바꿨을 수 있음 |
| "저장하지 못했어요. 아무것도 바뀌지 않았어요." | 저장 실패, 그대로 둠(불변 4) |
| "… 다만 바꾼 기록(담당자·시각·사유)을 남기지 못했어요." | 바뀌기는 했지만 기록이 빠짐 → 팀에 알림(서버 키 확인) |

## 7. 시뮬레이터 (`/admin/simulator`)
- **무엇:** "진짜 취약점은 발표 시간에 맞춰 나오지 않아서, 가짜 변경 1건(npm mcp-remote 0.1.15, 위험)을 만들어 처음부터 끝까지 도는 걸 보여 줍니다."
- **버튼:** "가짜 변경 1건 만들기" · "적용 기회 1건 만들기" · "시뮬레이터 지우기".
- **알림은 시연 계정에만 갑니다.** "그 계정이 이 기술을 쓰지 않으면 알림은 0건이고, 결과 화면에 이유가 나와요." 시연 계정의 내 기술에 **진짜 `npm:mcp-remote` 0.1.15 줄**이 있어야 합니다. 시뮬레이터가 만든 기술은 검색에 안 나와서 화면에서 직접 추가할 수 없습니다(11-19 사람 확인).
- **같은 버튼을 또 눌러도** "변경은 1건 그대로예요."
- **지우기:** "가짜 표시가 붙은 줄만 지우고, 실행 기록은 증거라 남겨요. 바꾼 기록(audit_logs)에 한 줄이 남습니다." 시연 계정이 쓰는 가짜 기술 1건은 남습니다.
- **⚠ 지우기는 시연의 맨 마지막에 한 번만.** 시연 중간에 지우면 알림·판단 기록이 사라져 흐름이 끊깁니다. 리허설 뒤 깨끗한 상태에서 출발하고, 발표가 끝나면 지웁니다.
- **막히면:** "서비스 키가 없어요. 서버 설정(.env.local)을 확인해 주세요."

## 8. 위키 챗봇 (`/admin/chat`)
- **무엇:** 팀 위키(`wiki/`)에서 맞는 쪽을 찾아 그 쪽만 Claude에 보내 답합니다. 답 아래에 출처 쪽이 나오고, 위키에 없으면 "위키에 없습니다"라고 답합니다. 지어내지 않습니다.
- **한도:** 한 사람 하루 20개(한국 0시 기준), 서비스 전체 하루 200번. 질문은 300자 안.
- **남는 것:** 내 질문·답·찾은 쪽·시각(`chat_logs`), Claude 호출 기록(`ai_calls`). 아래 "내 최근 질문"에서 볼 수 있습니다.

## 하면 안 되는 것
- 근거를 확인하지 않고 **같은 역할 확정** 누르기(되돌릴 수 없고, 적용 기회 알림이 나갈 수 있음).
- 시연 **중간에 시뮬레이터 지우기**(맨 마지막에 한 번).
- 사유 칸·챗봇 질문에 **비밀값·개인정보** 쓰기.
- 운영 주소에서 실패 시연 켜기(켜지지도 않지만, 스위치는 로컬에서만). 배포 주소에서는 5-3처럼 깨진 시연 저장소를 등록합니다. 진짜 사용자 저장소나 운영 환경변수를 일부러 망가뜨리지 않습니다.
- 규칙을 "지우려고" 하기 — 지우기는 없습니다. **끄기**를 씁니다.
