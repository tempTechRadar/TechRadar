# 관리자 사용설명서

> TechRadar 관리자 화면(`/admin`)을 처음 쓰는 사람을 위한 쉬운 설명입니다. 화면 문구는 2026-11-23 `fix/c-quality-1123` 브랜치 코드(관리자 화면 리뉴얼 `5722326`·`7fd4986`)에서 옮겼습니다(`app/admin/`).
> 관리자는 DB 프로필의 역할 칸(`role = admin`)으로 정합니다. 처음 관리자는 DB에서 정하고, 그 뒤로는 "회원과 권한" 화면에서 다른 계정을 관리자로 지정하거나 되돌릴 수 있습니다(1절).
> 관리자 화면으로 가는 길: 로그인 → 오른쪽 위 **아바타(별명 첫 글자)** 를 눌러 계정 메뉴를 펼침 → **관리자**. 관리자 계정에만 보입니다.

## 먼저 알아 둘 것

- **관리자만 열립니다.** 일반 계정으로 관리자 주소(지금 한 번 실행·시뮬레이터·실패 시연 포함)를 열면 "관리자만 볼 수 있어요."가 나옵니다. 버튼을 누르는 서버 동작도 매번 관리자인지 다시 확인하고("관리자만 할 수 있어요.", 위키 챗봇은 "관리자만 쓸 수 있어요."), DB 권한 규칙(RLS)도 한 번 더 막습니다(불변 5).
- **남의 알림은 판단하지 않습니다.** 관리자 화면에는 판단 버튼이 없습니다. 관리자도 **자기** 알림은 일반 사용자와 같은 규칙으로 판단할 수 있습니다(ADR 0016).
- **고치면 기록이 남습니다.** 아래 일은 사유(5자 이상)를 꼭 적어야 하고, 누가·언제·왜 했는지가 바꾼 기록(`audit_logs`)에 남습니다. 이 기록은 아무도 고치거나 지울 수 없습니다.
  - 권한 바꾸기(관리자로 지정·일반으로 되돌리기)
  - 갈래 정하기, 같은 역할 확정, 규칙 끄기·켜기·더하기, 규칙으로 한 번에 분류
  - 사용기 신고 처리(글 숨기기·숨김 풀기·신고 처리함)
- **비밀값은 어디에도 쓰지 않습니다.** 사유 칸에 키처럼 보이는 글을 쓰면 거절됩니다.

## 메뉴 한눈에

왼쪽 메뉴 맨 위가 **관제 요약**(첫 화면 `/admin`)이고, 그 아래에 묶음 4개·항목 11개가 있습니다. 좁은 화면(폭 760px 이하)에서는 메뉴가 위쪽 가로줄로 바뀝니다. 주소는 리뉴얼 전과 같습니다.

| 묶음 | 항목(주소) | 무엇을 보나 | 고칠 수 있나 |
|---|---|---|---|
| — | 관제 요약(`/admin`) | 숫자 타일 · 시연 순서 · 바뀌지 않는 규칙 | 보기만 |
| 지켜보기 · 자동 | 수집 실행과 오류(`/admin/runs`) | 실행 기록, 연속 실패, 수집 오류 종류 | 보기만 |
| | 지금 한 번 실행(`/admin/run-now`) | 등록된 수집기, 실행 버튼 | **실행**(기록이 남음) |
| | 수집 자료(`/admin/observations`) | 출처에서 모은 값(이전 값과 현재 값) | 보기만 |
| | 흐름 화면(`/admin/flow`) | 실제 실행 기록으로 칠한 지켜보는 길 | 보기만 |
| 사람 판단 현황 | 알림과 처리 현황(`/admin/alerts`) | 모든 회원의 알림과 판단 상태 | 보기만 |
| | 사용기 신고(`/admin/reports`) | 신고된 사용기 | **고침**(사유 필수) |
| 운영 관리 · 고치면 기록이 남음 | 회원과 권한(`/admin/members`) | 회원마다 프로젝트·저장소·기술 수·마지막 읽은 시각 | 보기 + 권한 바꾸기(사유 필수) |
| | 분류 확인(`/admin/classify`) | 갈래 없는 기술, 같은 역할 후보, 규칙 목록 | **고침**(사유 필수) |
| 시연과 지식 | 시뮬레이터(`/admin/simulator`) | 가짜 변경·적용 기회 만들기, 지우기 | **만들고 지움** |
| | 실패 시연과 채점(`/admin/demo`) | 일부러 실패 5가지, 정답 사례 채점 | **실행**(시연 스위치가 켜졌을 때만 일부) |
| | 위키 챗봇(`/admin/chat`) | 팀 위키에 묻기 | 질문(하루 20개) |

사용기 신고를 뺀 각 화면 머리에는 묶음 이름 · 제목 · 설명과 **"이 화면이 증명하는 것"** 한 줄이 있습니다. 발표 때 이 줄을 그대로 읽으면 됩니다.

## 0. 관제 요약 (`/admin`, 첫 화면)
- **무엇:** "정기 실행 · 수집 오류 · 사람 판단 · 분류 확인 거리를 한 장에 모았어요. 숫자를 누르면 그 화면으로 가요." 맨 위 문장은 "앱이 매일 혼자 지켜보고 실패까지 기록한 증거는 모두 여기 있고, 바꾸는 판단만은 사람 몫이에요."
- **숫자 타일**(메뉴 묶음과 같은 순서). 숫자는 관리자 본인 권한으로 DB에서 바로 셉니다.

| 묶음 | 타일 | 무엇을 세나 | 누르면 |
|---|---|---|---|
| 지켜보기(자동) | 마지막 정기 실행 | 가장 최근 매일 06:00 정기 실행이 끝난 시각. 아래 줄에 상태(끝남·진행 중·실행 실패·처리 단계 실패 n)와 "출처 n곳" | 그 실행의 흐름 화면 |
| | 수집 오류(마지막 정기 실행) | 그 실행에서 수집 오류가 난 **출처 수**. 0보다 크면 "출처 단위 · 변화 없음으로 치지 않음" | 수집 실행과 오류 |
| | 최근 7일 실행 | 7일 동안의 모든 실행 수. 아래 줄에 "실패 n · 일부 실패 n". 1,000건을 넘으면 숫자 뒤에 "+" | 수집 실행과 오류 |
| 사람 판단 현황 | 판단 대기 알림 | 모든 회원의 판단 대기 알림 수("판단은 알림을 받은 본인만") | 알림과 처리 현황(판단 대기만) |
| | 처리 전 사용기 신고 | 아직 처리하지 않은 신고 수("신고 건 기준") | 사용기 신고 |
| 운영 관리(고치면 기록이 남음) | 갈래 빈 기술 | 갈래가 빈 기술 수("분류 확인 화면과 같은 기준") | 분류 확인 |
| | 같은 역할 후보 | 관리자가 아직 확인하지 않은 같은 역할 후보 수 | 분류 확인 |

- **못 읽으면 0이 아니라 "읽지 못함":** 숫자 하나를 못 읽으면 그 타일만 **"읽지 못함"** 과 이유를 보이고, 나머지 타일은 그대로 보입니다. 0으로 바꿔 쓰지 않습니다(불변 2). 정기 실행이 아직 한 번도 없으면 "아직 없음"입니다. 사용기 신고 표가 DB에 없으면 이유가 "사용기 신고 표가 아직 DB에 없음(마이그레이션 적용 대기)"로 나옵니다.
- **시연 순서 카드 5장**(링크만, 여기서 아무것도 실행하지 않음): ① 시뮬레이터 ② 흐름 화면 ③ 알림 판단은 시연 계정으로 ④ 실패 장면 ⑤ 위키 챗봇 Q5. 카드마다 무엇을 말하면 되는지 한 줄이 적혀 있습니다. 발표 순서표로 씁니다.
- **바뀌지 않는 규칙** 띠: "사람이 판단하기 전엔 아무것도 바뀌지 않아요" · "수집 실패는 '변화 없음'이 아니라 '수집 오류'로 남아요" · "흐름 화면은 실제 실행 기록으로만 칠해요".
- 이 화면에는 판단 버튼이 없습니다(불변 1).

## 1. 회원과 권한 (`/admin/members`)
- **무엇:** "회원마다 등록한 프로젝트와 저장소 주소, 읽어 낸 기술 수(숨긴 것 제외), 마지막으로 읽은 시각이에요."
- **언제:** 누가 무엇을 등록했는지, 읽기가 오래 멈춘 회원이 있는지 볼 때. 위 칸에서 회원 · 기간(마지막 활동)을 고르고 **[필터]** 를 누릅니다.
- **표시:** "관리자"·"시연" 표시가 붙은 계정은 각각 관리자·시연 계정입니다. "등록 없음"은 프로젝트가 아직 없다는 뜻입니다. 보관한 프로젝트에는 "보관"이 붙습니다.
- **권한 바꾸기(11-23):** 오른쪽 "권한" 칸의 단추를 누르면 작은 창이 떠요. 사유(5~300자)를 쓰고 확인 체크를 한 뒤 보내요. 바꾼 기록(담당자·시각·사유)이 남아요. 체크를 안 하고 보내면 ""관리자 권한을 준다는 것을 확인했어요"에 체크해 주세요. 아무것도 바뀌지 않았어요."(되돌리기는 "…거둔다는 것을…")가 나옵니다.
  - 일반 계정 → **관리자로 지정**. 시연 계정은 "시연 계정(지정 불가)"로만 보여요.
  - 다른 관리자 → **일반으로 되돌리기**. 내 줄은 "관리자(나)", 관리자가 한 명뿐이면 "관리자(마지막 한 명)"로만 보이고 되돌릴 수 없어요.
  - 지정된 사람은 다시 로그인하면 계정 메뉴에 "관리자"가 보이고, 되돌려진 사람은 다시 로그인하면 사라져요.

## 2. 수집 자료 (`/admin/observations`)
- **무엇:** "출처에서 모은 값이에요. 이전 값과 현재 값을 나란히 보여 줘요. 시뮬레이터가 만든 줄은 '가짜' 표시가 붙어요."
- **거르기:** 출처 · 기간을 고르고 **[필터]**.
- **주의:** 시뮬레이터가 만든 줄에는 **"가짜"** 표시가 붙습니다. 진짜 자료와 섞어 판단하지 않습니다.

## 3. 알림과 처리 현황 (`/admin/alerts`)
- **무엇:** "모든 회원의 알림과 판단 상태예요. 이 화면에서는 보기만 해요: 판단은 알림을 받은 본인만 할 수 있어요."
- **위 건수 띠(거르기 아님):** 전체 · 판단 대기 · 완료 · 적용 후보 · 보류. 거르기와 상관없이 **모든 알림**의 수입니다. 눌러도 걸러지지 않습니다.
- **실제 거르기:** 그 아래 칸에서 상태(모든 상태·판단 대기·완료) · 종류(모든 종류·보안 경고·적용 기회·모델 종료) · 기간(전체 기간·최근 7일·최근 30일)을 고르고 **[필터]** 를 누릅니다. 걸러진 수는 표 바로 위에 "n건"으로 나옵니다.
- **언제:** 판단이 오래 밀린 알림이 있는지 볼 때. 대신 판단해 주는 버튼은 일부러 없습니다(불변 1).

## 4. 수집 실행과 오류 (`/admin/runs`)
- **무엇:** "언제 무엇이 돌았고 몇 건을 처리했는지, 실패가 몇 번 이어졌는지 보여 줘요. 수집 실패는 '변화 없음'이 아니라 '수집 오류'로 남아요."
- **연속 실패:** 같은 시작 방식(예약·지금 실행·처음 읽기 등)이 연달아 실패하면 "n번 연속"으로 나옵니다. 비어 있으면 "지금 이어지고 있는 실패는 없어요."
- **실행 기록 표:** 줄마다 **흐름 보기** 링크가 있어 그 실행의 흐름 화면으로 갑니다.
- **지금 한 번 실행:** 화면 위 **지금 한 번 실행** 단추를 누르면 `/admin/run-now`로 갑니다(아래 5-1). 메뉴의 같은 이름 항목으로도 갈 수 있습니다.

## 5. 흐름 화면 (`/admin/flow`)
- **무엇:** "앱이 실제로 돈 기록대로 칠해져요. 기록이 없는 상자는 회색으로 남아요." 미리 칠해 둔 그림이 아닙니다(불변 6).
- **쓰는 법:** 아래 "실행 목록"에서 한 줄을 고르면 그 실행의 길만 칠해집니다. 상자를 누르면 "설정과 이 실행의 기록(들어온 것·나간 것·호출·오류)"이 아래에 나오고, 화살표 위 숫자는 넘어간 건수입니다. 아무것도 고르지 않으면 가장 최근 실행을 그립니다.
- **색:** 안 켜짐(회색)·실행 중·성공·실패(빨강)·판단 대기(주황 점선)·꺼 둠.
- **비어 있으면:** "아직 실행 기록이 없어요. 시뮬레이터나 지금 한 번 실행을 돌리면 여기에 생겨요."
- **주소의 실행을 못 찾으면(`?run=…`):** 다른 화면의 "흐름 보기" 링크는 주소에 실행 id를 붙여 옵니다. 그 실행이 없으면 "그 실행을 찾지 못했어요. 주소의 실행 id를 확인하거나 아래 목록에서 골라 주세요(다른 실행으로 대신 그리지 않아요)."가 나오고, 아래 실행 목록에서 직접 고르면 됩니다. 그 실행을 읽다 실패했으면 "그 실행을 읽지 못했어요(없는 게 아니에요): …"입니다.
- **단계만 못 읽으면:** 실행은 골랐는데 그 단계 기록을 못 읽으면 그림 대신 "이 실행의 단계를 읽지 못했어요(없는 게 아니에요): …"가 나옵니다. 회색 그림("안 돎")으로 보이지 않게 일부러 그림을 숨긴 것입니다. 실행 목록은 남아 있어 다른 실행을 고를 수 있습니다.
- 위쪽 링크: 시뮬레이터 · 지금 한 번 실행 · 실패 시연.

### 5-1. 지금 한 번 실행 (`/admin/run-now`)
- **무엇:** "매일 06:00(한국 시간)에 저절로 도는 수집을 지금 한 번 돌려요. 출처 하나가 실패해도 나머지는 계속하고, 실패는 "수집 오류"로 남아요."
- **언제:** 정기 실행이 실패했을 때 다시 돌리거나, 시연 전에 최신 자료를 받을 때. 무료 플랜 예약은 하루 한 번이라 "다시 돌리려면 이 버튼을 눌러요."
- **누르면:** **지금 한 번 실행** 을 누르면 단추 글이 "실행 중… 기록을 남기는 중(최대 4분)"으로 바뀌고 다시 누를 수 없습니다. 끝나면 그 실행의 흐름 화면으로 넘어갑니다. 지난번 것은 "가장 최근 지금 실행 흐름 보기"로 다시 볼 수 있습니다.
- **등록된 수집기(7개):** `fetch_osv`(OSV 보안) · `fetch_github`(GitHub 저장소 정보) · `fetch_stars`(별 많은 저장소 찾기) · `fetch_registry`(공식 MCP 레지스트리) · `fetch_downloads`(npm·PyPI 다운로드) · `fetch_popularity`(Hacker News) · `fetch_news`(바깥 소식). 시간 예산(240초)을 넘기면 뒤쪽 수집기는 그 실행에서 시작하지 않고 회색으로 남습니다.
- **같은 출처가 3번 연속 수집 오류면** 화면 위에 "3번 연속 수집 오류: …"가 빨갛게 나옵니다.
- **재시도:** 화면 문구 그대로 "실패하면 다음 시도 시각(2분 뒤)을 실행 기록에 적기만 해요. 자동으로 다시 돌지는 않아요." 다음 시도 시각(`runs.next_retry_at`)은 **기록만** 하고, 그 시각에 다시 돌리는 곳은 아직 없습니다. 다음 기회는 매일 06:00 정기 실행이고, 급하면 이 버튼을 다시 누릅니다.
- **남는 것:** 실행 기록 1개(흐름 화면에서 볼 수 있음).
- **막히면:** "서비스 키가 없어요. 서버 설정(.env.local)을 확인해 주세요." → 서버 환경변수는 사람이 직접 넣습니다.

### 5-2. 실패 시연과 채점 (`/admin/demo`)
- **무엇:** 일부러 실패 5가지(① 수집 오류 ② 사건 아님 ③ 중복 ④ 판단 대기 ⑤ 저장 실패)를 만들어 흐름 화면에 실제 기록으로 남깁니다. 같은 화면 아래 "채점" 칸에 정답 사례 G1–G9 **채점 실행** 버튼도 있습니다("저장해 둔 조회 결과만 써서 바깥 호출은 없어요").
- **켜야 쓸 수 있음:** 운영 배포에서는 꺼져 있습니다. "시연 스위치: 꺼짐 — 운영 배포이거나 ENABLE_FAIL_DEMO가 true가 아니에요. ①②⑤는 눌러도 아무 일도 없어요." 꺼져 있으면 ①② 단추 옆에 "스위치가 꺼져 있어 못 눌러요"가 붙습니다. 미리보기 배포는 꺼 두었으니(ADR 0018) 지금은 **로컬에서만** 씁니다. ③④(시뮬레이터)와 채점은 스위치와 상관없이 됩니다.
- **운영 안내 상자:** 스위치가 꺼져 있으면 화면 위쪽에 **"운영에서 실패 보여 주기(스위치 없이)"** 상자가 나옵니다. 아래 5-3을 세 줄로 줄인 것이고, **프로젝트 보드로** · **흐름 화면으로** 링크만 있습니다(여기서 등록하지 않음).
- **⑤ 저장 실패:** **다음 저장 1번 실패시키기** 를 누르면 **이 브라우저**에서 **시연 계정**의 다음 판단 저장 1번이 실패합니다(10분 뒤 저절로 꺼짐). 끝나면 **끄기** 를 누릅니다.
- **누가 판단하나:** 관리자도 자기 알림은 판단할 수 있지만 남의 알림은 판단할 수 없습니다(ADR 0016). 시연 알림은 시연 계정 것이라, ⑤를 켠 뒤 같은 브라우저에서 시연 계정으로 판단합니다.

### 5-3. 배포 주소에서 실패 보여 주기
실패 시연 스위치를 켜지 않고, **진짜로 깨진 입력**을 넣어 빨간 상자를 만듭니다. 앱 코드는 사용자가 깨진 파일을 올렸을 때와 똑같이 돌고, 흐름 화면은 그 실행 기록대로 칠합니다(불변 6, ADR 0024 제안).
- **준비(끝남):** 공개 저장소 `csaeil/techradar-fail-demo`(https://github.com/csaeil/techradar-fail-demo)를 11-19 차세일이 만들어 두었습니다. 뿌리에 `README.md`("일부러 깨 둔 시연용")와 `package.json`(일부러 끝을 자른 JSON `{ "dependencies": `) 두 파일만 있습니다. `.mcp.json`·`requirements.txt`·`.claude/skills/`는 두지 않습니다(있으면 읽은 것이 생겨 "일부 실패"가 됩니다). 11-20 운영 주소에서 이 순서로 빨간 상자를 확인했습니다(실행 `fa948804`, `docs/flow.md` 6절 ②).
- **누르는 순서:**
  1. 배포 주소에 관리자 계정으로 로그인합니다(운영은 테스트 로그인이 꺼져 있습니다).
  2. 위 메뉴 **프로젝트**(`/dashboard`, 프로젝트 보드)를 엽니다. "진행 중 프로젝트" 판 맨 아래 **+ 레포 등록** 칸에 `https://github.com/csaeil/techradar-fail-demo`를 넣고 **등록하고 읽기** 를 누릅니다. 이미 등록했으면 같은 주소를 다시 넣거나, 그 레포 줄 오른쪽 **⟳**(다시 읽기)를 누릅니다.
  3. 프로젝트 보드로 돌아오면 그 레포 줄의 "마지막 읽기" 칸에 "마지막 읽기가 실패했어요. 목록이 비었거나 일부만 보일 수 있어요(없다는 뜻이 아니에요). '다시 읽기'를 눌러 보세요."가 보입니다. 레포 이름을 눌러 레포 상세(`/projects/<id>`)로 가도 같은 안내가 나옵니다.
  4. `/admin/flow`를 엽니다. 실행 목록 맨 위(그 사이 다른 실행이 없었다면)에 시작 "처음 등록 읽기"(또는 "다시 읽기 버튼")·상태 **실패** 줄이 있습니다. 그 줄을 고릅니다.
  5. 시작 상자와 **"내 기술 뽑기 (기술 키)"가 빨강**, "내 저장소 파일 읽기"는 성공(초록)입니다. 빨간 상자를 누르면 오류 종류 "응답 읽기 실패"와 `package.json: …JSON…` 오류 글이 아래에 나옵니다. 뒤 상자는 0건 성공입니다.
- **남는 것:** 실행 1줄과 단계 줄, 등록한 계정의 프로젝트 1줄(기술 0개). 변경·알림·수집 자료·기술 카탈로그는 생기지 않습니다. 같은 주소로 다시 등록하면 실행만 늘고 프로젝트는 늘지 않으니 **되풀이해도 됩니다.** 프로젝트를 지우는 화면은 없으니(보관만 있음) 이름으로 알아볼 수 있게 그냥 둡니다. `/admin/runs`의 연속 실패에 "처음 읽기·다시 읽기"가 잡히는 것은 진짜 실패라 맞는 표시입니다.
- **이렇게 보이면:** "이 저장소를 열 수 없어요. 주소가 틀렸거나 비공개일 수 있어요. 공개 GitHub 저장소만 등록할 수 있어요."가 뜨고 실행이 안 생기면 → 저장소가 비공개이거나 주소가 틀린 것(실행을 만들기 전에 막는 설계). "내 저장소 파일 읽기"까지 빨강이면 → GitHub 무인증 한도(시간당 60번)에 걸린 것일 수 있습니다. 그래도 실패 실행이라 시연은 됩니다.
- **안 될 때(인터넷 끊김 등):** 로컬에서 `ENABLE_FAIL_DEMO=true`로 5-2의 ① 수집 오류를 누르고 흐름 화면을 녹화·캡처해 둔 것을 보여 줍니다. "로컬에서 찍은 것"이라고 말합니다. 11-20 운영 캡처는 `docs/images/flow-fail-demo-1120.png`에 있습니다.

## 6. 분류 확인 (`/admin/classify`) — 고치는 탭
"지도 분류가 비어 있거나 사람이 확인해야 하는 것들이에요. 갈래 정하기, 같은 역할 확정, 규칙 고치기는 사유를 남겨야 해요."

| 할 일 | 버튼 | 사유 | 남는 기록 | 되돌리기 |
|---|---|---|---|---|
| 규칙으로 한 번에 분류 | 맨 위 사유 칸 → "규칙으로 한 번에 분류" | 5자 이상 | `audit_logs`(`classify_all`, 사유 + 결과 요약) | 관리자가 정한 갈래는 건드리지 않음. 못 정한 것은 아래 목록에 남음 |
| 갈래 정하기 | 작은 갈래 고르기 → "갈래 정하기"(이미 정했으면 "갈래 고치기") | 5자 이상 | 정한 사람·시각, `audit_logs`(`category_set`) | 다른 작은 갈래로 다시 정할 수 있음(비우기는 안 됨) |
| 같은 역할 확정 | 후보 줄의 "같은 역할로 확정" | 5자 이상 | 확정한 사람·시각, `audit_logs`(`relation_confirm`) | **안 됨** |
| 규칙 끄기·켜기 | 규칙 줄의 "끄기"/"켜기" | 5자 이상 | 고친 사람, `audit_logs`(`rule_disable`/`rule_enable`) | 반대로 한 번 더 |
| 규칙 더하기 | "새 규칙 더하기" → 종류·생태계·값 → "더하기" | 5자 이상 | 고친 사람, `audit_logs`(`rule_add`) | 지우지 않고 "끄기" |

- **규칙으로 한 번에 분류:** "매일 실행 뒤에 도는 것과 같은 규칙이에요. 관리자가 정한 갈래는 바꾸지 않아요." 한 번에 40초까지 돕니다. 중간에 멈추면 "분류하다 멈췄어요. 이미 정한 갈래는 그대로이고, 다시 누르면 남은 것부터 이어서 해요."
- **같은 역할 확정은 되돌릴 수 없습니다.** "확정한 관계만 적용 기회 알림에 쓰여요(ADR 0015). 확정은 되돌릴 수 없으니 근거를 확인한 뒤 눌러 주세요." 확정하면 그 관계로 **적용 기회 알림**이 만들어질 수 있습니다(PR #139).
- **위험 패턴**은 "코드 규칙(SPEC-2)과 짝이라 여기서 새로 만들지 않고 켜기·끄기만 해요."
- **허용 목록(패키지)** 을 더할 때는 생태계(npm·PyPI)를 꼭 고릅니다. 값은 공백 없이 100자 이하.
- **작은 갈래가 없으면:** "작은 갈래가 아직 없어 고를 수 없어요. 갈래의 처음 목록은 팀이 정해요(데이터설계 DQ2)."
- **맨 아래 "최근 바꾼 기록"**: 시각 · 한 일 · 나/다른 관리자 · 사유가 10줄까지 보입니다.

| 문구 | 뜻 / 할 일 |
|---|---|
| "사유를 5자 이상 300자 이하로 써 주세요(비밀값은 쓰지 마세요)." | 사유를 다시 씁니다 |
| "같은 규칙이 이미 있어요. 꺼져 있다면 켜기를 쓰세요." | 새로 더하지 말고 기존 줄을 켭니다 |
| "이미 그 상태라 바꾸지 않았어요." | 아무것도 바뀌지 않음, 기록도 없음 |
| "그 줄을 찾지 못했어요. 새로고침해 주세요." | 다른 관리자가 먼저 바꿨을 수 있음 |
| "저장하지 못했어요. 아무것도 바뀌지 않았어요." | 저장 실패, 그대로 둠(불변 4) |
| "… 다만 바꾼 기록(담당자·시각·사유)을 남기지 못했어요." | 바뀌기는 했지만 기록이 빠짐 → 팀에 알림(서버 키 확인) |

## 7. 시뮬레이터 (`/admin/simulator`)
- **무엇:** "진짜 취약점은 발표 시간에 맞춰 나오지 않아서, 가짜 변경 1건(npm mcp-remote 0.1.15, 위험)을 만들어 처음부터 끝까지 도는 걸 보여 줍니다."
- **버튼:** "가짜 변경 1건 만들기" · "적용 기회 1건 만들기" · "시뮬레이터 지우기". 누르는 동안 단추 글이 "실행 중… 기록을 남기는 중"으로 바뀝니다.
- **알림은 시연 계정에만 갑니다.** "그 계정이 이 기술을 쓰지 않으면 알림은 0건이고, 결과 화면에 이유가 나와요." 이유 문구는 "알림 0건: 시연 계정이 mcp-remote을(를) 사용 중인 항목으로 쓰지 않거나, 이 변경의 알림이 이미 만들어져 있어요."입니다. 그래서 시연 계정의 **사용 중인 항목**에 **진짜 `npm:mcp-remote` 0.1.15 줄**이 있어야 합니다. 시뮬레이터가 만든 기술은 검색에 안 나와서 화면에서 직접 추가할 수 없습니다(11-19 사람 확인).
- **알림이 1건 이상이면** 그 실행의 흐름 화면으로 바로 넘어갑니다. 0건이면 이 화면에 이유와 **방금 실행 보기** 링크가 나옵니다.
- **같은 버튼을 또 눌러도** "변경은 1건 그대로예요."
- **지우기:** "지우기는 가짜 표시가 붙은 줄만 지우고, 실행 기록은 증거라 남겨요. 바꾼 기록(audit_logs)에 한 줄이 남습니다." 끝나면 "…기술 n건을 지웠어요(사용 중인 항목에 걸린 가짜 기술 n건은 남김)."이 나옵니다.
- **⚠ 지우기는 시연의 맨 마지막에 한 번만.** 시연 중간에 지우면 알림·판단 기록이 사라져 흐름이 끊깁니다. 리허설 뒤 깨끗한 상태에서 출발하고, 발표가 끝나면 지웁니다.
- **막히면:** "서비스 키가 없어요. 서버 설정(.env.local)을 확인해 주세요."

## 8. 위키 챗봇 (`/admin/chat`)
- **무엇:** 팀 위키(`wiki/`)에서 맞는 쪽을 찾아 그 쪽만 Claude에 보내 답합니다. 답 아래에 출처 쪽이 나오고, 위키에 없으면 "위키에 없습니다"라고 답합니다. 지어내지 않습니다.
- **예시 질문 칩(11-23):** 질문 칸 위 "정답표 예시 질문"에 Q1–Q5 칩이 있습니다(`docs/wiki-chat.md` 정답표 질문 그대로). "누르면 질문 칸에 채워져요. 묻기는 직접 눌러 주세요. Q4는 위키에 없는 질문, Q5는 문서끼리 말이 다른 질문이에요." 칩은 **질문 칸만 채웁니다.** 묻는 것은 사람이 **묻기** 를 눌러야 하고, 그래서 칩만 눌러서는 하루 질문 수가 줄지 않습니다.
- **한도:** 한 사람 하루 20개(한국 0시 기준), 서비스 전체 하루 200번. 질문은 300자 안, 답은 800자 안. 화면 위에 "오늘 남은 질문: n / 20개"가 나옵니다. Claude 호출이 실패한 질문도 한도에 들어갑니다(그런 질문이 있으면 "실패한 질문 n개도 한도에 들어가요"가 붙음). 실패한 질문 수를 못 읽으면 "실패한 질문 수를 읽지 못해 성공한 질문만 셌어요"가 붙습니다.
- **남는 것:** 내 질문·답·찾은 쪽·시각(`chat_logs`), Claude 호출 기록(`ai_calls`, 실패한 호출 포함). 아래 "내 최근 질문"에서 볼 수 있습니다.

| 문구 | 뜻 |
|---|---|

## 9. 사용기 신고 (`/admin/reports`) — 고치는 탭
- **무엇:** "사용자가 신고한 사용기예요. 글을 숨기면 쓴 사람 말고는 볼 수 없어요. 숨기기·풀기·처리는 사유를 남겨요(담당자·시각·사유). 쓴 사람과 신고한 사람은 보이지 않아요."
- **거르기:** 위 링크 **처리 전 (n)** · **처리함 (n)** · **전체 (n)**. 처음은 "처리 전"입니다.
- **버튼(사유 5자 이상):** 보이는 글은 **글 숨기기**(신고도 함께 처리함) 또는 **신고만 처리함으로 (글은 그대로)**. 숨긴 글은 **숨김 풀기** 또는 **신고 처리함으로**. 바꾼 기록(`audit_logs`)에 `hide_note`·`unhide_note`·`handle_report`로 남습니다.
- 이 버튼들은 알림 판단이 아닙니다(불변 1은 알림 판단 이야기).
- **표가 없으면:** "사용기 표가 아직 DB에 없어요(마이그레이션 적용 대기). 다른 관리자 탭은 그대로예요."

| 보이는 것 | 뜻 | 할 일 |

| "관리자만 볼 수 있어요." | 이 계정은 관리자가 아님 | 다른 관리자에게 "회원과 권한"에서 지정을 요청(처음 관리자는 DB `role=admin`) |
| 계정 메뉴에 "관리자"가 없음 | 관리자가 아니거나, 지정된 뒤 다시 로그인하지 않음 | 로그아웃 뒤 다시 로그인 |
| "Supabase 연결 전이에요. .env.local을 확인해 주세요." | 서버에 DB 주소·키가 없음 | 서버 설정 확인(값은 사람이 직접 넣음) |

| "… column … does not exist" | 코드는 새 칸을 읽는데 운영 DB에 그 칸이 아직 없음(마이그레이션 적용 전) | 마이그레이션 적용을 영식 님께 요청. 팀 규칙: 새 칸은 합치기 전에 운영에 먼저(CLAUDE.md 10절) |

| "서비스 키가 없어요. 서버 설정(.env.local)을 확인해 주세요." | 서버용 키가 없어 시뮬레이터·지금 실행이 못 돎 | 서버 환경변수 확인 |

| 로그인 때 "Invalid path specified in request URL"(로컬) | `.env.local`의 Supabase 주소 끝에 `/rest/v1/`가 붙음 | 주소 끝을 지움 |

## 하면 안 되는 것
- 근거를 확인하지 않고 **같은 역할 확정** 누르기(되돌릴 수 없고, 적용 기회 알림이 나갈 수 있음).
- 시연 **중간에 시뮬레이터 지우기**(맨 마지막에 한 번).
- 사유 칸·챗봇 질문에 **비밀값·개인정보** 쓰기.
- 운영 주소에서 실패 시연 켜기(켜지지도 않지만, 스위치는 로컬에서만). 배포 주소에서는 5-3처럼 깨진 시연 저장소를 등록합니다. 진짜 사용자 저장소나 운영 환경변수를 일부러 망가뜨리지 않습니다.
- 규칙을 "지우려고" 하기 — 지우기는 없습니다. **끄기**를 씁니다.
